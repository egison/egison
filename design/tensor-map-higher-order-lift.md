# 高階引数の変換と関数定義の候補

高階引数とは，別の関数へ引数として渡す関数である．利用者は，引数型，返り値型，テンソルを受け取る位置，候補の名前を指定しない．

統合型推論は，入力全体を変更しない挿入なし型推論を優先する．明示的な `tensorMap`・`tensorMap2` は挿入なし型推論でも扱う．それが失敗した場合，自動挿入型推論が，本体から生成する高階引数の変換候補を比較する．以下の候補生成と選び直しは，この自動挿入型推論の処理である．三用語の定義は [テンソル型と添字記法](type-tensor-simple.md) を参照する．

## 通常の型と変換候補

テンソルの要求がなければ，高階関数を使う定義も通常の型を保つ．

```egison
def sum xs := foldl (+) 0 xs
-- 通常の型：[Integer] -> Integer

def increments xs := map (\x -> x+1) xs
-- 通常の型：[Integer] -> [Integer]
```

定義には，高階引数を変換する候補も保持する．候補は型，コード，内部の型変数の共有と制約を一緒に持つ．組合せを先にすべて展開せず，コードと制約を表すテンプレートとして保持できる．

```egison
-- sum のテンソル用候補
\xs -> foldl (\x y -> tensorMap2 (+) x y) 0 xs

-- increments のテンソル用候補
\xs -> map (\x -> tensorMap (\n -> n+1) x) xs
```

候補は元の定義の本体から生成する．本体が分からない関数について，別の実装の存在を仮定しない．

## 受け取り側の型を満たす条件

変換後の関数型が，受け取り側の型変数への一貫した代入によって適合する場合だけ選択できる．同じ型変数のすべての出現と，ほかの引数の要求も照合する．

```text
map    : (a -> b) -> [a] -> [b]
foldl  : (b -> a -> b) -> b -> [a] -> b
filter : (a -> Bool) -> [a] -> [a]
```

`map` は `a` と `b` をテンソル型にできる．`foldl` は結果の `b` を累積値にも共有するため，入力と結果への変換を一緒に検査する．`filter` に渡す述語の結果は `Bool` に固定され，`Tensor Bool` へ変更できない．したがって，`p : Integer -> Bool` を `\x -> tensorMap p x` に変換して `filter` へ渡すことはできない．もともとテンソル全体を受け取って `Bool` を返す述語は使える．

述語の本体内の写像は，返り値を `Bool` に保てる場合に許す．例えば `filter (\x -> let unused := x+1 in True) [[|1,2|]]` は，加算だけへ `tensorMap` を挿入し，述語を `Tensor Integer -> Bool` とできる．別名で定義した述語も，既知の本体からこの候補を生成する．述語全体を写像して `Tensor Bool` を返す変換とは別に検査する．

高階関数全体の結果がリストになる `map` でも変換を許す．判定に必要なのは，各型変数と固定された型の整合である．

## 使用ごとの選択

関数を含むリストや組などの値にも，本体から生成する候補を保持する．例えば，`let predicates := [\x -> let unused := x+1 in True] in filter (head predicates) [[|1,2|]]` では，取り出した述語の入力に合わせて，保存した加算の変換を選ぶ．通常のリストの使用では，述語の入力を整数のまま保つ．

自動挿入型推論の各参照では通常の候補を優先し，使用箇所の制約を満たさなければ変換候補を選ぶ．入力全体について挿入なし型推論が成功する場合は，この候補選択よりもその結果を優先する．一般化した型変数は参照ごとに新しくする．外側から捕捉した単相な変数は，同じ型の関係を共有する．

```egison
(sum [1,2], sum [[|1,2|],[|3,4|]])
-- (Integer, Tensor Integer)
-- (3, [|4,6|])

let f := sum in
  (f [1,2], f [[|1,2|],[|3,4|]])
-- 同じ二つの候補を使用できる
```

直近の引数だけで候補を確定しない．後続の引数，高階引数，let の使用によって不一致が分かった場合も，型代入と制約を戻して選び直す．選択のためにプログラムを実行しない．

捕捉した値には定義位置で一意な内部名を付ける．候補のコードを使用位置へ展開しても，そこで同じ名前の変数が束縛されていることによって，捕捉した値が変わらないようにする．

部分適用の返り値が関数のテンソルである場合も，`Tensor` を保持して照合する．残る引数は保存された関数へ写像によって適用し，もともとテンソルを受け取る仮引数には，全体のテンソルを渡す．明示的な `tensorMap` の入力も，型を正規化する前の成分だけへ分解して確定せず，テンソル全体の等式として解く．`Tensor a` の `a` がテンソルである可能性を保ち，後続の制約に応じて選び直す．

## 未確定の仮引数

```egison
\k -> k [|1,2|]
-- (Tensor Integer -> a) -> a

\k -> tensorMap k [|1,2|]
-- (Integer -> a) -> Tensor a
```

挿入なし型推論は，どちらの式も書かれたまま受理する．第一の式では未確定の仮引数にテンソル全体を渡し，第二の式では明示した `tensorMap` によって成分ごとに適用する．統合型推論は，それぞれの式をそのまま採用する．

## 実装と検証

`\v -> 1` のように引数を使わない関数は，テンソル全体を受け取る型を優先する．受け取り側がテンソルの結果を要求する場合は，返り値だけを階数0のテンソルへ補完できる．入力へ写像して入力の軸を結果へ追加する必要はない．

`Integer -> Tensor (Integer -> Integer)` のように返り値の途中に関数のテンソルを含む場合は，残る引数をそのテンソル内の関数へ適用できる．例えば，スカラーの二つの引数を受け取ってテンソルを返す関数へ変換できる．もともとの引数の型を保ち，関数を格納したテンソルに対して写像する．

テンソルを受け取る位置へ型が未確定の値を渡す場合は，テンソル全体として渡す候補と，スカラーを階数0として補完する候補を保持する．後続のリストの連結やパターンマッチがスカラーのリストを要求する場合も，そこで制約を合わせて候補を選べる．

`Type/Env.hs` は候補とコード・制約のテンプレートを保存する．`Type/Infer.hs` は参照ごとの具体化，捕捉変数の共有，候補の比較と選び直しを行う．`Type/TensorMapInsertion.hs` の `buildCallbackLiftPlan`，`typeDirectedTensorLiftTypes`，`callbackLiftMask` は，受け取り側の型に適合する入力の部分集合を扱い，選択後に `tensorMap`・`tensorMap2` のコードを生成する．

スカラー初期値は階数0として受け取れる．`foldl` の初期値 `0` を受け取ることを理由に，結果をさらにテンソルで包まない．`IO`，`IORef`，`Port` やこれらを含む型は，成分ごとの自動変換の対象にしない．関数を格納したテンソルの適用では，関数の値をデータの成分へ変換するのではなく，格納された関数の呼び出しへ写像を挿入する．

推論型と挿入は `test/TensorInference.hs`，実行は `test/lib/core/tensor-function-families.egi`，`tensor-higher-order.egi`，`tensor-result-types.egi` で検査する．

## 追加添字と既存の名前の範囲

`tensor..._j` は，先頭から連続する名前付き軸だけを残し，その直後から新しい添字を処理する．名前のない軸の内側に名前付き軸があっても，その名前は残す範囲には含まれない．例えば `([|[|1,2|]_i,[|3,4|]_i|])..._j` の結果には外側の `_j` だけが付き，内側の古い `_i` は消える．`..._2` は名前のない `[|3,4|]` を返す．これは論文の，既存の先頭部分と新しい添字列を連結してから直接参照する規則に対応する．

内部の `DF` は名前のない次元を表すための印であり，数値添字やシンボリックな添字として `tref` に渡さない．`refTensorWithOverride` は追加参照の既存添字を最初の `DF` の手前までに限定する．`mini-test/9921-appended-index-prefix.egi` で，入れ子の配列，数値による成分選択，既存の先頭の名前の保持，同じ名前による対角成分の選択を検査する．

## 空のテンソルの添字参照

次元に `0` を含むテンソルでも，添字参照は残りの次元を保持する．例えば形状 `[0,3]` への `_i` は形状 `[0,3]`，`_i_2` は形状 `[0]` を返す．成分がなくても `_i_4` は範囲外として失敗する．同じ名前の添字による対角成分の選択も，先の次元が後の次元以下であることを検査し，後の軸だけを取り除く．形状 `[0,3,2]` への `_i_i` は形状 `[0,2]` を返し，形状 `[2,0,3]` への `_i_i` は失敗する．

`emptyReference` は，成分を分割する代わりに次元と添字の列を処理する．整数とシンボリックな添字の判定は通常の参照と共有する．空のテンソルから配列を組み立てる場合も，外側の要素数を保持する．例えば形状 `[0,3]` のテンソルを2個並べると形状 `[2,0,3]` になる．`mini-test/9922-empty-tensor-references.egi` で，通常の参照・追加参照・数値選択・対角成分・範囲指定・再構築を検査する．範囲外と軸数超過は `type-tensor-mech/tests/egison-tensor-operations.json` の独立した期待結果と照合する．
