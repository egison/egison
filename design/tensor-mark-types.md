# テンソルになりうる位置の印（提案と作業の指示）

状態：**提案**（未実装）．2026-11-11 の検討で決まった方針をまとめた指示書である．Egison，論文（`~/PL/type-tensor-paper`），Lean の機械化（`~/PL/type-tensor-mech`）は，この文書に従ってあとでまとめて直す．実装したら内容を仕様の文書（[type-tensor-simple.md](type-tensor-simple.md) など）へ移し，この文書を削除する．

用語は `EgisonTERM.md` §9 に従う．**挿入**は `tensorMap`・`tensorMap2` の呼び出しを式に加えること，**持ち上げ**はスカラー型の仮引数にテンソルを渡す適用を成分ごとの適用にすること，**階数 0 の包含**はスカラーを値も式も変えずに階数 0 のテンソルとして扱うことである．この文書で新しく使う語は §3 で定義する．

この文書の内容は三種類に分かれる．§2 はユーザーの決定である．§4 はそこから導いた規則で，まだ試作で確かめていない．§8 は判断待ちの点である．

## 1. 現在の制限

現行の設計は，一つの定義に**定義の候補**（元の本体と，本体の中に挿入を行った挿入後の本体）を持たせ，使用箇所ごとに候補と挿入の組合せを比べて一つを選ぶ．この方式には次の制限がある．以下の値は 2026-11-11 に Egison（60e3df3e 相当のビルド）と Lean（8f8b007）で確認した．`ts` は `[[|1,2|],[|3,4|]]` である．

**使用箇所ごとの調べ直しが終わらない．**

```
def sum2 := foldl (+) 0
def twiceSum xs := sum2 xs + sum2 xs
sum2 ts + sum2 ts        -- Egison：90 秒で終わらない
twiceSum ts              -- Egison：420 秒，Lean：400 秒で終わらない

def mysum xs := match xs as list something with
  | [] -> 0
  | $x :: $rest -> x + mysum rest
mysum ts                 -- Egison：420 秒で終わらない

def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
f [[|1,2|]] [[|3,4|]]    -- Lean：150 秒で終わらない
```

**Lean と Egison で結果が違う式がある．**（期待する結果は §5.5）

**引数を本体に代入すると値が変わる．**

```
(\x -> x + [|10,20|]) [|1,2|]    -- [|[|11,21|],[|12,22|]|]
[|1,2|] + [|10,20|]              -- [|11,22|]
```

**テンソル全体を受け取る関数を書けない場合がある．** `(\x -> [|x, x + 10|]) [|1,2|]` は成分ごとの適用になる．`x` にテンソル全体を渡す関数は，型注釈なしでは書けない．

## 2. 決定事項

2026-11-11 のユーザーの決定である．

- **D1（印）** 型推論のさいに，テンソルになりうる型に印をつける．`def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys` の型は `[Integer*p] -> [Integer*q] -> Integer*(p∨q)` である．引数の印のどれかがテンソルになれば，返り値もテンソルになる．
- **D2（そのまま渡す）** `(\x -> [|x, x + 10|]) [|1,2|]` は，成分ごとの適用にせず，テンソルをそのまま渡す．値は `[|[|1,2|],[|11,12|]|]` である．理由：適用を成分ごとにする `tensorMap` を自動で挿入すると，挿入しないほうの関数が記述できなくなる．成分ごとにしたい場合は，利用者が `tensorMap` を書ける．
- **D3（形状エラー）** `(\x -> [|x, 10|]) [|1,2|]` は形状エラーになる．
- **D4（高階関数の型）** `foldl` の型は `(b -> a -> b) -> b*p -> [a*q] -> b*(p∨q)` である（引数の順は Egison のライブラリに合わせた）．`foldl (+) 0 [[|1,2|]]` でも，利用者が `foldl` に渡す関数の型は `Integer -> Integer -> Integer` であり，`Tensor Integer -> Tensor Integer -> Tensor Integer` ではない．
- **D5（以前の決定で保つもの）**
  - `\k -> k [|1,2|]` の型は `(Tensor Integer -> a) -> a`，`\k -> tensorMap k [|1,2|]` の型は `(Integer -> a) -> Tensor a` である（2026-10-30）．
  - 高階関数の定義の本体を，使用箇所ごとに調べ直さない（2026-11-11）．
  - 利用者は，引数型，返り値型，テンソルを受け取る位置を指定しない．

同日の「関数の仮引数の適用では `tensorMap` の挿入を検討しない」という案は，D4 により次のように置き換える．関数の仮引数の適用を成分ごとにするかどうかは，定義の型付けのときに印として型に記録し，使用箇所では型だけを見て決める．

## 3. 記法と用語

- **印**：型のある位置が，スカラー型のままか `Tensor` 型になるかを表す二値の変数．値は「スカラー」か「テンソル」．`p`，`q` などの名前で区別する．英語名は未定（§8）．
- **`τ*p`**：印 `p` をつけた型．`p` がスカラーなら `τ`，テンソルなら `Tensor τ` を表す．
- **`p∨q`**：`p` か `q` のどちらかがテンソルならテンソル，どちらもスカラーならスカラー．
- **正規化**：`(τ*p)*q = τ*(p∨q)`，`(Tensor τ)*p = Tensor τ`．既存の `Tensor (Tensor τ) = Tensor τ` と合わせて使う．
- **印を消した型**：印をすべてスカラーにした型．`[Integer*p] -> Integer*p` の印を消した型は `[Integer] -> Integer` である．
- **印の値ごとの本体**：定義の型の印に値を与えたとき，その値に従って挿入を行った本体．印がすべてスカラーなら，書かれた本体そのものである．現行の「定義の候補」に代わる．

## 4. 規則

D1〜D5 から導いた規則である．形式的な定義と解く手順は，§6.1 の試作で確定する．

### 4.1 基準

**テンソルは，できるだけそのまま渡す．** 適用を成分ごとにする挿入は，挿入しない形が型付けできないときだけ行う（D2）．この基準から，引数を本体に代入した式が型付けできるなら，適用の値はその式の値と同じになる．定義を展開した場合も同じである．

### 4.2 印が生じる位置

連続適用 `f e1 … en` の各引数の位置に，その引数について適用を成分ごとにするかどうかの印を置く．`f` の仮引数型が `τi`，印が `pi` のとき，実引数は型 `τi*pi` として受け取り，結果の型は `ρ*(p1∨…∨pn)` になる．`f` は基本操作，定義，関数の仮引数のいずれでもよい．

実引数の型が決まっていれば，印はその場で決まる．実引数の型が定義の仮引数などに依存して決まらない場合，印は決まらないまま残り，定義の型に現れる．

```
\x -> x + 1             -- x : Integer*p，結果は Integer*p
\x y -> x + y           -- Integer*p -> Integer*q -> Integer*(p∨q)
\f x -> f x             -- (a -> b) -> a*p -> b*p
```

適用のない位置には印は生じない．`\x -> x` は `a -> a`，`\x -> [|x|]` は `a -> Tensor a` のままである．

### 4.3 定義の型

- 定義（`def`，`let`）の本体は一度だけ型付けする．決まらなかった印は型に残し，型変数と同じく使用箇所ごとに新しくする．
- 印の間に「`q` がテンソルなら `p` もテンソル」という関係が生じる．結果の位置にしか現れない印は，それを決める引数の印の `∨` に置き換えて整理する（`foldl` の結果 `b*(p∨q)`）．
- 再帰定義の中では，その定義自身の印は共有する．`foldl` の再帰呼び出しへ渡す累積値は，階数 0 の包含で受け取る．
- 定義を閉じる時点で，テンソルが渡される位置の型がまだ型変数のままなら，その型変数をテンソル型にする（D5 の `\k -> k [|1,2|]` では，`k` の入力の型が `Tensor Integer` になる）．
- 印を消した型は，通常の型推論の型と一致する．

### 4.4 使用箇所での決定

使用箇所では，定義の型と実引数の型から印を決める．定義の本体は調べ直さない（D5）．

テンソルが印つきの位置に来たときは，内側から順に，受けられるところで受ける．

1. その位置の型がまだ決まっていない型変数なら，型変数をテンソル型にする．何も挿入しない．
2. 適用する関数や渡された関数が，その位置に自身の印を持つなら，その印をテンソルにする．その関数がテンソル全体を受け取る．
3. 高階関数の型の印（D4）をテンソルにする．高階関数の本体の中で，関数の仮引数の適用が成分ごとになる．
4. その連続適用を成分ごとにする（持ち上げ）．関数を渡している位置では，渡す関数を変換する（§4.5）．

どれもできなければ型エラーである．テンソルが来なかった印は，スカラーにする．したがってテンソル操作のないプログラムは，印がすべてスカラーになり，通常の型推論と同じ型を持つ．

要件：

- 印は，連続適用，定義の本体，またはトップレベルの式の等式をすべて集めてから決める．引数を調べる順序で結果が変わってはならない（`e + 1` と `(\x -> x + 1) e`，`c xs + foldl (+) 0 xs` と左右を入れ替えた式が同じ結果になること）．
- スカラーでなければ型が合わない位置（`if` の条件など）へ流れる印は，先にスカラーに決める．
- 候補の列挙と比較を行わない．印の決定は，型の等式と印の間の関係を解くことだけで行う．

注意：関数の仮引数は単相なので，その関数の印も一つの使用の中で共有する．`def gp f xs := (map f xs, f 0)` に `\x -> x + 1` とテンソルのリストを渡すと，渡した関数がテンソル全体を受け取る型に決まり，`f 0` の型は `Tensor Integer`（階数 0，値は 1）になる．現行の型は `Integer` である．

### 4.5 高階関数と渡す関数

- 高階関数の型は，関数の仮引数に適用するデータの位置に印を持つ（D4）．

  ```
  foldl : (b -> a -> b) -> b*p -> [a*q] -> b*(p∨q)
  map   : (a -> b) -> [a*p] -> [b*p]
  ```

- 渡す関数の型は変えない．`foldl (+) 0 [[|1,2|]]` では `a` と `b` は `Integer` で，`q` がテンソルになる．`foldl` の印の値ごとの本体が，`fn init x` を成分ごとに適用する．
- 渡す関数が自身の印を持つ場合は，§4.4 の 2 が先になる．`map (\x -> [|x, x + 10|]) [[|1,2|]]` では，渡した関数がテンソル全体を受け取る．
- 述語のように結果の型が固定されている場合は，これまでと同じである．`filter : (a -> Bool) -> [a] -> [a]` は印を持たない．結果が `Bool` のままなら，渡した関数自身の印でテンソルを受け取れる（`filter (\x -> let unused := x + 1 in True) [[|1,2|]]`）．
- **渡す関数の変換**（`(+)` を `\u v -> tensorMap2 (+) u v` に置き換える挿入）は，§4.4 の 4 の場合だけ使う．印のないスカラー関数を，定義域がテンソル型に決まった関数引数へ渡す場合である（`def ap k := k [|1,2|]` に対する `ap ((+) 1)`）．§8 の Q3．

### 4.6 成分ごとの適用が残る場合

連続適用を成分ごとにする（§4.4 の 4）のは，仮引数の型が印のないスカラー型に決まり，実引数がテンソルのときである．印のないスカラー型になるのは次の場合である．

- 基本操作（`+`，`*` など）の仮引数．
- 型注釈でスカラー型と書いた仮引数（§8 の Q4）．
- 本体がスカラーを要求する仮引数．`def min x y := if x < y then x else y` の `x`・`y` は条件に使うので，印がスカラーに決まる．

この場合は，連続適用の等式をすべて解いたあとで，成分ごとにする引数の最小の集合を選ぶ（2026-09-28 の決定を保つ）．

### 4.7 テンソル構築式

- 成分の型は，論文の現行の規則で比べる．型のわからない成分はそのまま，型のわかる成分は `Tensor` で包んで比べる．`\x -> [|x, 10|]` の `x` はテンソルを受け取る仮引数になる．
- 成分の形状が合わない構築は，実行時の形状エラーである（D3）．型推論は，形状エラーを避けるために適用を成分ごとにすることはしない．

### 4.8 生成する式

- 定義の使用箇所では，決まった印の値に対応する「印の値ごとの本体」を使う．本体は，印がテンソルになった適用に `tensorMap`・`tensorMap2` を挿入したものである．
- 印がすべてスカラーなら，書かれた本体をそのまま使う．
- 印の値ごとの本体は，使われた組合せの分だけ作り，同じ組合せには同じものを使う．組合せを先にすべて作らない．
- `tensorMap`・`tensorMap2` はスカラーの入力も受け取る（`tensorMap2 (+) 1 2` は 3，`tensorMap2 (+) [|1,2|] 10` は `[|11,12|]`）．実装は，一部の印について同じ本体を共有してよい．ただし，仮引数がテンソル型の関数（`foldl (.) A [B]` の `.`）を成分ごとに適用してはならない．

### 4.9 変えない規則

- 階数 0 の包含，型の正規化，明示した `tensorMap`・`tensorMap2` の扱い．
- 統合型推論の性質：入力式全体が挿入なしで型付けできるなら，その式を変えない．
- 添字記法，添字補完，形状エラーの定義．
- `IO`，`IORef`，`Port` とこれらを含む型を，成分ごとの自動変換の対象にしない．

### 4.10 現行の仕組みとの対応

- 定義の候補（元の本体／挿入後の本体）→ 印つきの型と，印の値ごとの本体．
- 根拠の条件（仮引数を `Tensor` 型にしてよいかの判定）→ テンソルが来なかった印はスカラーにする，という規則．`dot` を特別に扱う必要はない．
- 優先順位（複数の導出の比較）→ §4.4 の順．
- 最小の持ち上げ集合 → §4.6 に残る．印の決定は同じ考え方を型全体へ広げたものである．
- 渡す関数の変換 → §4.5 の最後の場合だけに残る．

## 5. 例と期待する結果

実装の受け入れ検査に使う．`inc` は `def inc x := x + 1`，`A` は `[|1,2|]~i`，`B` は `[|10,20|]_i`，`ts` は `[[|1,2|],[|3,4|]]` である．

### 5.1 定義の型

```
foldl : (b -> a -> b) -> b*p -> [a*q] -> b*(p∨q)
map   : (a -> b) -> [a*p] -> [b*p]
filter : (a -> Bool) -> [a] -> [a]

def inc x := x + 1                    -- Integer*p -> Integer*p
def sum xs := foldl (+) 0 xs          -- [Integer*p] -> Integer*p
def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
                                      -- [Integer*p] -> [Integer*q] -> Integer*(p∨q)
def g xs ys := (foldl (+) 0 xs, foldl (+) 0 ys)
                                      -- [Integer*p] -> [Integer*q] -> (Integer*p, Integer*q)
def (.) u v := contractWith (\x y -> x + y) (u * v)
                                      -- Integer*p -> Integer*q -> Tensor Integer
def apply k x := k x                  -- (a -> b) -> a*p -> b*p
def min x y := if x < y then x else y -- Integer -> Integer -> Integer（印なし）

\x -> x                               -- a -> a
\x -> [|x|]                           -- a -> Tensor a
\x -> [|x, x + 10|]                   -- Integer*p -> Tensor Integer
\k -> k [|1,2|]                       -- (Tensor Integer -> a) -> a
\k -> tensorMap k [|1,2|]             -- (Integer -> a) -> Tensor a
```

`g` の型のように，印は名前で区別する．`g ts [5,6]` の型は `(Tensor Integer, Integer)` である．

### 5.2 値が変わる例

### 5.5 Lean と Egison で結果が違う例

```
(\f x -> [|f x, x|]) (\y -> y + 1) [|1,2|]
  -- Lean：[|[|2,1|],[|3,2|]|]   Egison：[|[|2,3|],[|1,2|]|]   期待：[|[|2,3|],[|1,2|]|]
(\f -> f B) (dot A)
  -- Lean：[|[|10,20|],[|20,40|]|]   Egison：50   期待：50
(\g -> g A B) dot
  -- Lean：[|10,40|]   Egison：50   期待：50
map (dot A) [B]
  -- Lean：[[|[|10,20|],[|20,40|]|]]   Egison：[50]   期待：[50]
foldl dot A [B]
  -- Lean：[|10,40|]   Egison：50   期待：50
(\x -> [|x, 10|]) [|1,2|]
  -- Lean：形状エラー   Egison：[|[|1,10|],[|2,10|]|]   期待：形状エラー（D3）
[| [|1,2|], 10 |]
  -- Lean：形状エラー   Egison：型エラー   期待：§8 の Q2
```

`dot` は `def dot u v := contractWith (\x y -> x + y) (u * v)` である．

### 5.6 成分ごとの適用が残る例

```
(\x -> if x > 0 then 1 else 0) [|1,-2|]          -- [|1,0|]
map (\x -> if x > 0 then 1 else 0) [[|1,-2|]]    -- [[|1,0|]]

def hIf x k := if k x > 0 then 1 else 0
hIf [|1,-2|] inc                                 -- [|1,0|]
```

`hIf` では，`k` の結果が条件に使われるのでスカラーに決まる．`inc` を渡すと `x` の型は `Integer` になり，連続適用の等式を解いたあとで第一引数を成分ごとにする．

### 5.7 成分ごとの適用を書く方法

```
tensorMap (\x -> [|x, x + 10|]) [|1,2|]          -- [|[|1,11|],[|2,12|]|]

def mkS (x : Integer) : Tensor Integer := [|x, x + 10|]
mkS [|1,2|]                                      -- [|[|1,11|],[|2,12|]|]（§8 の Q4）
```
