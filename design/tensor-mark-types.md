# テンソルになりうる位置の印（提案と作業の指示）

状態：**提案**（未実装）．2026-11-11 の検討で決まった方針をまとめた指示書である．Egison，論文（`~/PL/type-tensor-paper`），Lean の機械化（`~/PL/type-tensor-mech`）は，この文書に従ってあとでまとめて直す．実装したら内容を仕様の文書（[type-tensor-simple.md](type-tensor-simple.md) など）へ移し，この文書を削除する．

用語は `EgisonTERM.md` §9 に従う．**挿入**は `tensorMap`・`tensorMap2` の呼び出しを式に加えること，**持ち上げ**はスカラー型の仮引数にテンソルを渡す適用を成分ごとの適用にすること，**階数 0 の包含**はスカラーを値も式も変えずに階数 0 のテンソルとして扱うことである．この文書で新しく使う語は §3 で定義する．

この文書の内容は三種類に分かれる．§2 はユーザーの決定である．§4 はそこから導いた規則で，まだ試作で確かめていない．§8 は判断待ちの点である（残りは一点）．

## 1. 現在の制限

現行の設計は，一つの定義に**定義の候補**（元の本体と，本体の中に挿入を行った挿入後の本体）を持たせ，使用箇所ごとに候補と挿入の組合せを比べて一つを選ぶ．この方式には次の制限がある．以下の値は 2026-11-11 に Egison（60e3df3e 相当のビルド）と Lean（8f8b007）で確認した．`ts` は `[[|1,2|],[|3,4|]]` である．

**使用箇所ごとの調べ直しが終わらない．**

```
def sum2 := foldl (+) 0
def twiceSum xs := sum2 xs + sum2 xs
sum2 ts + sum2 ts        -- Egison：90 秒で終わらない
twiceSum ts              -- Egison：420 秒，Lean：400 秒で終わらない

def mysum xs := match xs as list something with
  | [] -> 0
  | $x :: $rest -> x + mysum rest
mysum ts                 -- Egison：420 秒で終わらない

def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
f [[|1,2|]] [[|3,4|]]    -- Lean：150 秒で終わらない
```

**Lean と Egison で結果が違う式がある．**（期待する結果は §5.5）

**積の定義が二つの候補を持つ．** `def (.) u v := contractWith (\x y -> x + y) (u * v)` は，`u`・`v` が整数の元の本体と，テンソルの挿入後の本体を持ち，優先順位で選ぶ．この選択が，積を高階関数へ渡したときの結果の違い（§5.5）の原因になっている．

**テンソル構築式の成分に書いた仮引数が，テンソル全体を受け取れない．** `(\x -> [|x, x + 10|]) [|1,2|]` は成分ごとの適用になる．成分ごとの適用が自動で入ると，`x` にテンソル全体を渡す関数が書けない．

## 2. 決定事項

2026-11-11 のユーザーの決定である．

- **D1（印）** 型推論のさいに，テンソルになりうる型に印をつける．`def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys` の型は `[Integer*p] -> [Integer*q] -> Integer*(p∨q)` である．引数の印のどれかがテンソルになれば，返り値もテンソルになる．
- **D2（高階関数の型）** `foldl` の型は `(b -> a -> b) -> b*p -> [a*p] -> b*p` である（引数の順は Egison のライブラリに合わせた）．初期値，リスト要素，返り値には同じ印 `p` を使う．再帰呼び出しでは演算結果を次の累積値に渡すため，返り値がテンソルなら累積値の引数もテンソルでなければならない．これは以前の設計で結果と累積値の型を共有していたことの延長である．`foldl (+) 0 [[|1,2|]]` では `p` がテンソルになり，初期値 `0` は階数 0 の包含で受け取る．利用者が書く `(+)` の型は `Integer -> Integer -> Integer` のままである．D18 に従い，`foldl` へ渡す箇所で `\u v -> tensorMap2 (+) u v` に包む．挿入後に `foldl` が受け取る関数の型は `Tensor Integer -> Tensor Integer -> Tensor Integer` になる．
- **D3（スカラー関数）** `def inc x := x + 1` の型は `Integer -> Integer` である．テンソルを適用したときに，その適用に `tensorMap` が挿入され，適用の型が変わる．
- **D4（テンソル型の位置から決まる仮引数）** `def (.) u v := contractWith (\x y -> x + y) (u * v)` の型は `Tensor Integer -> Tensor Integer -> Tensor Integer` である．`contractWith` があることから，引数も `Tensor` であることがわかる．
- **D5（テンソル構築式の成分）** `\x -> [|x|]` の型は `Tensor a -> Tensor a`，`\x -> [|x, x + 10|]` の型は `Tensor Integer -> Tensor Integer` である．`(\x -> [|x, x + 10|]) [|1,2|]` はテンソルをそのまま渡し，値は `[|[|1,2|],[|11,12|]|]` になる．理由：この適用に `tensorMap` を自動で挿入すると，挿入しないほうの関数が記述できなくなる．
- **D6（形状エラー）** `(\x -> [|x, 10|]) [|1,2|]` は形状エラーになる．
- **D7（成分がスカラー関数の適用である場合）** `(\x -> [|x * 2, x + 10|]) [|1,2|]` は，引数をテンソルとしてそのまま受け取り，`[|[|2,4|],[|11,12|]|]` を返す．
- **D8（仮引数そのものではない位置）** `\xs -> head xs + 1` の型は `[Integer*p] -> Integer*p` であり，`(\xs -> head xs + 1) [[|1,2|]]` は `[|2,3|]` を返す．`tensorMap` が挿入されるのは `head xs` に対してだからである．
- **D9（以前の決定で保つもの）**
  - `\k -> k [|1,2|]` の型は `(Tensor Integer -> a) -> a`，`\k -> tensorMap k [|1,2|]` の型は `(Integer -> a) -> Tensor a` である（2026-10-30）．
  - 高階関数の定義の本体を，使用箇所ごとに調べ直さない（2026-11-11）．
  - 利用者は，引数型，返り値型，テンソルを受け取る位置を指定しない．
- **D10（関数の仮引数に渡す仮引数）** `def h x k := [|k x + 10, k x + 20|]` の `h [|1,2|] inc` は `[|[|12,13|],[|22,23|]|]` になる．D18 に従い，`h` へ渡す `inc` を `\t -> tensorMap inc t` に包む．`h` の本体では，二つの `k x` が同じ関数をそのまま呼ぶ．既知の演算である `+ 10` と `+ 20` への挿入は，テンソル構築式の成分の型から決める．
- **D11（直接書いた不揃いのテンソル構築式）** `[| [|1,2|], 10 |]` は，型エラーではなく実行時の形状エラーにする．2026-09-28 の決定（成分はすべて同じ型）は，この決定で置き換える．
- **D12（渡す関数の変換）** `(\k -> k [|1,2|]) inc` は動く．`Tensor Integer -> a` を期待する位置に `Integer -> Integer` の関数を渡したら，`tensorMap` を挿入する．
- **D13（型注釈）** スカラー型の注釈（`(x : Integer)`）をつけた仮引数は，印のないスカラー型になる．型変数の注釈（ライブラリの `foldl` の `(init : b)`）をつけた位置には，印がつきうる．
- **D14（型の表示）** 推論した型には，印を利用者に見せる．
- **D15（リストに入れて高階関数へ渡す仮引数）** `(\x -> map (\y -> y + 1) [x]) [|1,2|]` は `[[|2,3|]]` になる．`map` の型から `x` に印がつく．
- **D16（述語の本体内の挿入）** `filter (\x -> let unused := x + 1 in True) [[|1,2|]]` は，`filter (\x -> let unused := tensorMap2 (+) x 1 in True) [[|1,2|]]` へ挿入する．述語はテンソル全体を受け取り，返り値は `Bool` のままである．
- **D17（テンソル型が期待される位置への挿入）** `\x -> tensorShape (x + 1)` は，`\x -> tensorShape (tensorMap (\z -> z + 1) x)` にする．型は `Tensor Integer -> [Integer]` である．`x` がスカラーでも，挿入後の式は同じ整数のリストを返す．テンソル型がもともと期待される位置から決まる挿入は，スカラー入力でも行ってよい．この決定により，「入力式全体が挿入なしで型付けできるなら，その式を変えない」という原則に，この挿入の例外を設ける．その場合は，階数 0 の入力に対する評価結果を保つ．
- **D18（関数を渡すときに一度だけ挿入を決める）** 高階関数の本体にある，まだ型が確定していない関数の仮引数の適用について，`tensorMap`・`tensorMap2` を挿入するかどうかを個別に検討しない．その高階関数に実際の関数を渡す箇所で，受け取り側と渡す側の型から一度だけ決める．本体では，同じ仮引数を使うすべての箇所で，渡された同じ関数と型を共有する．`def gp k xs := (map k xs, k 0)` の `gp inc [[|1,2|]]` は，`gp (\t -> tensorMap inc t) [[|1,2|]]` にする．値は `([[|2,3|]], 1)`，型は `([Tensor Integer], Tensor Integer)` である．以前の期待型 `([Tensor Integer], Integer)` はこの決定で置き換える．`gp` の本体の `map k xs` と `k 0` を別々に変換しない．

ユーザーが示した型の一覧（2026-11-11）．高階関数の関数引数の型は，利用者が挿入前に渡す関数の型を表す．挿入後に本体が受け取る関数の型との対応は §4.4 に示す．§4 の規則がこの一覧を導くことを，§6.1 の試作で検証する．

```
foldl : (b -> a -> b) -> b*p -> [a*p] -> b*p
map   : (a -> b) -> [a*p] -> [b*p]
filter : (a -> Bool) -> [a] -> [a]

def inc x := x + 1                    -- Integer -> Integer
def sum xs := foldl (+) 0 xs          -- [Integer*p] -> Integer*p
def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
                                      -- [Integer*p] -> [Integer*q] -> Integer*(p∨q)
def g xs ys := (foldl (+) 0 xs, foldl (+) 0 ys)
                                      -- [Integer*p] -> [Integer*q] -> (Integer*p, Integer*q)
def (.) u v := contractWith (\x y -> x + y) (u * v)
                                      -- Tensor Integer -> Tensor Integer -> Tensor Integer
def apply k x := k x                  -- (a -> b) -> a*p -> b*p
def min x y := if x < y then x else y -- Integer -> Integer -> Integer

\x -> x                               -- a -> a
\x -> [|x|]                           -- Tensor a -> Tensor a
\x -> [|x, x + 10|]                   -- Tensor Integer -> Tensor Integer
\k -> k [|1,2|]                       -- (Tensor Integer -> a) -> a
\k -> tensorMap k [|1,2|]             -- (Integer -> a) -> Tensor a
```

D18 は，関数の仮引数の適用ごとに印を置いて本体内へ挿入する，この文書の以前の案を置き換える．定義時には，仮引数が共有する型とその制約を記録する．使用箇所では，高階関数の型と渡す関数の型から，渡す箇所での挿入を一度だけ決める．高階関数の本体を調べ直したり，同じ関数の適用ごとに別の挿入を選んだりしない．

## 3. 記法と用語

- **印**：型のある位置が，スカラー型のままか `Tensor` 型になるかを表す二値の変数．値は「スカラー」か「テンソル」．`p`，`q` などの名前で区別する．英語名は未定（§8 の Q1）．
- **`τ*p`**：印 `p` をつけた型．`p` がスカラーなら `τ`，テンソルなら `Tensor τ` を表す．
- **`p∨q`**：`p` か `q` のどちらかがテンソルならテンソル，どちらもスカラーならスカラー．
- **正規化**：`(τ*p)*q = τ*(p∨q)`．既存の `Tensor (Tensor τ) = Tensor τ` と合わせて使う．`τ` が `Tensor` 型に決まった場合，その位置の印はスカラーに決める（`Tensor` 型の値を受け取る関数を成分ごとに適用しないため）．
- **印を消した型**：印をすべてスカラーにした型．`[Integer*p] -> Integer*p` の印を消した型は `[Integer] -> Integer` である．
- **印の値ごとの本体**：定義の型の印に値を与えたとき，その値に従って挿入を行った本体．印がすべてスカラーなら，印に基づく挿入は行わない．テンソル型の位置から決まる挿入は，印の値によらず残す（D17，§4.6）．
- **テンソル型の位置**：`Tensor` 型の仮引数（`contractWith` の第二引数，`tensorShape` の引数，`tensorMap` の第二引数など）と，テンソル構築式の成分．

## 4. 規則

D1〜D18 から導いた規則である．形式的な定義と解く手順は，§6.1 の試作で確定する．

### 4.1 定義の本体での型の決め方

型がまだ決まっていない式（仮引数，リストの要素，関数の仮引数の結果など）の型は，その式の使われ方から決める．番号の小さい規則を優先する．

1. **テンソル型の位置へ流れる式は，`Tensor` 型にする**（D4，D5，D7，D17）．スカラー関数の適用の結果がテンソル型の位置へ流れる場合は，その適用を成分ごとにし，型が決まっていない引数を `Tensor` 型にする．スカラー関数に直接渡していても，この規則を優先する．

   ```
   \x -> [|x|]                  -- x は成分．Tensor a -> Tensor a
   \x -> [|x, x + 10|]          -- x は成分．x + 10 は本体の中で成分ごとにする
   \x -> [|x * 2, x + 10|]      -- x * 2 と x + 10 が成分．Tensor Integer -> Tensor Integer
   \u v -> contractWith (\x y -> x + y) (u * v)
                                -- u * v が contractWith の Tensor 型の仮引数へ流れる
   \x -> tensorShape (x + 1)    -- Tensor Integer -> [Integer]
   ```

   最後の例では，`tensorShape` の入力が `Tensor` 型なので，`x` を `Tensor Integer` に決め，本体を `\x -> tensorShape (tensorMap (\z -> z + 1) x)` にする（D17）．あとでスカラーを渡す場合も同じ本体を使う．例えば `5` は階数 0 として受け取り，`tensorMap (\z -> z + 1) 5` は `6`，その形状は `[]` である．挿入なしのスカラー入力での計算と，値も返り値型 `[Integer]` も一致する．

2. **関数の仮引数の適用は，共有する関数型で通常の適用として型付けする**（D18）．本体の `k e` ごとに挿入するかどうかを選ばず，`k` の入力・結果と `e` の型の関係を記録する．同じ `k` を複数回使う場合も，一つの関数型を共有する．高階関数の印は，実際の関数を渡す箇所での挿入と，その関数の入力・結果に関係するデータの型を表す．

   ```
   \k x -> k x                  -- (a -> b) -> a*p -> b*p
   ```

   この型の先頭の `a -> b` は，利用者が渡す挿入前の関数の型である．挿入後に本体が受け取る `k` の型は `a*p -> b*p` であり，`k x` 自体には挿入しない．`k` を別の高階関数へ渡す場合も，型が未確定の仮引数を渡す箇所で独立した変換を選ばず，共有する型の制約を伝える．`gp` の `map k xs` と `k 0` はこの規則で同じ関数型を使う．

3. **外側の式からテンソル型に決まる制約も印もない仮引数を，スカラー関数に直接渡す場合は，スカラー型にする**（D3）．印はつけない．テンソルを渡す適用は，適用の側で成分ごとにする（§4.3）．

   ```
   \x -> x + 1                  -- Integer -> Integer
   \x -> x + [|10,20|]          -- Integer -> Tensor Integer
   ```

   引数として直接書いたラムダ式では，受け取り側の関数とほかの実引数の型の等式も反映してから，仮引数の型を決める．D16 の `filter` では，リストから述語の入力が `Tensor Integer` に決まるため，ラムダ式の `x` も `Tensor Integer` になる．本体の `x + 1` に `tensorMap2 (+) x 1` を挿入し，最後の `True` はそのままにする．これは同じ入力式の型の等式をまとめて解く処理であり，型を確定した定義の本体を使用箇所ごとに推論し直すことではない．

   仮引数そのものではない位置（リストの要素，関数の仮引数の結果など）にスカラー関数を直接適用する場合は，印つきのスカラー型にする（D8）．`head xs + 1` で `tensorMap` が挿入されるのは `head xs` に対してであり，定義を適用する側では挿入できないためである．

   ```
   \xs -> head xs + 1           -- [Integer*p] -> Integer*p
   ```

4. **印つきの型の式にスカラー関数を適用すると，結果にも印がつく**（D1）．印がテンソルになったとき，その適用が成分ごとになる．

5. **それ以外は型変数のままにする．** `\x -> x` は `a -> a` である．定義を閉じる時点で，テンソルを渡している関数の仮引数の入力の型が型変数のままなら，`Tensor` 型にする（D9 の `\k -> k [|1,2|]`）．

スカラーでなければ型が合わない位置（`if` の条件など）へ流れる印は，スカラーに決める．`filter` の `p x` の結果は条件に使うので，`filter : (a -> Bool) -> [a] -> [a]` には印が残らない．`min` も同じである．

### 4.2 定義の型

- 定義（`def`，`let`）の本体は一度だけ型付けする．決まらなかった印は型に残し，型変数と同じく使用箇所ごとに新しくする．
- 印の間に「`q` がテンソルなら `p` もテンソル」という関係が生じる．結果の位置にしか現れない印は，それを決める引数の印の `∨` に置き換えて整理する（D1 の `f` の結果 `Integer*(p∨q)`）．異なる定義の使用箇所の印は，型の制約が結び付けない限り独立である．`f` の二つの `foldl` の使用には，それぞれ別の印を使う．
- 再帰定義の中では，その定義自身の印は共有する．`foldl` では，返り値と次の再帰呼び出しへ渡す累積値の型をそろえ，初期値，リスト要素，返り値を同じ印 `p` で表す（D2）．`p` がテンソルなら，呼び出し側で変換した関数を受け取る．本体の `fn init x` はそのままで，結果と同じ `fn` を再帰呼び出しへ渡す（D18）．初期値がスカラーでも，ほかの引数から `p` がテンソルに決まれば，その初期値を階数 0 の包含で受け取る．初期値がテンソルでリスト要素がスカラーの場合も，同じ `p` を使い，各要素を階数 0 として受け取る．
- 印を消した型は，テンソル操作のない定義では通常の型推論の型と一致する．
- テンソル型の位置から決まった仮引数（規則 1）を持つ定義は，型が一つである．スカラーの実引数は階数 0 の包含で受け取る（`2 . 3` は 6）．元の本体と挿入後の本体を比べない．
- 型注釈がある場合（D13）：スカラー型の注釈をつけた仮引数は，印のないスカラー型になる．型変数の注釈をつけた位置には，本体の型付けから印がつきうる．注釈に書かれた型は，印を消した型と一致しなければならない．
- 推論した型を利用者に示すときは，印をこの文書の記法（`Integer*p`，`Integer*(p∨q)`）で表示する（D14）．

### 4.3 使用箇所での決定

使用箇所では，定義の型と実引数の型から挿入を決める．定義の本体は調べ直さない（D9）．テンソルを渡す位置の仮引数の型によって，次のようになる．

- **型変数**：型変数をテンソル型にして，そのまま渡す．
- **`Tensor` 型**：そのまま渡す．
- **印つきの型**：印をテンソルにする．関数引数に結び付く印は，その高階関数へ実際の関数を渡す箇所での挿入を決める（D18）．既知のスカラー演算への適用に結び付く印は，その適用への挿入を決める（D1，D8）．
- **印のないスカラー型**：その連続適用を成分ごとにする（持ち上げ，D3）．連続適用の等式をすべて解いたあとで，成分ごとにする引数の最小の集合を選ぶ（2026-09-28 の決定を保つ）．

どれにも当てはまらなければ型エラーである．型の等式と印の間の関係を解いたあと，テンソルに決める制約がない印をスカラーにする．一つの実引数がスカラーであることだけでは，共有する印をスカラーに固定しない．例えば `foldl (+) 0 [[|1,2|]]` の `p` は，リスト要素からテンソルに決まり，`0` を階数 0 として受け取る．テンソル操作のないプログラムは，印がすべてスカラーになり，通常の型推論と同じ型を持つ．

要件：

- 印と持ち上げは，連続適用，定義の本体，またはトップレベルの式の等式をすべて集めてから決める．引数を調べる順序で結果が変わってはならない（`c xs + foldl (+) 0 xs` と左右を入れ替えた式が同じ結果になること）．
- D18 の「一度だけ」は，高階関数に関数を渡す各使用箇所を単位とする．第一引数だけを見て即座に確定するという意味ではない．`foldl (+)` のように後続の引数の型が必要な部分適用では，その制約がそろうまで印を保留する．同じ仮引数を受け渡す本体内の各箇所で，別の挿入を選ぶことはしない．
- 候補の列挙と比較を行わない．印の決定は，型の等式と印の間の関係を解くことだけで行う．
- 印が入れ子になる場合（`(τ*p)*q`）は，内側の印を先にテンソルにする．

### 4.4 高階関数と渡す関数

- **渡す関数の変換**は，高階関数へ実際の関数を渡す箇所で，その使用の型の制約から一度だけ決める（D18）．例えば `inc` を `\t -> tensorMap inc t` に包む．受け取った高階関数の本体では，仮引数の各適用に別の挿入を加えない．
- §2 の型に書いた関数引数の型は，挿入前の関数の型である．挿入後に本体が受け取る関数は，データの印も反映した型を持つ．`foldl` なら，挿入前の `b -> a -> b` に対して，受け取る関数は `b*p -> a*p -> b*p` である．`map` と `apply` でも，挿入前の `a -> b` に対して，受け取る関数は `a*p -> b*p` になる．これらの対応を通常の関数型の等式と区別して表す方法は，§6.1 で確定する．
- `foldl (+) 0 [[|1,2|]]` では `a` と `b` は `Integer` で，共有する `p` がテンソルになる．呼び出し側で `(+)` を `\u v -> tensorMap2 (+) u v` に包む．本体の `fn init x` はそのまま呼び出し，初期値と各段階の累積値を同じ `Tensor Integer` 型として受け取る．`0` は階数 0 であり，再帰呼び出しでも同じ変換済みの関数を渡す．
- 渡す関数の入力が `Tensor` 型なら，印はスカラーのままで，関数がテンソル全体を受け取る．`foldl (.) A [B]` は `A . B` を計算する．
- 結果の型が固定されている場合は，これまでと同じである．`filter` へ渡す述語全体を成分ごとにして `Tensor Bool` を返すことはできない．本体内の演算へ挿入しても最後の結果が `Bool` のままなら，テンソルのリストに使える（D16）．
- D12 の `(\k -> k [|1,2|]) inc` も，同じく `inc` を渡す箇所で変換する．受け取り側の入力が最初からテンソル型である場合と，印からテンソル型に決まる場合で，挿入の箇所を分けない．

```
foldl (+) 0 [[|1,2|],[|3,4|]]
  → foldl (\u v -> tensorMap2 (+) u v) 0 [[|1,2|],[|3,4|]]

gp inc [[|1,2|]]
  → gp (\t -> tensorMap inc t) [[|1,2|]]
```

`gp` は `def gp k xs := (map k xs, k 0)` である．挿入後は `k : Tensor Integer -> Tensor Integer` を両方の箇所で共有する．`map k xs` の型は `[Tensor Integer]`，`k 0` の型は `Tensor Integer` になる．`k 0` には `0` を階数 0 として渡し，値は `1` である．右側の型だけを `Integer` に戻すための別の関数や，`map k xs` の箇所だけの変換を作らない．

D16 の型の等式と挿入は次のようになる．`filter : (a -> Bool) -> [a] -> [a]` の `a` は，リスト要素から `Tensor Integer` に決まる．その型を直接書いたラムダ式の `x` にも伝え，既知の演算である加算だけを成分ごとにする．`unused` は `Tensor Integer` になるが，述語の返り値は `True : Bool` である．`filter` の定義内の述語の適用は変更しない．渡すラムダ式の本体の型付けと，高階関数の本体内の未確定の関数の適用に挿入を選ぶことは区別する．

```
filter (\x -> let unused := x + 1 in True) [[|1,2|]]
  → filter (\x -> let unused := tensorMap2 (+) x 1 in True) [[|1,2|]]
```

述語の型は `Tensor Integer -> Bool`，式全体の型は `[Tensor Integer]`，値は `[[|1,2|]]` である．

### 4.5 テンソル型の位置

- テンソル構築式の成分は，テンソル型の位置である（D5）．型のわからない成分は `Tensor a` 型になる．これは論文の現行の規則（型のわからない成分はそのままにする）からの変更である．
- 成分の型は `Tensor` で包んで比べる．スカラーの成分は階数 0 の包含で受け取る．
- 成分の形状が合わない構築は，実行時の形状エラーである（D6）．型推論は，形状エラーを避けるために適用を成分ごとにすることはしない．直接書いた `[| [|1,2|], 10 |]` も，型エラーにせず実行時の形状エラーにする（D11）．
- 仮引数がテンソル構築式の成分でなく，構築式と並ぶ引数である場合は，規則 1 は当てはまらない．`\x -> x + [|10,20|]` の `x` はスカラー型のままである．

### 4.6 生成する式

- 印を持つ定義の使用箇所では，確定した印から，既知の演算への挿入と，実際の関数を渡す箇所での挿入を生成する．例えば `sum` の本体では，`foldl` へ渡す `(+)` を包むかどうかが印によって変わる．このように生成する式が変わる定義には「印の値ごとの本体」を使う．未確定の関数の仮引数の適用ごとに挿入を選んだ本体は作らない（D18）．印がすべてスカラーなら，印に基づく挿入は行わない．テンソル型の位置から決まる挿入は，印の値によらず行う（D17）．
- 印の値ごとの本体は，使われた組合せの分だけ作り，同じ組合せには同じものを使う．組合せを先にすべて作らない．
- `foldl`・`map`・`gp` のように，関数の仮引数を呼ぶかそのまま渡すだけの部分は変更しない．呼び出し側で包んだ関数を渡し，定義内では同じ関数を共有する．この挿入のために，`foldl` の `fn init x` を変更した別の本体や，`gp` の `k` の使用ごとに変換を選ぶ本体を作らない．
- テンソル型の位置から決まった仮引数を持ち，印による挿入の違いがない定義（`.` など）は，挿入を行った本体を一つだけ持つ（`\u v -> contractWith (\x y -> x + y) (tensorMap2 (*) u v)`）．`tensorMap`・`tensorMap2` はスカラーの入力も受け取るので（`tensorMap2 (*) 2 3` は 6），スカラーの実引数にも同じ本体を使う．D17 の `\x -> tensorShape (x + 1)` も同じ扱いであり，スカラー入力用に挿入なしの別の本体を作らない．

### 4.7 保つ規則と，挿入なし型付けの扱い

- 階数 0 の包含，型の正規化，明示した `tensorMap`・`tensorMap2` の扱い．
- テンソル型の位置から §4.1 の規則 1 で決まる挿入は，入力式全体に挿入なしの型付けがあっても行う（D17）．この場合，式そのものを保つことに代えて，階数 0 の入力に対する評価結果を保つ．例えば `\x -> tensorShape (x + 1)` は本体が変わるが，スカラー入力では挿入前後とも `[] : [Integer]` を返す．
- 上の挿入以外については，入力式全体が挿入なしで型付けできるなら，その式を変えないという原則を保つ．テンソル型の位置からの根拠がない挿入を，D17 を理由に追加しない．
- 添字記法，添字補完，形状エラーの定義．
- `IO`，`IORef`，`Port` とこれらを含む型を，成分ごとの自動変換の対象にしない．

階数 0 の包含そのものは，従来どおり値も式も変えない．D17 で追加するのは，テンソル型の位置へ結果を渡す演算を成分ごとにするための `tensorMap`・`tensorMap2` である．この区別を，型付け規則と保存の定理にも反映する．

### 4.8 現行の仕組みとの対応

- 定義の候補（元の本体／挿入後の本体）→ 二つに分かれる．`sum` のように使用箇所で決まるものは，印つきの型と印の値ごとの本体になる．`.` のようにテンソル型の位置から決まるものは，挿入を行った一つの本体になる．
- 根拠の条件 → 規則 1 として残る．起点にテンソル構築式の成分を加える．根拠のある挿入後の本体は，候補の一つではなく，その定義のただ一つの本体になる．
- 優先順位（複数の導出の比較）→ 不要になる．§4.1 の規則の順と §4.3 で決まる．
- 最小の持ち上げ集合 → §4.3 に残る．
- 渡す関数の変換 → 高階関数へ実際の関数を渡す箇所で，一度だけ決める（D18，§4.4）．未確定の関数の仮引数の各適用への挿入を，この方式へ置き換える．

### 5.7 テンソル型が期待される位置への挿入

D17 では，スカラー入力での値だけでなく，生成する本体も検査する．

```
\x -> tensorShape (x + 1)
  → \x -> tensorShape (tensorMap (\z -> z + 1) x)
```

推論する型は `Tensor Integer -> [Integer]` である．同じ挿入後の本体を，次の両方に使う．

```
(\x -> tensorShape (x + 1)) 5         -- [] : [Integer]
(\x -> tensorShape (x + 1)) [|1,2|]   -- [2] : [Integer]
```

スカラー入力の場合，挿入前の式も `[] : [Integer]` を返す．この一致と，本体への挿入が行われることを両方確かめる．

### 5.8 高階関数へ渡す箇所での一度だけの挿入

D18 では，型と値に加え，挿入する箇所を検査する．

```
def gp k xs := (map k xs, k 0)
gp inc [[|1,2|]]
  → gp (\t -> tensorMap inc t) [[|1,2|]]
```

- 値は `([[|2,3|]], 1)`，型は `([Tensor Integer], Tensor Integer)` である．値は以前の期待と同じで，右側の型が `Integer` から `Tensor Integer` に変わる．
- `gp` の本体は `(map k xs, k 0)` のままである．両方に同じ `k : Tensor Integer -> Tensor Integer` を使う．`map` に渡す箇所だけで `k` を包んだり，`k 0` だけに別の挿入を選んだりしない．
- スカラーのリストを渡す `gp inc [1,2]` は，`inc` を包まずに `([2,3], 1) : ([Integer], Integer)` を返す．異なる呼び出しの判断は独立である．
- `foldl (+) 0 [[|1,2|],[|3,4|]]` は §4.4 の挿入で `[|4,6|]` を返す．`foldl` の本体の `fn init x` と再帰呼び出しは変更せず，最初に渡した同じ関数を使う．
- `(foldl (+)) 0 ts` と `(\g -> g 0 ts) (foldl (+))` も検査し，部分適用で判断が早すぎるためにテンソル入力を扱えなくなることがないようにする．
