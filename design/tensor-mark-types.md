# テンソルになりうる位置の印（提案と作業の指示）

状態：**提案**（未実装）．2026-11-11 の検討で決まった方針をまとめた指示書である．Egison，論文（`~/PL/type-tensor-paper`），Lean の機械化（`~/PL/type-tensor-mech`）は，この文書に従ってあとでまとめて直す．実装したら内容を仕様の文書（[type-tensor-simple.md](type-tensor-simple.md) など）へ移し，この文書を削除する．

用語は `EgisonTERM.md` §9 に従う．**挿入**は `tensorMap`・`tensorMap2` の呼び出しを式に加えること，**持ち上げ**はスカラー型の仮引数にテンソルを渡す適用を成分ごとの適用にすること，**階数 0 の包含**はスカラーを値も式も変えずに階数 0 のテンソルとして扱うことである．この文書で新しく使う語は §3 で定義する．

この文書の内容は三種類に分かれる．§2 はユーザーの決定である．§4 はそこから導いた規則で，まだ試作で確かめていない．§8 は判断待ちの点である．

## 1. 現在の制限

現行の設計は，一つの定義に**定義の候補**（元の本体と，本体の中に挿入を行った挿入後の本体）を持たせ，使用箇所ごとに候補と挿入の組合せを比べて一つを選ぶ．この方式には次の制限がある．以下の値は 2026-11-11 に Egison（60e3df3e 相当のビルド）と Lean（8f8b007）で確認した．`ts` は `[[|1,2|],[|3,4|]]` である．

**使用箇所ごとの調べ直しが終わらない．**

```
def sum2 := foldl (+) 0
def twiceSum xs := sum2 xs + sum2 xs
sum2 ts + sum2 ts        -- Egison：90 秒で終わらない
twiceSum ts              -- Egison：420 秒，Lean：400 秒で終わらない

def mysum xs := match xs as list something with
  | [] -> 0
  | $x :: $rest -> x + mysum rest
mysum ts                 -- Egison：420 秒で終わらない

def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
f [[|1,2|]] [[|3,4|]]    -- Lean：150 秒で終わらない
```

**Lean と Egison で結果が違う式がある．**（期待する結果は §5.5）

**積の定義が二つの候補を持つ．** `def (.) u v := contractWith (\x y -> x + y) (u * v)` は，`u`・`v` が整数の元の本体と，テンソルの挿入後の本体を持ち，優先順位で選ぶ．この選択が，積を高階関数へ渡したときの結果の違い（§5.5）の原因になっている．

**テンソル構築式の成分に書いた仮引数が，テンソル全体を受け取れない．** `(\x -> [|x, x + 10|]) [|1,2|]` は成分ごとの適用になる．成分ごとの適用が自動で入ると，`x` にテンソル全体を渡す関数が書けない．

## 2. 決定事項

2026-11-11 のユーザーの決定である．

- **D1（印）** 型推論のさいに，テンソルになりうる型に印をつける．`def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys` の型は `[Integer*p] -> [Integer*q] -> Integer*(p∨q)` である．引数の印のどれかがテンソルになれば，返り値もテンソルになる．
- **D2（高階関数の型）** `foldl` の型は `(b -> a -> b) -> b*p -> [a*q] -> b*(p∨q)` である（引数の順は Egison のライブラリに合わせた）．`foldl (+) 0 [[|1,2|]]` でも，利用者が `foldl` に渡す関数の型は `Integer -> Integer -> Integer` であり，`Tensor Integer -> Tensor Integer -> Tensor Integer` ではない．
- **D3（スカラー関数）** `def inc x := x + 1` の型は `Integer -> Integer` である．テンソルを適用したときに，その適用に `tensorMap` が挿入され，適用の型が変わる．
- **D4（テンソル型の位置から決まる仮引数）** `def (.) u v := contractWith (\x y -> x + y) (u * v)` の型は `Tensor Integer -> Tensor Integer -> Tensor Integer` である．`contractWith` があることから，引数も `Tensor` であることがわかる．
- **D5（テンソル構築式の成分）** `\x -> [|x|]` の型は `Tensor a -> Tensor a`，`\x -> [|x, x + 10|]` の型は `Tensor Integer -> Tensor Integer` である．`(\x -> [|x, x + 10|]) [|1,2|]` はテンソルをそのまま渡し，値は `[|[|1,2|],[|11,12|]|]` になる．理由：この適用に `tensorMap` を自動で挿入すると，挿入しないほうの関数が記述できなくなる．
- **D6（形状エラー）** `(\x -> [|x, 10|]) [|1,2|]` は形状エラーになる．
- **D7（以前の決定で保つもの）**
  - `\k -> k [|1,2|]` の型は `(Tensor Integer -> a) -> a`，`\k -> tensorMap k [|1,2|]` の型は `(Integer -> a) -> Tensor a` である（2026-10-30）．
  - 高階関数の定義の本体を，使用箇所ごとに調べ直さない（2026-11-11）．
  - 利用者は，引数型，返り値型，テンソルを受け取る位置を指定しない．

ユーザーが示した型の一覧（2026-11-11）．§4 の規則は，この一覧をすべて導けるように定めた．

```
foldl : (b -> a -> b) -> b*p -> [a*q] -> b*(p∨q)
map   : (a -> b) -> [a*p] -> [b*p]
filter : (a -> Bool) -> [a] -> [a]

def inc x := x + 1                    -- Integer -> Integer
def sum xs := foldl (+) 0 xs          -- [Integer*p] -> Integer*p
def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
                                      -- [Integer*p] -> [Integer*q] -> Integer*(p∨q)
def g xs ys := (foldl (+) 0 xs, foldl (+) 0 ys)
                                      -- [Integer*p] -> [Integer*q] -> (Integer*p, Integer*q)
def (.) u v := contractWith (\x y -> x + y) (u * v)
                                      -- Tensor Integer -> Tensor Integer -> Tensor Integer
def apply k x := k x                  -- (a -> b) -> a*p -> b*p
def min x y := if x < y then x else y -- Integer -> Integer -> Integer

\x -> x                               -- a -> a
\x -> [|x|]                           -- Tensor a -> Tensor a
\x -> [|x, x + 10|]                   -- Tensor Integer -> Tensor Integer
\k -> k [|1,2|]                       -- (Tensor Integer -> a) -> a
\k -> tensorMap k [|1,2|]             -- (Integer -> a) -> Tensor a
```

同日の「関数の仮引数の適用では `tensorMap` の挿入を検討しない」という案は，D2 により次のように置き換える．関数の仮引数の適用を成分ごとにするかどうかは，定義の型付けのときに印として型に記録し，使用箇所では型だけを見て決める．

## 3. 記法と用語

- **印**：型のある位置が，スカラー型のままか `Tensor` 型になるかを表す二値の変数．値は「スカラー」か「テンソル」．`p`，`q` などの名前で区別する．英語名は未定（§8）．
- **`τ*p`**：印 `p` をつけた型．`p` がスカラーなら `τ`，テンソルなら `Tensor τ` を表す．
- **`p∨q`**：`p` か `q` のどちらかがテンソルならテンソル，どちらもスカラーならスカラー．
- **正規化**：`(τ*p)*q = τ*(p∨q)`．既存の `Tensor (Tensor τ) = Tensor τ` と合わせて使う．`τ` が `Tensor` 型に決まった場合，その位置の印はスカラーに決める（`Tensor` 型の値を受け取る関数を成分ごとに適用しないため）．
- **印を消した型**：印をすべてスカラーにした型．`[Integer*p] -> Integer*p` の印を消した型は `[Integer] -> Integer` である．
- **印の値ごとの本体**：定義の型の印に値を与えたとき，その値に従って挿入を行った本体．印がすべてスカラーなら，書かれた本体そのものである．
- **テンソル型の位置**：`Tensor` 型の仮引数（`contractWith` の第二引数，`tensorShape` の引数，`tensorMap` の第二引数など）と，テンソル構築式の成分．

## 4. 規則

D1〜D7 から導いた規則である．形式的な定義と解く手順は，§6.1 の試作で確定する．

### 4.1 定義の本体での型の決め方

型がまだ決まっていない式（仮引数，リストの要素，関数の仮引数の結果など）の型は，その式の使われ方から決める．番号の小さい規則を優先する．

1. **テンソル型の位置へ流れる式は，`Tensor` 型にする**（D4，D5）．スカラー関数の適用の結果がテンソル型の位置へ流れる場合は，その適用を成分ごとにし，型が決まっていない引数を `Tensor` 型にする．スカラー関数に直接渡していても，この規則を優先する．

   ```
   \x -> [|x|]                  -- x は成分．Tensor a -> Tensor a
   \x -> [|x, x + 10|]          -- x は成分．x + 10 は本体の中で成分ごとにする
   \u v -> contractWith (\x y -> x + y) (u * v)
                                -- u * v が contractWith の Tensor 型の仮引数へ流れる
   \x -> tensorShape (x + 1)    -- Tensor Integer -> [Integer]
   ```

2. **関数の仮引数を適用する実引数は，印つきの型にする**（D2）．`k : a -> b` を `k e` と適用するとき，`e` の型を `a*p`，結果の型を `b*p` とする．

   ```
   \k x -> k x                  -- (a -> b) -> a*p -> b*p
   ```

3. **スカラー関数に直接渡す仮引数は，スカラー型にする**（D3）．印はつけない．テンソルを渡す適用は，適用の側で成分ごとにする（§4.3）．

   ```
   \x -> x + 1                  -- Integer -> Integer
   \x -> x + [|10,20|]          -- Integer -> Tensor Integer
   ```

   仮引数そのものではない位置（リストの要素，関数の仮引数の結果など）にスカラー関数を直接適用する場合は，印つきのスカラー型にする．この位置は適用の側で成分ごとにできないためである（§8 の Q6）．

   ```
   \xs -> head xs + 1           -- [Integer*p] -> Integer*p
   ```

4. **印つきの型の式にスカラー関数を適用すると，結果にも印がつく**（D1）．印がテンソルになったとき，その適用が成分ごとになる．

5. **それ以外は型変数のままにする．** `\x -> x` は `a -> a` である．定義を閉じる時点で，テンソルを渡している関数の仮引数の入力の型が型変数のままなら，`Tensor` 型にする（D7 の `\k -> k [|1,2|]`）．

スカラーでなければ型が合わない位置（`if` の条件など）へ流れる印は，スカラーに決める．`filter` の `p x` の結果は条件に使うので，`filter : (a -> Bool) -> [a] -> [a]` には印が残らない．`min` も同じである．

### 4.2 定義の型

- 定義（`def`，`let`）の本体は一度だけ型付けする．決まらなかった印は型に残し，型変数と同じく使用箇所ごとに新しくする．
- 印の間に「`q` がテンソルなら `p` もテンソル」という関係が生じる．結果の位置にしか現れない印は，それを決める引数の印の `∨` に置き換えて整理する（`foldl` の結果 `b*(p∨q)`）．
- 再帰定義の中では，その定義自身の印は共有する．`foldl` の再帰呼び出しへ渡す累積値は，階数 0 の包含で受け取る．
- 印を消した型は，テンソル操作のない定義では通常の型推論の型と一致する．
- テンソル型の位置から決まった仮引数（規則 1）を持つ定義は，型が一つである．スカラーの実引数は階数 0 の包含で受け取る（`2 . 3` は 6）．元の本体と挿入後の本体を比べない．

### 4.3 使用箇所での決定

使用箇所では，定義の型と実引数の型から挿入を決める．定義の本体は調べ直さない（D7）．テンソルを渡す位置の仮引数の型によって，次のようになる．

- **型変数**：型変数をテンソル型にして，そのまま渡す．
- **`Tensor` 型**：そのまま渡す．
- **印つきの型**：印をテンソルにする．その定義の印の値ごとの本体が，本体の中で成分ごとに適用する．
- **印のないスカラー型**：その連続適用を成分ごとにする（持ち上げ，D3）．連続適用の等式をすべて解いたあとで，成分ごとにする引数の最小の集合を選ぶ（2026-09-28 の決定を保つ）．

どれにも当てはまらなければ型エラーである．テンソルが来なかった印は，スカラーにする．したがってテンソル操作のないプログラムは，印がすべてスカラーになり，通常の型推論と同じ型を持つ．

要件：

- 印と持ち上げは，連続適用，定義の本体，またはトップレベルの式の等式をすべて集めてから決める．引数を調べる順序で結果が変わってはならない（`c xs + foldl (+) 0 xs` と左右を入れ替えた式が同じ結果になること）．
- 候補の列挙と比較を行わない．印の決定は，型の等式と印の間の関係を解くことだけで行う．
- 印が入れ子になる場合（`(τ*p)*q`）は，内側の印を先にテンソルにする．

### 4.4 高階関数と渡す関数

- 高階関数の型は，関数の仮引数に適用するデータの位置に印を持つ（D2）．渡す関数の型は変えない．`foldl (+) 0 [[|1,2|]]` では `a` と `b` は `Integer` で，`q` がテンソルになる．`foldl` の印の値ごとの本体が，`fn init x` を成分ごとに適用する．
- 渡す関数の入力が `Tensor` 型なら，印はスカラーのままで，関数がテンソル全体を受け取る．`foldl (.) A [B]` は `A . B` を計算する．
- 結果の型が固定されている場合は，これまでと同じである．`filter` に渡す `Integer -> Bool` の述語は，テンソルのリストには使えない．入力をテンソルとして受け取り `Bool` を返す述語は使える（`filter (\x -> let unused := x + 1 in True) [[|1,2|]]`）．
- **渡す関数の変換**（`inc` を `\t -> tensorMap inc t` に置き換える挿入）は，受け取り側の関数の仮引数の入力がテンソル型に決まっていて，渡す関数がスカラー関数の場合だけ使う（`(\k -> k [|1,2|]) inc`）．高階関数の印で受けられる場合は使わない．§8 の Q3．

### 4.5 テンソル型の位置

- テンソル構築式の成分は，テンソル型の位置である（D5）．型のわからない成分は `Tensor a` 型になる．これは論文の現行の規則（型のわからない成分はそのままにする）からの変更である．
- 成分の型は `Tensor` で包んで比べる．スカラーの成分は階数 0 の包含で受け取る．
- 成分の形状が合わない構築は，実行時の形状エラーである（D6）．型推論は，形状エラーを避けるために適用を成分ごとにすることはしない．
- 仮引数がテンソル構築式の成分でなく，構築式と並ぶ引数である場合は，規則 1 は当てはまらない．`\x -> x + [|10,20|]` の `x` はスカラー型のままである．

### 4.6 生成する式

- 印を持つ定義の使用箇所では，決まった印の値に対応する「印の値ごとの本体」を使う．本体は，印がテンソルになった適用に `tensorMap`・`tensorMap2` を挿入したものである．印がすべてスカラーなら，書かれた本体をそのまま使う．
- 印の値ごとの本体は，使われた組合せの分だけ作り，同じ組合せには同じものを使う．組合せを先にすべて作らない．
- テンソル型の位置から決まった仮引数を持つ定義（`.` など）は，挿入を行った本体を一つだけ持つ（`\u v -> contractWith (\x y -> x + y) (tensorMap2 (*) u v)`）．`tensorMap`・`tensorMap2` はスカラーの入力も受け取るので（`tensorMap2 (*) 2 3` は 6），スカラーの実引数にも同じ本体を使う．

### 4.7 変えない規則

- 階数 0 の包含，型の正規化，明示した `tensorMap`・`tensorMap2` の扱い．
- 統合型推論の性質：入力式全体が挿入なしで型付けできるなら，その式を変えない．
- 添字記法，添字補完，形状エラーの定義．
- `IO`，`IORef`，`Port` とこれらを含む型を，成分ごとの自動変換の対象にしない．

### 4.8 現行の仕組みとの対応

- 定義の候補（元の本体／挿入後の本体）→ 二つに分かれる．`sum` のように使用箇所で決まるものは，印つきの型と印の値ごとの本体になる．`.` のようにテンソル型の位置から決まるものは，挿入を行った一つの本体になる．
- 根拠の条件 → 規則 1 として残る．起点にテンソル構築式の成分を加える．根拠のある挿入後の本体は，候補の一つではなく，その定義のただ一つの本体になる．
- 優先順位（複数の導出の比較）→ 不要になる．§4.1 の規則の順と §4.3 で決まる．
- 最小の持ち上げ集合 → §4.3 に残る．
- 渡す関数の変換 → §4.4 の最後の場合だけに残る．

## 5. 例と期待する結果

実装の受け入れ検査に使う．`inc` は `def inc x := x + 1`，`dot` は `def dot u v := contractWith (\x y -> x + y) (u * v)`，`A` は `[|1,2|]~i`，`B` は `[|10,20|]_i`，`ts` は `[[|1,2|],[|3,4|]]` である．

### 5.1 定義の型

§2 の一覧のとおりである．そのほかに，規則から次の型になる．

```
def twiceSum xs := sum xs + sum xs       -- [Integer*p] -> Integer*p
def h x k := [|k x + 10, k x + 20|]      -- a*p -> (a -> Tensor Integer) -> Tensor Integer（Q7）
def hIf x k := if k x > 0 then 1 else 0  -- a -> (a -> Integer) -> Integer
\x -> tensorShape (x + 1)                -- Tensor Integer -> [Integer]
\x -> x + [|10,20|]                      -- Integer -> Tensor Integer
\xs -> head xs + 1                       -- [Integer*p] -> Integer*p（Q6）
```

`g` の型のように，印は名前で区別する．`g ts [5,6]` の型は `(Tensor Integer, Integer)` である．

### 5.2 値が変わる例

現行の値は Lean と Egison で一致している．

```
(\x -> [|x, x + 10|]) [|1,2|]
  -- 現行：[|[|1,11|],[|2,12|]|]      期待：[|[|1,2|],[|11,12|]|]（D5）
def vec t := [|t, t * t|]
vec [|1,2|]
  -- 現行：[|[|1,1|],[|2,4|]|]        期待：[|[|1,2|],[|1,4|]|]
map (\x -> [|x, x + 10|]) [[|1,2|]]
  -- 現行：[[|[|1,11|],[|2,12|]|]]    期待：[[|[|1,2|],[|11,12|]|]]

(\x -> [|x * 2, x + 10|]) [|1,2|]
  -- 現行：[|[|2,11|],[|4,12|]|]      期待：[|[|2,4|],[|11,12|]|]（Q7）
(\x -> [|x + 10|]) [|1,2|]
  -- 現行：[|[|11|],[|12|]|]          期待：[|[|11,12|]|]（Q7）
(\x -> [|x + 0, 10|]) [|1,2|]
  -- 現行：[|[|1,10|],[|2,10|]|]      期待：形状エラー（Q7）

(\x -> map (\y -> y + 1) [x]) [|1,2|]
  -- 現行：[|[2],[3]|]                期待：[[|2,3|]]（Q8）

def h x k := [|k x + 10, k x + 20|]
h [|1,2|] inc
h [|1,2|] ((+) 1)
  -- 現行：[|[|12,22|],[|13,23|]|]    期待：[|[|12,13|],[|22,23|]|]（Q1）
```

値は同じで型だけが変わる例：

```
(\x -> (tensorShape (x + 1), x)) 5
  -- 値：([], 5)   現行の型：([Integer], Integer)   期待する型：([Integer], Tensor Integer)
```

### 5.3 値が変わらない例

```
inc [|1,2|]                           -- [|2,3|]（tensorMap inc [|1,2|]）
inc [|1,2|]_i                         -- [|2,3|]_i
(\x -> x + [|10,20|]) [|1,2|]         -- [|[|11,21|],[|12,22|]|]
(\x -> (x, x + 1)) [|1,2|]            -- [|(1,2), (2,3)|]
```

## 8. 判断待ち

- **Q1** `def h x k := [|k x + 10, k x + 20|]` の `h [|1,2|] inc` の値．`apply` の型（§4.1 の規則 2）から，`x` に印がつき，`h` の本体の中で `k x` を成分ごとにするので，値は `[|[|12,13|],[|22,23|]|]` になる．現行は連続適用を成分ごとにして `[|[|12,22|],[|13,23|]|]` である．論文の `def h x k := k x + 0` の値は変わらない．
- **Q2** 直接書いた不揃いのテンソル構築式 `[| [|1,2|], 10 |]` を，Egison でも型エラーでなく実行時の形状エラーにそろえるか．そろえる場合，2026-09-28 の決定（成分はすべて同じ型）を変える．D6 を満たすには，どちらの場合も Egison の成分の規則の変更が必要である．
- **Q3** 渡す関数の変換を §4.4 の最後の場合として残すこと．残さない場合，`(\k -> k [|1,2|]) inc` と論文の付録の例は型エラーになる．現行は Lean・Egison とも受理するので，この文書は残す前提で書いた．
- **Q4** 型注釈と印の関係．この文書は，スカラー型の注釈（`(x : Integer)`）は印なし，型変数の注釈（ライブラリの `foldl` の `(init : b)`）には印がつきうる，という前提で書いた．
- **Q5** 推論した型の表示．印を利用者に見せるか，区別が要るときだけ名前をつけるか，印を消した型を併記するか．
- **Q6** 仮引数そのものではない位置にスカラー関数を直接適用した場合（§4.1 の規則 3 の後半）．`\xs -> head xs + 1` の型を `[Integer*p] -> Integer*p` とするか，`[Integer] -> Integer` とするか．この文書は前者で書いた．現行は Lean・Egison とも `(\xs -> head xs + 1) [[|1,2|]]` と `(\k -> k 5 + 10) (\y -> [|y, y|])` を受理する．後者にすると，これらは型エラーになり，再帰で書いた和（`mysum`）もテンソルのリストに使えない．
- **Q7** テンソル構築式の成分がスカラー関数の適用である場合（§4.1 の規則 1 の後半を成分にも当てはめること）．`(\x -> [|x * 2, x + 10|]) [|1,2|]` を，`x` をテンソルとして受け取る `[|[|2,4|],[|11,12|]|]` にするか，現行の成分ごとの `[|[|2,11|],[|4,12|]|]` にするか．この文書は前者で書いた．`contractWith` の仮引数へ流れる `u * v`（D4）と同じ扱いである．`\θ -> [|cos θ, sin θ|]` のように，スカラーからテンソルを作る定義にテンソルを渡す場合の結果が変わる．
