## 1. テンソル型と実行時の形状

テンソルは `Tensor a` と型付けし，`a` は要素型を表す．次元数，各軸の大きさ，添字名，
共変・反変（下付き・上付きという添字の区別）は型には含めない．

```egison
def v : Tensor Integer := [| 1, 2, 3 |]
def m : Tensor Integer := [| [| 1, 0 |], [| 0, 1 |] |]
```

入れ子の `Tensor` 型は正規化で一つにまとめる．

```text
Tensor (Tensor a)  =  Tensor a
```

テンソル構築式は `[|e1, ..., en|]` のように成分を並べる式である．成分の型は `Tensor` で包んで比較する．例えば整数と整数のテンソルは，どちらも `Tensor Integer` として受け取る．成分の形状がそろうかは実行時に検査する．`[|1, [|2,3|]|]` は型エラーにせず，実行時の形状エラーにする．異なる要素型を無条件に混在させてよいという意味ではない．

実行時には，階数 0 のテンソルをスカラーそのものとして表す．例えば
`generateTensor f []` はテンソル容器ではなく `f []` を返す．大きさ 1 のベクトルは
階数 1 なので `Tensor a` のままである．

生成関数がテンソルを返す場合は，外側の形状 `S` と共通する内側の形状 `R` を `S ++ R` に
連結し，スカラー成分の配列も連結する．例えば `generateTensor (\_ -> [|1,2|]) [2]` は形状
`[2,2]`，成分 `[1,2,1,2]` を持つ．生成・保存配列・成分ごとの適用の結果を
組み立て，内側の形状と添字の一致を検査する．リストなどのデータの内部はたどらない．
成分の形状が異なる `[|[|1,2|],[|3|]|]` は構築時に形状の不一致による形状エラーとする．成分ごとの適用が返したテンソルを並べる場合も同じであり，`tensorMap (\f -> f 1) [|(\x -> [|x|]),(\x -> [|x,x|])|]` は同じ形状エラーとなる．通常のリストはスカラーなので，`[|[1,2],[3]|]` は許す．
`tensor` と `generateTensor` の各軸長は正整数に限る．`tensor` は通常の引数評価後，軸長，成分数の順で検査する．`generateTensor` は形状の検査後に座標を列挙し，不正な形状では生成関数を適用しない．形状 `[]` は階数0として許し，空の座標へ一度適用する．空のテンソル構築式と，始点が終点を超える範囲参照は実行時エラーにする．通常の空リストはスカラーのまま扱う．

行列の分解で必要になる0行・0列の部分行列は，通常のデータ `MatrixBlock a` で表す．
行数・列数・成分列を保持し，テンソルへの変換は両方の寸法が正の場合だけ許す．
この処理にはテンソルの型推論や軸長の例外を追加しない．
[行列の逆行列と部分行列](matrix.md) に公開操作と分解・結合の規則を記す．

## 2. テンソル印と推論した型

- **テンソル印（tensor flag）**：型 `τ` をそのまま使うか，`Tensor τ` として使うかを表す二値の変数．値は「スカラー」または「テンソル」とする．`p`，`q` などの名前で区別する．
- **`τ*p`**：テンソル印 `p` をつけた型．`p` がスカラーなら `τ`，テンソルなら `Tensor τ` を表す．
- **テンソル印の対象**：既に `Tensor` 型である型に，さらにテンソル印を付けることは認めない．`(Tensor Integer)*p` は不正な型であり，`Tensor Integer` と直接書く．共有する `p` をスカラーに固定して，この不正な型を受理する規則は設けない．
- **同じテンソル印の共有**：共有の範囲は一つの型宣言の内部である．別々の型宣言に同じ名前の `p` が書かれていても，それぞれ別の変数である．一つの型の使用で同じ `p` が付く位置は，すべて一つのテンソル印の値を共有する．どこか一つの `τ*p` を `Tensor τ` にするために `p` がテンソルに決まれば，ほかの同じ `p` が付く位置もテンソルになる．`a*p` と `b*p` のように，要素型が異なっていても同じである．一般化されたテンソル印は，使用箇所ごとに新しくする（§3.2）．
- **`p∨q`**：`p` か `q` のどちらかがテンソルならテンソル，どちらもスカラーならスカラー．
- **正規化**：テンソル印の入れ子は，値を具体化する前に `(τ*p)*q = τ*(p∨q)` と整理する．ここで `τ` 自体は `Tensor` 型ではない．`Tensor (Tensor τ) = Tensor τ` は，§1 のテンソル型そのものの正規化として扱う．
- **テンソル印を消した型**：テンソル印をすべてスカラーにした型．`[Integer*p] -> Integer*p` のテンソル印を消した型は `[Integer] -> Integer` である．
- **テンソル印の値ごとの本体**：定義の型のテンソル印に値を与えたとき，その値に従って挿入を行った本体．テンソル印がすべてスカラーなら，テンソル印に基づく挿入は行わない．テンソル型の位置から決まる挿入は，テンソル印の値によらず残す（§8）．
- **テンソル型の位置**：`Tensor` 型の仮引数（`contractWith` の第二引数，`tensorShape` の引数，`tensorMap` の第二引数など），テンソル構築式の成分，添字参照の対象．

例えば，二つの引数と結果が固定のテンソル型である関数は，次のように表す．

```text
Tensor Integer -> Tensor Integer -> Tensor Integer
```

テンソル印は推論した型に表示する．`foldl`・`map`・`filter`・`apply` では，関数引数の型にもデータと共有するテンソル印を明示する．関数引数の位置に書くのは，高階関数の本体が受け取る関数に要求する型である．渡す関数を包む場合や，渡す関数自身のテンソル印を具体化する場合は，その後の型がこの要求を満たすようにする（§5）．数値演算の例では，型クラスによる多相性を省略して `Integer` を用いる．

```text
foldl  : (b*p -> a*p -> b*p) -> b*p -> [a*p] -> b*p
map    : (a*p -> b*p) -> [a*p] -> [b*p]
filter : (a*p -> Bool) -> [a*p] -> [a*p]
apply  : (a*p -> b*p) -> a*p -> b*p
```

同じ `p` を共有する位置は，次のとおりである．

- `foldl`：渡す関数の二つの入力と結果，初期値，リスト要素，`foldl` の結果．
- `map`：渡す関数の入力と結果，入力リストと結果リストの要素．
- `filter`：述語の入力，入力リストと結果リストの要素．述語の結果の `Bool` にはテンソル印を付けない．
- `apply`：渡す関数の入力と結果，`apply` の第二引数と結果．

例えば `p` がテンソルなら，次の型になる．

```text
foldl  : (Tensor b -> Tensor a -> Tensor b) -> Tensor b -> [Tensor a] -> Tensor b
map    : (Tensor a -> Tensor b) -> [Tensor a] -> [Tensor b]
filter : (Tensor a -> Bool) -> [Tensor a] -> [Tensor a]
apply  : (Tensor a -> Tensor b) -> Tensor a -> Tensor b
```

```egison
def inc x := x + 1                    -- Integer -> Integer
def sum xs := foldl (+) 0 xs          -- [Integer*p] -> Integer*p
def f xs ys := foldl (+) 0 xs + foldl (+) 0 ys
                                      -- [Integer*p] -> [Integer*q] -> Integer*(p∨q)
def g xs ys := (foldl (+) 0 xs, foldl (+) 0 ys)
                                      -- [Integer*p] -> [Integer*q] -> (Integer*p, Integer*q)
def (.) u v := contractWith (\x y -> x + y) (u * v)
                                      -- Tensor Integer -> Tensor Integer -> Tensor Integer
def apply k x := k x
def min x y := if x < y then x else y -- Integer -> Integer -> Integer

\x -> let unused := x + 1 in True      -- Integer*p -> Bool
\x -> x                               -- a -> a
\x -> [|x|]                           -- Tensor a -> Tensor a
\x -> [|x, x + 10|]                   -- Tensor Integer -> Tensor Integer
\k -> k [|1,2|]                       -- (Tensor Integer -> a) -> a
\k -> tensorMap k [|1,2|]             -- (Integer -> a) -> Tensor a
```

## 3. 定義を一度だけ型付けする

### 3.1 本体内の式と仮引数

型がまだ決まっていない式（仮引数，リストの要素，関数の仮引数の結果など）の型は，その式の使われ方から決める．番号の小さい規則を優先する．

1. **テンソル型の位置へ流れる式は，`Tensor` 型にする**．スカラー関数の適用の結果がテンソル型の位置へ流れる場合は，その適用を成分ごとにし，型が決まっていない引数を `Tensor` 型にする．スカラー関数に直接渡していても，この規則を優先する．

   ```
   \x -> [|x|]                  -- x は成分．Tensor a -> Tensor a
   \x -> [|x, x + 10|]          -- x は成分．x + 10 は本体の中で成分ごとにする
   \x -> [|x * 2, x + 10|]      -- x * 2 と x + 10 が成分．Tensor Integer -> Tensor Integer
   \u v -> contractWith (\x y -> x + y) (u * v)
                                -- u * v が contractWith の Tensor 型の仮引数へ流れる
   \x -> tensorShape (x + 1)    -- Tensor Integer -> [Integer]
   ```

   最後の例では，`tensorShape` の入力が `Tensor` 型なので，`x` を `Tensor Integer` に決め，本体を `\x -> tensorShape (tensorMap (\z -> z + 1) x)` にする．あとでスカラーを渡す場合も同じ本体を使う．例えば `5` は階数 0 として受け取り，`tensorMap (\z -> z + 1) 5` は `6`，その形状は `[]` である．挿入なしのスカラー入力での計算と，値も返り値型 `[Integer]` も一致する．

2. **関数の仮引数の適用は，共有する関数型で通常の適用として型付けする**．本体の `k e` ごとに挿入するかどうかを選ばず，`k` の入力・結果と `e` の型の関係を記録する．同じ `k` を複数回使う場合も，一つの関数型を共有する．高階関数のテンソル印は，実際の関数を渡す箇所での挿入と，その関数の入力・結果に関係するデータの型を表す．

   ```
   \k x -> k x                  -- (a*p -> b*p) -> a*p -> b*p
   ```

   この型の先頭の `a*p -> b*p` は，本体が受け取る `k` の型である．`k` の入力と `x` は同じ `a*p`，`k` の結果と本体 `k x` の結果は同じ `b*p` であり，`k x` 自体には挿入しない．`k` を別の高階関数へ渡す場合も，型が未確定の仮引数を渡す箇所で独立した変換を選ばず，共有する型の制約を伝える．`gp` の `map k xs` と `k 0` はこの規則で同じ関数型を使う．

3. **スカラー関数に直接渡す仮引数の型は，その演算結果の使われ方も含めて決める**．例えば，内部の演算結果を返り値に使わない次の述語は，入力にテンソル印を残す．`x` と `unused` の型に同じテンソル印を持たせても，最後の `True` は `Bool` のままである．

   ```
   \x -> let unused := x + 1 in True -- Integer*p -> Bool
   -- x : Integer*p，x + 1 と unused : Integer*p，True : Bool
   ```

   一方，`inc` のように演算結果をそのまま返すスカラー関数については，これまでの決定どおりテンソル印のないスカラー入力の型を使う．テンソルを渡す適用は，適用の側で成分ごとにする（§4）．

   ```
   \x -> x + 1                  -- Integer -> Integer
   \x -> x + [|10,20|]          -- Integer -> Tensor Integer
   ```

   引数として直接書いたラムダ式（`\x -> ...` のような無名関数）も，名前付き関数と同じく，その本体から型・テンソル印・制約を求める．使用箇所でテンソル印が決まったら，そのテンソル印に従って本体内の既知の演算への挿入を生成する．上の述語を `filter` へ渡す場合は，入力のテンソル印をテンソルに決め，加算に挿入する（§5.1）．本体の型を使用先に合わせて推論し直すことや，未確定の関数の仮引数の各適用で別の挿入を選ぶことはしない．入力だけにテンソル印を残す規則と，`inc` のようなスカラー関数の規則の形式的な区別は，この型の一覧を満たすよう試作で確定する．

   仮引数そのものではない位置（リストの要素，関数の仮引数の結果など）にスカラー関数を直接適用する場合は，テンソル印つきのスカラー型にする．`head xs + 1` で `tensorMap` が挿入されるのは `head xs` に対してであり，定義を適用する側では挿入できないためである．

   ```
   \xs -> head xs + 1           -- [Integer*p] -> Integer*p
   ```

4. **テンソル印つきの型の式にスカラー関数を適用すると，結果にもテンソル印がつく**．テンソル印がテンソルになったとき，その適用が成分ごとになる．

5. **それ以外は型変数のままにする．** `\x -> x` は `a -> a` である．定義を閉じる時点で，テンソルを渡している関数の仮引数の入力の型が型変数のままなら，`Tensor` 型にする（`\k -> k [|1,2|]`）．

スカラーでなければ型が合わない位置（`if` の条件など）へ流れるテンソル印は，スカラーに決める．`filter` の本体で述語を `pred` と書くと，`pred x` の結果は条件に使うため `Bool` でなければならない．これは述語の入力のテンソル印をスカラーに固定する条件ではない．`filter : (a*p -> Bool) -> [a*p] -> [a*p]` の入力とリスト要素には共有するテンソル印 `p` が残る．`min` のように比較の入力もスカラーである必要がある場合は，その入力をスカラーに決める．

### 3.2 定義に記録する型と制約

- 定義（`def`，`let`）の本体は一度だけ型付けする．決まらなかったテンソル印は型に残し，型変数と同じく使用箇所ごとに新しくする．このように，異なる型で利用できる変数を定義の型に残すことを一般化と呼ぶ．外側から捕捉した値と，一つの型を共有する変数は，一般化によって切り離さない．
- テンソル印の間に「`q` がテンソルなら `p` もテンソル」という関係が生じる．結果の位置にしか現れないテンソル印は，それを決める引数のテンソル印の `∨` に置き換えて整理する（`f` の結果 `Integer*(p∨q)`）．異なる定義の使用箇所のテンソル印は，型の制約が結び付けない限り独立である．`f` の二つの `foldl` の使用には，それぞれ別のテンソル印を使う．
- 再帰定義の中では，その定義自身のテンソル印は共有する．`foldl` では，返り値と次の再帰呼び出しへ渡す累積値の型をそろえ，関数引数の二つの入力と結果，初期値，リスト要素，`foldl` の返り値を同じテンソル印 `p` で表す．`p` がテンソルなら，呼び出し側で変換した関数を受け取る．本体の `fn init x` はそのままで，結果と同じ `fn` を再帰呼び出しへ渡す．初期値がスカラーでも，ほかの引数から `p` がテンソルに決まれば，その初期値を階数 0 の包含で受け取る．初期値がテンソルでリスト要素がスカラーの場合も，同じ `p` を使い，各要素を階数 0 として受け取る．
- テンソル印を消した型は，テンソル操作のない定義では通常の型推論の型と一致する．
- テンソル型の位置から決まった仮引数（規則 1）を持つ定義は，型が一つである．スカラーの実引数は階数 0 の包含で受け取る（`2 . 3` は 6）．元の本体と挿入後の本体を比べない．
- 型注釈がある場合：スカラー型の注釈をつけた仮引数は，テンソル印のないスカラー型になる．型変数の注釈をつけた位置には，本体の型付けからテンソル印がつきうる．注釈との照合は §7 に従う．縮約結果に対するトップレベルのスカラー型注釈を認める規則も，そこで区別する．
- 推論した型を利用者に示すときは，テンソル印をこの文書の記法（`Integer*p`，`Integer*(p∨q)`）で表示する．

ローカル定義は依存関係に従って一般化する．互いに再帰する定義の内部では，型とテンソル印の共有を保つ．別名は元の定義の型とテンソル印の制約を引き継ぎ，元の本体を推論し直さない．

## 4. 関数の適用式で型と挿入を決める

**適用式**とは，`inc [|1,2|]` や `foldl (+) 0 [[|1,2|]]` のように，関数へ引数を渡す式である．この節では，その式を評価する前の型推論で，式の型と必要な挿入を決める方法を説明する．

第3節では，関数の本体から，その関数の型・テンソル印・制約を求めた．適用式を調べるときは，記録した関数の型を，引数の型や，適用式の結果に要求される型と照合する．関数の本体は推論し直さない．

### 4.1 定義した関数の型と，適用式の型

`sum` の定義と，その関数を呼び出す二つの式を例にする．

```egison
def sum xs := foldl (+) 0 xs
-- sum : [Integer*p] -> Integer*p

sum [1,2]                         -- 3 : Integer
sum [[|1,2|],[|3,4|]]             -- [|4,6|] : Tensor Integer
```

定義の型を求める段階では，`sum` にどちらのリストを渡すかは決めず，`[Integer*p] -> Integer*p` を記録する．上の二つの適用式では，それぞれ新しい `p` を使う．最初の式では `p` がスカラーになり，式の結果型は `Integer` になる．二つ目では，リスト要素が `Tensor Integer` なので `p` がテンソルになり，式の結果型も `Tensor Integer` になる．

挿入する場所は，記録したテンソル印と演算の関係から決まる．この `sum` では，`p` がテンソルになると，本体の `foldl` へ渡す `(+)` を `\u v -> tensorMap2 (+) u v` に包む．このように，呼び出す式からテンソル印の値を決め，その値に対応する本体を生成することがある（§8.1）．本体の型を推論し直す必要はない．

### 4.2 引数の型に応じた渡し方

`def inc x := x + 1` の `x` のように，定義で引数を受け取る変数を**仮引数**と呼ぶ．`inc [|1,2|]` の `[|1,2|]` のように，適用式で渡す式を**実引数**と呼ぶ．`inc` の仮引数の型は `Integer` であり，この実引数の型は `Tensor Integer` である．

テンソルを実引数として渡す場合は，対応する仮引数の型に応じて，次のように扱う．

- **テンソル印のない型変数 `a`**：`a` をテンソル型に具体化し，テンソル全体をそのまま渡す．例えば `\x -> x` の型は `a -> a` であり，この関数に `[|1,2|]` を渡す場合は，`a` を `Tensor Integer` にする．
- **`Tensor` 型**：テンソル全体をそのまま渡す．例えば `tensorShape [|1,2|]` では，`tensorShape` がテンソルを受け取るので，挿入は不要である．
- **テンソル印つきの型 `τ*p`**：`p` をテンソルに決め，同じ `p` を共有するほかの位置にも反映する．記録した関係に従って，既知の演算への挿入や，高階関数へ渡す関数の変換を決める（§5，§8.1）．
- **テンソル印のないスカラー型**：関数を成分ごとに適用する式に変える（持ち上げ）．例えば `inc [|1,2|]` は `tensorMap inc [|1,2|]` になる．`inc` 自身の型は `Integer -> Integer` のままで，適用式の結果型は `Tensor Integer` になる．

テンソル印は，引数型の内部に現れることもある．`sum [[|1,2|]]` では，実引数の型 `[Tensor Integer]` を，`sum` の引数型 `[Integer*p]` と照合する．この照合でリスト要素の `p` がテンソルに決まり，同じ `p` を使う結果型も `Tensor Integer` になる．挿入は §4.1 で説明したとおり，`sum` の本体に記録された関係から生成する．

型の照合とこれらの処理で型を合わせられなければ，型エラーである．複数の引数がある場合は，次の §4.3 に従って全引数の制約を使う．

一引数の成分ごとの適用には `tensorMap`，二引数には `tensorMap2` を使う．三引数以上では，添字の整列を保ってこれらを組み合わせる．もともとテンソルを受け取る位置は，テンソル全体を渡す．スカラー入力に対する `tensorMap`・`tensorMap2` は通常の適用として働く．

```egison
inc [|1,2|]                         -- tensorMap inc [|1,2|]
tensorMap inc 5                     -- 6
tensorMap2 (+) [|1,2|] 10            -- [|11,12|]
```

### 4.3 複数の引数と周囲の式から判断する

**連続適用**とは，`f e1 ... en` のように引数を続けて渡す式である．例えば `foldl (+) 0 [[|1,2|]]` は，`foldl` に三つの引数を渡す連続適用である．テンソル印と挿入は，全引数と，式の結果に要求される型を合わせて判断する．

この `foldl` の例では，リスト要素から共有する `p` がテンソルに決まる．初期値 `0` は階数 0 として受け取り，第一引数の `(+)` を `\u v -> tensorMap2 (+) u v` に包む．一つの実引数がスカラーであることだけでは，共有するテンソル印をスカラーに固定しない．

高階関数へ渡す関数の変換を「一度だけ」決めるとは，この例では `(+)` を `foldl` に渡す式について，一つの変換を決めることをいう．`foldl` の本体にある `fn init x` や再帰呼び出しでは，同じ関数を使う．`foldl (+)` のように一部の引数だけを渡した式では，残りの引数などから必要な制約がそろうまで，テンソル印の決定を保留する．

後の引数によって，前の引数の扱いが決まることもある．

```egison
def hIf x k := if k x > 0 then 1 else 0
-- a -> (a -> Integer) -> Integer
hIf [|1,-2|] inc
  → tensorMap (\x -> hIf x inc) [|1,-2|]
-- [|1,0|]
```

`hIf` の型では，第一引数の型と，第二引数の関数が受け取る型が，同じ `a` である．第二引数に `inc : Integer -> Integer` を渡すと，この `a` が `Integer` に決まる．`k` の結果も `Integer` でなければならないため，`inc` をテンソルの結果を返す関数に包む方法は使えない．そこで，第一引数のベクトルに対して `hIf` を成分ごとに適用する．

判断には，次の条件を課す．

- 連続適用，定義の本体，またはトップレベルの式の等式をすべて集めてから，テンソル印と持ち上げを決める．例えば `sum xs + foldl (+) 0 xs` と左右を入れ替えた式でも，型と挿入の判断を同じにする．
- 持ち上げる引数の選び方が複数ある場合は，全体の制約を満たす集合のうち，ほかのすべての集合に含まれる最小の集合を使う．そのような集合がなければ型エラーにする．
- 型の等式とテンソル印の間の関係を解いたあと，テンソルに決める制約がないテンソル印をスカラーにする．テンソル操作のないプログラムは，テンソル印がすべてスカラーになり，通常の型推論と同じ型を持つ．
- 定義の候補（元の本体と挿入後の本体）を列挙して比較する処理は行わない．テンソル印の決定は，型の等式とテンソル印の間の関係を解くことだけで行う．関数の仮引数を呼んだり，別の高階関数へ渡したりする本体内の各箇所で，別の挿入を選ばない．
- テンソル印の入れ子（`(τ*p)*q`）を §2 に従って整理した場合は，元の内側のテンソル印 `p` を先にテンソルにする．

## 5. 高階関数へ渡す関数の変換

高階関数とは，関数を引数として受け取る関数である．

- **渡す関数の変換**は，高階関数へ実際の関数を渡す箇所で，その使用の型の制約から一度だけ決める．例えば `inc` を `\t -> tensorMap inc t` に包む．受け取った高階関数の本体では，仮引数の各適用に別の挿入を加えない．
- 渡す関数が既にテンソル印を持つ場合は，受け取り側の型からそのテンソル印を決め，対応する本体を生成する．既知の演算への挿入は定義時に記録したテンソル印に従う（§8.1）．関数全体を `tensorMap` で包む場合と区別する．
- `foldl` が受け取る関数の型は `b*p -> a*p -> b*p`，`map` と `apply` では `a*p -> b*p`，`filter` では `a*p -> Bool` である．いずれも §2 の型に明示した要求であり，関数引数の型にあるテンソル印と，その入力・結果に関係するデータのテンソル印を別々に決めない．
- 実際に渡す関数の元の型を，この要求と照合する．例えば `inc : Integer -> Integer` を `apply` へ渡し，共有する `p` がテンソルに決まった場合は，`\t -> tensorMap inc t` に包み，要求される `Tensor Integer -> Tensor Integer` を満たす．照合・挿入の形式的な表現は，[移行作業](tensor-flag-types.md) §2 で確定する．
- `foldl (+) 0 [[|1,2|]]` では `a` と `b` は `Integer` で，共有する `p` がテンソルになる．呼び出し側で `(+)` を `\u v -> tensorMap2 (+) u v` に包む．本体の `fn init x` はそのまま呼び出し，初期値と各段階の累積値を同じ `Tensor Integer` 型として受け取る．`0` は階数 0 であり，再帰呼び出しでも同じ変換済みの関数を渡す．
- 渡す関数がもともと `Tensor` 型を受け取る位置には，さらにテンソル印を付けず，テンソル全体を渡す．`foldl (.) A [B]` では，`.` の型 `Tensor Integer -> Tensor Integer -> Tensor Integer` が受け取り側の要求を満たすので，`.` をそのまま渡して `A . B` を計算する．
- 結果の型が固定されている場合は，受け取り側の要求を保つ．`filter` は `Bool` を要求するため，述語全体を成分ごとにして `Tensor Bool` を返す関数は渡せない．述語自身の型がテンソル全体を受け取って `Bool` を返す型なら，そのまま使える．
- `(\k -> k [|1,2|]) inc` も，同じく `inc` を渡す箇所で変換する．受け取り側の入力が最初からテンソル型である場合と，テンソル印からテンソル型に決まる場合で，挿入の箇所を分けない．

```
foldl (+) 0 [[|1,2|],[|3,4|]]
  → foldl (\u v -> tensorMap2 (+) u v) 0 [[|1,2|],[|3,4|]]

apply inc [|1,2|]
  → apply (\t -> tensorMap inc t) [|1,2|]
-- [|2,3|] : Tensor Integer

gp inc [[|1,2|]]
  → gp (\t -> tensorMap inc t) [[|1,2|]]
```

`gp` は `def gp k xs := (map k xs, k 0)` である．挿入後は `k : Tensor Integer -> Tensor Integer` を両方の箇所で共有する．`map k xs` の型は `[Tensor Integer]`，`k 0` の型は `Tensor Integer` になる．`k 0` には `0` を階数 0 として渡し，値は `1` である．右側の型だけを `Integer` に戻すための別の関数や，`map k xs` の箇所だけの変換を作らない．

### 5.1 述語を渡す場合

直接書いたラムダ式，名前付き関数，保存した関数を同じ規則で扱う．次の述語の型は `Integer*p -> Bool` である．`x + 1` の結果がテンソルになっても，関数の結果 `True` の型は `Bool` のままなので，入力にテンソル印 `p` を残す．

```egison
filter (\x -> let unused := x + 1 in True) [[|1,2|]]
  → filter (\x -> let unused := tensorMap2 (+) x 1 in True) [[|1,2|]]
-- [[|1,2|]] : [Tensor Integer]

def pred x := let unused := x + 1 in True
-- Integer*p -> Bool
filter pred [[|1,2|]]                -- [[|1,2|]] : [Tensor Integer]

let predicates := [pred] in
  filter (head predicates) [[|1,2|]] -- [[|1,2|]] : [Tensor Integer]
```

`filter` の型 `(a*p -> Bool) -> [a*p] -> [a*p]` において，リスト要素と述語の入力は同じテンソル印を共有する．この例では `a` を `Integer`，`p` をテンソルに決めると，必要な述語の型は `Tensor Integer -> Bool` になる．述語自身に記録した `Integer*q -> Bool` のテンソル印 `q` も，この照合によってテンソルに決まる．`x` と `unused` は `Tensor Integer` になり，加算に `tensorMap2` を挿入する．述語の結果は `Bool` のままである．これはテンソル印に従う本体の生成であり，本体を推論し直して別の候補を探す処理ではない．名前付き・保存済みの関数でも，同じテンソル印と制約を引き継ぐ．

述語全体を `tensorMap` で包む方法では結果が `Tensor Bool` になるため，`filter` に渡せない．この例で挿入するのは述語の本体内の既知の加算であり，`filter` の本体内で述語を適用する式は変更しない．スカラーのリストに渡す場合はテンソル印をスカラーに決め，加算への挿入は行わない．

利用者が成分ごとの適用を明示する場合や，述語が入力を使わず通常の型変数を持つ場合も扱える．

```egison
filter (\x -> let unused := tensorMap2 (+) x 1 in True) [[|1,2|]]
-- 利用者が tensorMap2 を明示した場合も同じ値になる
-- [[|1,2|]] : [Tensor Integer]

filter (\x -> True) [[|1,2|]]
-- 述語は a -> Bool．a を Tensor Integer に具体化し，そのまま渡す
-- [[|1,2|]] : [Tensor Integer]
```

例えば `(x : Integer)` と明示してテンソル印のないスカラー入力に固定した述語は，上の `Integer*p -> Bool` とは異なり，このテンソル印による挿入を使えない．関数の本体にあるテンソル操作から入力型を決める規則も維持する．`\x -> tensorShape (x + 1)` は，本体自身の `tensorShape` の要求から，使用箇所のテンソル印によらず挿入する（§8）．

### 5.2 複数の関数引数と共有

```egison
def positive x := x > 0
def mapFilter f p xs := map f (filter p xs)
def filterMap p f xs := map f (filter p xs)

\xs -> mapFilter inc positive xs     -- [Integer] -> [Integer]
\xs -> filterMap positive inc xs     -- [Integer] -> [Integer]
```

`positive` の結果は `Bool` でなければならず，両方の関数が入力型を共有する．全引数の制約をまとめて解き，引数順で結果を変えない．もともとテンソル全体を受け取る述語なら，`mapFilter` または `filterMap` へ `inc` を渡す箇所で，`inc` だけを包める．本体の `map f` と `filter p` はそのままにする．

`\g h -> (g h, h 1)` のように，同じ仮引数を別の高階関数へ渡す場合にも，共有した型を使う．外側へ実際の関数を渡す箇所で変換を決める．本体の `g h` だけで `h` を包み，`h 1` には元のスカラー関数を残す変換は選ばない．

### 5.3 部分適用・別名・関数を返す式

部分適用とは，引数の一部だけを渡して，残りの引数を受け取る関数を得ることである．`(foldl (+)) 0 ts` と `foldl (+) 0 ts` は同じ型・値・挿入の判断になる．`let f := sum` のような別名では，一般化されたテンソル印を各使用で独立に決められる．捕捉した値の型は共有し，同名の変数が使用先にあっても捕捉する値を変えない．

```egison
let f := sum in (f [1,2], f [[|1,2|],[|3,4|]])
-- (3, [|4,6|]) : (Integer, Tensor Integer)
```

渡す関数の返り値が，使用箇所でさらに関数型になる場合も，全体の型から引数の個数を求める．型の途中にある `Tensor` を消して照合しない．`Integer -> Tensor (Integer -> Integer)` のような関数は，残る引数を格納された関数へ成分ごとに適用できる．もともとの入力型を保ち，テンソル全体を受け取る位置には全体を渡す．この場合も，関数の仮引数の使用ごとに異なる変換を選ぶことはしない．具体的な型表現と生成手順は，移行作業の試作で確定する．

## 6. テンソル型の位置から決まる入力

- テンソル構築式の成分は，テンソル型の位置である．型のわからない成分は `Tensor a` 型になる．
- 成分の型は `Tensor` で包んで比べる．スカラーの成分は階数 0 の包含で受け取る．
- 成分の形状が合わない構築は，実行時の形状エラーである．型推論は，形状エラーを避けるために適用を成分ごとにすることはしない．直接書いた `[| [|1,2|], 10 |]` も，型エラーにせず実行時の形状エラーにする．
- 仮引数がテンソル構築式の成分でなく，構築式と並ぶ引数である場合は，§3.1 の規則 1 は当てはまらない．`\x -> x + [|10,20|]` の `x` はスカラー型のままである．

```egison
(\x -> [|x, x + 10|]) [|1,2|]
  → (\x -> [|x, tensorMap2 (+) x 10|]) [|1,2|]
-- [|[|1,2|],[|11,12|]|] : Tensor Integer

(\x -> [|x, 10|]) [|1,2|]           -- 実行時の形状エラー
[|[|1,2|], 10|]                      -- 実行時の形状エラー
```

### 6.1 要求を伝える範囲

`Tensor` 型の仮引数，テンソル構築式の成分，添字参照の対象を起点として，型が未確定の式の型を決める．ここで起点とは，ソースのテンソル操作が `Tensor` 型を要求する型の位置である．基本操作と利用者定義の関数に同じ条件を使い，演算子の名前だけで判断しない．

成分ごとの適用の結果が `Tensor` 型として必要なら，その適用で成分ごとに扱う入力へ要求を伝える．`let` とその参照，別名の型の関係も使う．一方の入力がテンソルであることだけを理由に，結果を経由して他方の入力をテンソル型に固定しない．通常の適用で入力と結果の型が無関係なら，結果への要求を入力に伝えない．リストの要素や関数の返り値を無条件にたどることもしない．

```egison
\x -> x + [|10,20|]                 -- Integer -> Tensor Integer
\x -> tensorShape (inc x)            -- Tensor Integer -> [Integer]
\x -> let y := inc x in tensorShape y
                                     -- Tensor Integer -> [Integer]
```

`ignore : a -> Integer` が引数を使わずスカラーを返す場合，`tensorShape (ignore (inc x))` の結果への要求だけでは，`x` をテンソル型に固定しない．`tensorShape 1` は階数 0 の包含で `[]` を返す．

`def inner u v := u_1 * v_1 - u_2 * v_2` は，添字参照のためにベクトル全体を受け取り，関数内で成分を選択する．先にベクトルを成分へ分けてから `u_1` を評価しない．

### 6.2 テンソルの積と縮約

縮約は，同じ名前の上下の添字に対応する成分をまとめる操作である．Egison のライブラリの基本操作は次の型を持つ．

```text
contract     : Tensor a -> [Tensor a]
contractWith : (Tensor a -> Tensor a -> Tensor a) -> Tensor a -> Tensor a
```

`contractWith reducer t` は `foldl1 reducer (contract t)` として定義する．積も共通の型付け規則で扱う．

```egison
def dot u v := contractWith (\x y -> x + y) (u * v)
-- Tensor Integer -> Tensor Integer -> Tensor Integer

-- 挿入後の本体
\u v -> contractWith (\x y -> tensorMap2 (+) x y) (tensorMap2 (*) u v)
```

`contractWith` の入力から `u * v` に要求が伝わり，`u` と `v` はテンソル型になる．スカラーを渡す場合にも同じ本体を使い，`dot 2 3` は値 `6`，静的な型は `Tensor Integer` である．添字のあるベクトルでは内積，行列では行列積を表せる．`dot a b`，`(dot a) b`，`let p := dot a in p b`，`map (dot a) xs` でも同じ入力型を使う．

論文と Lean の整数モデルでは，縮約の基本操作を `contractWith : (a -> a -> a) -> Tensor a -> Tensor a` と表す．このモデルの型と，Egison のライブラリの `contract` による分解および還元関数の型は区別する．

## 7. 型注釈

型注釈とは，利用者が式や仮引数に書く型である．通常は型注釈を必要としない．

### 7.1 仮引数の型を指定する場合

`(x : Integer)` と書いた仮引数は，テンソル印のないスカラー型になる．テンソルを渡す場合は関数の外側の適用を持ち上げる．型変数による注釈，例えば `foldl` の `(init : b)` には，本体の型付けからテンソル印がつきうる．通常の注釈の照合では，テンソル印を消した型を使う．

```egison
def mkS (x : Integer) : Tensor Integer := [|x, x + 10|]
mkS [|1,2|]
  → tensorMap mkS [|1,2|]
-- [|[|1,11|],[|2,12|]|]
```

### 7.2 縮約結果へのトップレベルの注釈

トップレベル定義の型注釈と推論型を合わせる境界では，外側の `Tensor` を取り除いて照合する規則を引き続き認める．例えば，縮約結果の推論型が `Tensor Integer` でも，利用者は `Integer` と注釈できる．**この規則は，利用者が実際の結果に合う型を正しく注釈することを前提とする**（2026-11-11 の決定）．階数が 0 であることを型推論が証明する規則ではない．

```egison
def A := [|1,2|]~i
def B := [|10,20|]_i
def r : Integer := dot A B
-- 注釈なしの式 dot A B は Tensor Integer，値は 50
-- r は注釈した Integer として使う
```

この照合は，テンソル印を消す処理とは別である．固定された `Tensor Integer` はテンソル印を消しても変わらないが，この明示的な注釈は受け入れる．通常の適用や型の等式で `Tensor a` と `a` を同一視したり，リストなどの内部の `Tensor` を無条件に消したりする規則にはしない．型を合わせるために値を成分へ分解する処理やテンソルを構築する処理も追加しない．

## 8. 生成する式と挿入なし型付け

### 8.1 テンソル印の決定から式を作る

- テンソル印を持つ定義の使用箇所では，確定したテンソル印から，既知の演算への挿入と，実際の関数を渡す箇所での挿入を生成する．例えば `sum` の本体では，`foldl` へ渡す `(+)` を包むかどうかがテンソル印によって変わる．このように生成する式が変わる定義には「テンソル印の値ごとの本体」を使う．未確定の関数の仮引数の適用ごとに挿入を選んだ本体は作らない．テンソル印がすべてスカラーなら，テンソル印に基づく挿入は行わない．テンソル型の位置から決まる挿入は，テンソル印の値によらず行う．
- テンソル印の値ごとの本体は，使われた組合せの分だけ作り，同じ組合せには同じものを使う．組合せを先にすべて作らない．
- `foldl`・`map`・`filter`・`apply`・`gp` のように，関数の仮引数を呼ぶかそのまま渡すだけの部分は変更しない．呼び出し側で包んだ関数を渡し，定義内では同じ関数を共有する．この挿入のために，`foldl` の `fn init x` や `apply` の `k x` を変更した別の本体や，`gp` の `k` の使用ごとに変換を選ぶ本体を作らない．
- テンソル型の位置から決まった仮引数を持ち，テンソル印による挿入の違いがない定義（`.` など）は，挿入を行った本体を一つだけ持つ（§6.2 の本体）．`tensorMap`・`tensorMap2` はスカラーの入力も受け取るので（`tensorMap2 (*) 2 3` は 6），スカラーの実引数にも同じ本体を使う．`\x -> tensorShape (x + 1)` も同じ扱いであり，スカラー入力用に挿入なしの別の本体を作らない．

### 8.2 挿入なし型付けとの関係

- テンソル型の位置から §3.1 の規則 1 で決まる挿入は，入力式全体に挿入なしの型付けがあっても行う．この場合，式そのものを保つことに代えて，階数 0 の入力に対する評価結果を保つ．例えば `\x -> tensorShape (x + 1)` は本体が変わるが，スカラー入力では挿入前後とも `[] : [Integer]` を返す．
- 上の挿入以外については，入力式全体が挿入なしで型付けできるなら，その式を変えないという原則を保つ．テンソル型の位置からの根拠がない挿入を，この例外を理由に追加しない．

階数 0 の包含そのものは，従来どおり値も式も変えない．テンソル型の位置から追加するのは，テンソル型の位置へ結果を渡す演算を成分ごとにするための `tensorMap`・`tensorMap2` である．この区別を，型付け規則と保存の定理にも反映する．

挿入なし型推論は，利用者が明示した `tensorMap`・`tensorMap2` を含む式も，追加の挿入なしで型付けする．自動挿入型推論は，型と必要な挿入を一緒に求める．この二つの扱いを合わせた利用者向けの型推論を統合型推論と呼ぶ．新設計では，上のテンソル型の位置からの挿入を優先し，そのほかでは入力式全体の挿入なし型付けを保つ．現行実装の「まず挿入なし型推論を試し，成功すれば必ず元の式を使う」という手順をそのまま規則にしない．

```egison
\x -> tensorShape (x + 1)
  → \x -> tensorShape (tensorMap (\z -> z + 1) x)
-- Tensor Integer -> [Integer]

(\x -> tensorShape (x + 1)) 5        -- [] : [Integer]
(\x -> tensorShape (x + 1)) [|1,2|]  -- [2] : [Integer]
```

上の二つには同じ挿入後の本体を使う．スカラー入力では，挿入前と同じ値 `[]` と結果型 `[Integer]` を保つ．

明示した `tensorMap` では，成分に適用する関数がテンソル型を受け取る場合も，階数 0 の包含を使える．例えば次の式では，同じ `f : Tensor Integer -> Integer` を使い，最後の適用に新たな挿入は行わない．

```egison
(\f -> let ys := tensorMap f [|1,2|] in f [|1,2|]) (\x -> 0)
-- 0 : Integer
```

既にある `tensorMap` を同じ理由で二重に包まない．渡す関数の式は一度束縛して，生成した関数の中で共有する．型や挿入の決定のためにソースのプログラムを実行しない．

## 9. リスト・分岐・関数の共通型

リスト構築，先頭への追加，連結，条件分岐では，成分や分岐に共通する型を求める．スカラーを階数 0 として受け取り，リストやタプルの内部にあるテンソルの位置も保つ．

```egison
[1] ++ [[|2,3|]]                     -- [Tensor Integer]
[[|2,3|]] ++ [1]                     -- [Tensor Integer]
[\x -> 0, \x -> [|0|]]              -- [a -> Tensor Integer]
```

関数は入力型を保ったまま返り値を階数 0 として受け取れる．上の関数のリストでは，要素の順序によらず同じ共通型になり，どちらの関数の本体にも挿入やテンソル構築を加えない．返り値がさらに関数の場合も，入力型を保つ条件でこの受け取りを繰り返せる．`\v -> 1` のように引数を使わない関数は，テンソル全体を受け取れる．結果を `Tensor Integer` として受け取るだけなら，同じ式を使う．

階数 0 の包含では `tensor [] [e]` を生成しない．`a` の値を `Tensor a` として受け取ることと，型の等式 `a = Tensor a` を解くことは別である．後者は正規化 `Tensor (Tensor b) = Tensor b` に従い，`a := Tensor b` と解く．リストなどを介して自分自身を含む型は循環する型として拒否する．

入れ子の適用では，外側が要求する型も内側の結果型の制約に含める．例えば `dp vars (map unique cnf)` の `dp` が `[[MathValue]]` を要求する場合，`map` の結果の要素型を `[MathValue]` と照合する．結果がリストだと分かる前に，`unique` へ不要なテンソル用の挿入を決めない．一方，型変数を含む期待型などから早く確定した型だけを理由に，全体の制約で成立する挿入を拒否しない．この処理でも，定義の本体は推論し直さない．

## 10. 型クラスと自動挿入の対象

型クラスは，加算など共通の操作を持つ型をまとめる仕組みである．スカラー型かどうかの判定には，具体型だけでなく型クラスの制約も使う．制約のない型変数だけではスカラーと断定しない．

例えば `+ : {AddSemigroup a} a -> a -> a` へ `Tensor Integer` を渡すとき，`AddSemigroup (Tensor Integer)` のインスタンスを要求するのではなく，要素型 `Integer` の加算を成分ごとに適用する．型の置換を制約にも反映してから定義を一般化し，使用箇所にも型と制約を一緒に引き継ぐ．型と挿入の決定後に，要素型に対応する操作の実装を選ぶ．操作をまとめて渡す値を型クラス辞書と呼び，その展開は挿入より後に行う．

`IO`，`IORef`，`Port` とこれらを含む型は，成分ごとの自動変換の対象にしない．関数型そのものを通常のスカラー成分と見なして持ち上げることもない．高階関数へ渡す関数を包む処理や，テンソルに格納された関数を呼び出す処理は，関数値をデータ成分として変換することとは区別する（§5）．

## 11. 添字・微分形式・シンボル宣言

添字はテンソル値の各軸に付く実行時情報であり，`Tensor a` の型引数には入らない．

```egison
def g_i_j : Tensor MathValue := [| [| 1, 0 |], [| 0, r^2 |] |]_i_j
def g~i~j : Tensor MathValue := [| [| 1, 0 |], [| 0, 1 / r^2 |] |]~i~j
```

同じ名前の共変添字と反変添字は，`contract` や添字つき演算によって縮約される．縮約後が
スカラーかテンソルかは型だけからは決まらないため，§7.2 のトップレベルの型注釈の
照合規則を使う．

### 11.1 追加添字と既存の名前の範囲

`tensor..._j` は，先頭から連続する名前付き軸だけを残し，その直後から新しい添字を処理する．名前のない軸の内側に名前付き軸があっても，その名前は残す範囲には含まれない．例えば `([|[|1,2|]_i,[|3,4|]_i|])..._j` の結果には外側の `_j` だけが付き，内側の古い `_i` は消える．`..._2` は名前のない `[|3,4|]` を返す．これは論文の，既存の先頭部分と新しい添字列を連結してから直接参照する規則に対応する．

内部の `DF` は名前のない次元を表す実行時の記号であり，§2 の型につけるテンソル印とは別である．数値添字やシンボリックな添字として `tref` に渡さない．

`withSymbols` は，その式で導入した添字名だけを取り除く．名前のない軸には添字名を
取り出す操作を適用せず，その軸の寸法と成分を保持する．例えば
`withSymbols [i] [|[|1,2|]_i,[|3,4|]_i|]` は，名前のない外側の軸を保って
`[|[|1,2|],[|3,4|]|]` を返す．

添字による軸の並べ替えは，名前のない軸も含めた入力全体から指定した軸を探す．
指定した軸を先頭へ移し，残りの軸の順序を保つ．行列を値に持つ微分形式のように，
名前のある軸と名前のない軸が混在する場合も同じ規則を使う．
微分形式の積に使う一時的な軸情報は，部分積を結合して全体の軸順序を確定した後に除去する．

### 11.2 内部の空の保存配列

公開の `tensor` と `generateTensor` は0以下の軸長を拒否する．内部の配列表現と添字処理は，0の軸長も扱う．内部の参照処理は次元と添字の列を直接処理し，成分がなくても後続の軸長を保持する．例えば，内部の形状 `[0,3]` への `_i` は形状 `[0,3]` を保ち，`_i_4` は範囲外として失敗する．これは内部処理の性質であり，利用者が `tensor [0,3] []` を構築できることを意味しない．

実装箇所と検査対象は [仕様と実装の対応](tensor-inference-boundaries.md) に記す．

### 11.3 Wedge 適用

`!` を伴う Wedge 適用では，スカラー二項関数なら `tensorMap2` の Wedge 版へ変換し，
微分形式の添字を補ってから成分ごとに適用する．関数自身がテンソルを受け取る場合は，
通常の Wedge 適用を保つ．

### 11.4 シンボル宣言

テンソル成分に使う自由な数式シンボルは，未束縛変数ではなく `declare symbol` で宣言する．

```egison
declare symbol a11, a12, a21, a22
declare symbol x, y, z : Float
```

型を省略した場合は `Integer` を使う．宣言は型環境へ登録されるため，参照時に未束縛変数の
警告を出さない．CAS のシンボル値としての構築と型環境への登録は評価の前に行う．

## 12. 例と期待する結果

以下は新設計の期待結果であり，今後の実装の受け入れ検査にも使う．`inc` は `def inc x := x + 1`，`dot` は `def dot u v := contractWith (\x y -> x + y) (u * v)`，`A` は `[|1,2|]~i`，`B` は `[|10,20|]_i`，`ts` は `[[|1,2|],[|3,4|]]` である．

### 12.1 定義の型

基本の型は §2 の一覧のとおりである．そのほかに，規則から次の型になる．

```
def twiceSum xs := sum xs + sum xs       -- [Integer*p] -> Integer*p
def h x k := [|k x + 10, k x + 20|]      -- a*p -> (a*p -> Tensor Integer) -> Tensor Integer
def hIf x k := if k x > 0 then 1 else 0  -- a -> (a -> Integer) -> Integer
\x -> tensorShape (x + 1)                -- Tensor Integer -> [Integer]
\x -> x + [|10,20|]                      -- Integer -> Tensor Integer
\xs -> head xs + 1                       -- [Integer*p] -> Integer*p
\k -> k 5 + 10                           -- (Integer -> Integer*p) -> Integer*p
```

`h` でも，`x` の型と `k` の入力型に同じ `a*p` を使う．二つの `k x` は同じ関数型を共有する．`k` の結果はテンソル構築式の成分へ流れるため，固定の `Tensor Integer` である．

`g` の型のように，テンソル印は名前で区別する．`g ts [5,6]` の型は `(Tensor Integer, Integer)` である．

### 12.2 テンソル全体を受け取る例

### 12.7 同じ関数引数を共有する例

§5 の `gp` の本体は `(map k xs, k 0)` のままである．テンソルのリストを渡す場合には，一度包んだ `k : Tensor Integer -> Tensor Integer` を両方の箇所で使う．

```egison
gp inc [[|1,2|]]
  → gp (\t -> tensorMap inc t) [[|1,2|]]
-- ([[|2,3|]], 1) : ([Tensor Integer], Tensor Integer)

gp inc [1,2]
-- ([2,3], 1) : ([Integer], Integer)
```

値だけでなく，右側の静的な型と挿入箇所も確認する．`foldl` についても，本体の `fn init x` と再帰呼び出しに，最初に渡した同じ関数を使うことを確認する．`apply` では，本体の `k x` を変更せず，関数を渡す箇所だけで挿入を決めることを確認する．
