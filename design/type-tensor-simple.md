# Egison のテンソル型・型推論・挿入の設計仕様

状態：**設計仕様．`↑` の推論と挿入は実装・証明の確認対象である．** この文書を，利用者が設計全体の意図を確認するための正本とする．型と評価結果の例は仕様上の期待結果であり，現行処理系で確認済みという意味ではない．実装状況は [仕様と実装の対応](tensor-inference-boundaries.md)，作業項目は [実装・証明の課題](tensor-lifting-tasks.md) に記す．

引数型，返り値型，持ち上げを許す位置の指定を利用者に要求しない．定義の本体を一度だけ型付けし，型，制約，挿入する位置を保存する．高階関数（関数を引数として受け取る関数）の型では，受け取る関数型の各入力型の後ろに，その入力位置の持ち上げを許す `↑` を付ける．例えば `map : (a↑ -> b) -> [a] -> [b]` の `a -> b` は，必要な変換を行った後に `map` の本体が受け取る関数の型である．

**挿入**とは `tensorMap`・`tensorMap2` の呼び出しを式に加えることである．**スカラー**は，整数など，テンソルの一つの成分として扱う値である．挿入は次の二つに分ける．

1. **スカラー関数にテンソルを渡す場合**：その関数呼び出しを，テンソルの成分ごとの適用へ変える．この処理を**持ち上げ**と呼ぶ（§4）．
2. **高階関数にスカラー関数を渡す場合**：受け取る関数型の `↑` が許す入力位置を選び，渡すスカラー関数全体を，その入力の成分ごとに適用する関数に包む（§5）．受け取った仮引数の各適用や転送では，別の変換を選ばない．

**階数0の包含**とは，スカラーを値も式も変えずに，軸を持たないテンソルとして受け取ることである．そのためだけのテンソル構築は挿入しない．用語は [EgisonTERM.md](../EgisonTERM.md) §9 に従う．

## 1. テンソル型と実行時の形状

テンソルは `Tensor a` と型付けし，`a` は要素型を表す．次元数，各軸の大きさ，添字名，
共変・反変（下付き・上付きという添字の区別）は型には含めない．

```egison
def v : Tensor Integer := [| 1, 2, 3 |]
def m : Tensor Integer := [| [| 1, 0 |], [| 0, 1 |] |]
```

入れ子の `Tensor` 型は正規化で一つにまとめる．

```text
Tensor (Tensor a)  =  Tensor a
```

テンソル構築式は `[|e1, ..., en|]` のように成分を並べる式である．成分の型は `Tensor` で包んで比較する．例えば整数と整数のテンソルは，どちらも `Tensor Integer` として受け取る．成分の形状がそろうかは実行時に検査する．`[|1, [|2,3|]|]` は型エラーにせず，実行時の形状エラーにする．異なる要素型を無条件に混在させてよいという意味ではない．

実行時には，階数 0 のテンソルをスカラーそのものとして表す．例えば
`generateTensor f []` はテンソル容器ではなく `f []` を返す．大きさ 1 のベクトルは
階数 1 なので `Tensor a` のままである．

生成関数がテンソルを返す場合は，外側の形状 `S` と共通する内側の形状 `R` を `S ++ R` に
連結し，スカラー成分の配列も連結する．例えば `generateTensor (\_ -> [|1,2|]) [2]` は形状
`[2,2]`，成分 `[1,2,1,2]` を持つ．生成・保存配列・成分ごとの適用の結果を
組み立て，内側の形状と添字の一致を検査する．リストなどのデータの内部はたどらない．
成分の形状が異なる `[|[|1,2|],[|3|]|]` は構築時に形状の不一致による形状エラーとする．成分ごとの適用が返したテンソルを並べる場合も同じであり，`tensorMap (\f -> f 1) [|(\x -> [|x|]),(\x -> [|x,x|])|]` は同じ形状エラーとなる．通常のリストはスカラーなので，`[|[1,2],[3]|]` は許す．
`tensor` と `generateTensor` の各軸長は正整数に限る．`tensor` は通常の引数評価後，軸長，成分数の順で検査する．`generateTensor` は形状の検査後に座標を列挙し，不正な形状では生成関数を適用しない．形状 `[]` は階数0として許し，空の座標へ一度適用する．空のテンソル構築式と，始点が終点を超える範囲参照は実行時エラーにする．通常の空リストはスカラーのまま扱う．

行列の分解で必要になる0行・0列の部分行列は，通常のデータ `MatrixBlock a` で表す．
行数・列数・成分列を保持し，テンソルへの変換は両方の寸法が正の場合だけ許す．
この処理にはテンソルの型推論や軸長の例外を追加しない．
[行列の逆行列と部分行列](matrix.md) に公開操作と分解・結合の規則を記す．

## 2. 型と持ち上げの許可

型は型変数，整数などの基本型，関数型，リストなどのデータ型，`Tensor a` で表す．**持ち上げの許可（lifting permission）**を `↑` と書き，高階関数が受け取る関数の入力型ごとに付ける．

```text
map    : (a↑ -> b) -> [a] -> [b]
map2   : (a↑ -> b↑ -> c) -> [a] -> [b] -> [c]
filter : (a -> Bool) -> [a] -> [a]
foldl  : (b↑ -> a↑ -> b) -> b -> [a] -> b
apply  : (a↑ -> b) -> a -> b
```

- `(a↑ -> b)` は，渡す関数の第1入力を，必要なら成分ごとの適用へ持ち上げてよいことを表す．`↑` はその入力位置への許可であり，型変数 `a` のほかの出現には付かない．
- `↑` を除いた `a -> b` は**変換後に受け取る関数型**である．渡す関数の元の型は別に推論する．`↑` 自体は型構成子でも実行時の値でもなく，挿入を必須にしない．
- 一つ以上の入力位置を持ち上げると，結果もテンソル型になる．結果型には `↑` を付けず，変換後の入力型と結果型の両方を照合する．
- `↑` のない入力位置は，新たに成分ごとの適用へ変換しない．通常の型の具体化と階数0の包含は使える．ほかの入力位置の持ち上げにより関数全体を包む場合も，この入力はそのまま渡す．
- 型変数は `Tensor Integer` などにも具体化できる．`foldl` の累積値の入力・結果・初期値・最終結果は `b`，リスト要素は別の `a` である．同じ型変数の出現は同じ具体化を共有する．
- 明示的なテンソル型の入力に許可を付ける場合は，`(Tensor a)↑` と書く．型全体を括弧で囲み，その入力位置を示す．渡す関数が既にそのテンソル全体を受け取れるなら，その入力位置を持ち上げない．
- 各入力位置の `↑` は定義時に推論する．実際に持ち上げる入力位置の集合は，全引数と要求結果型の制約を合わせて一度だけ決める．許可のある位置の任意の組合せを無条件に認めるものではない．

`map2` は，二つのリストの対応する要素を関数へ渡す．例えば次の式では，加算の第2入力だけを持ち上げる．

```egison
map2 (+) [1,2] [[|10,20|],[|30,40|]]
  → map2 (\x t -> tensorMap ((+) x) t) [1,2] [[|10,20|],[|30,40|]]
-- [[|11,21|],[|32,42|]] : [Tensor Integer]
-- a = Integer，b = Tensor Integer，c = Tensor Integer
```

両入力を持ち上げる場合は，渡す関数を `\s t -> tensorMap2 (+) s t` のように一度包む．いずれの場合も，`map2` の本体が受け取る関数と型は一つである．

`map` の三つの例では，次のように具体化する．`tensorRank : Tensor a -> Integer` は階数を返す関数とする．

```egison
map inc [[|1,2|]]
-- inc : Integer -> Integer を Tensor Integer -> Tensor Integer へ包む
-- a = Tensor Integer，b = Tensor Integer
-- [[|2,3|]] : [Tensor Integer]

map tensorRank [[|1,2|]]
-- Tensor Integer -> Integer をそのまま渡す
-- a = Tensor Integer，b = Integer
-- [1] : [Integer]

consume : (Integer -> Integer) -> Tensor Integer
map consume [\x -> x+1]
-- consume をそのまま渡す
-- a = Integer -> Integer，b = Tensor Integer
-- 結果の型は [Tensor Integer]
```

入力がテンソルであるだけでは，結果をテンソル型にしない．結果にもテンソル型を加えるのは，スカラー関数を持ち上げる変換を実際に行う場合である．元からテンソルを返す関数や，テンソル全体を受け取ってスカラーを返す関数は，型が合えばそのまま渡す．

## 3. 定義を一度だけ型付けする

### 3.1 本体の型と制約

**制約**は，型の等式，式を変えない型の包含，または許可された関数変換について満たすべき条件である．定義の本体を一度走査して制約を集め，その定義の型と一緒に保存する．型が未確定の位置は，次の規則で扱う．

1. **テンソル型の位置へ流れる式は，`Tensor` 型にする．** スカラー演算の結果がその位置へ流れる場合は，型が未確定の入力へ要求を伝え，その演算を成分ごとにする．`\x -> tensorShape (x+1)` では，`x+1 : Tensor Integer` の要求から `x : Tensor Integer` が決まる（§4.2）．
2. **関数の仮引数の適用は，共有する一つの関数型で通常の適用として型付けする．** 同じ `k` の `k x` や `map k xs` ごとに変換を選ばない．転送先の型との制約も，この共有型へ集める．
3. **スカラー演算へ直接渡す仮引数は，テンソル型の要求がなければスカラーにする．** `\x -> x+1` は `Integer -> Integer`，`\x -> let unused := x+1 in True` は `Integer -> Bool` である．結果を捨てても入力だけの変換を許さない．
4. **中間結果の型が未確定なら，既知の演算への変換条件を保存する．** `head xs + 1` や `k 5 + 10` の加算については，入力・結果の関係と挿入位置を定義時に記録する．使用時に新たに本体を調べない．
5. **ほかは型変数のままにする．** `\x -> x` は `a -> a` である．`\k -> k [|1,2|]` では，渡す実引数から `k` の入力が `Tensor Integer` に決まる．

### 3.2 `↑` を付ける条件

本体から得た型と制約を用いて，関数の仮引数の**入力位置ごと**に判定する．関数の仮引数を `k`，その第 `i` 入力の型を `τi` とする．

1. `k` のすべての適用・転送・再帰呼び出しで共有する型と，定義の全制約を取り出す．
2. **第 `i` 入力を含む集合を持ち上げる**合法な関数変換を，`k` の要求型で受け取れる具体化が存在するか調べる．選んだ位置では対象となるスカラー入力をテンソル型にし，受け取る関数のその入力型も `Tensor` 型として照合する．結果もテンソル型にする．固定した `Integer` などの入力型は，この判定のために変えない．変換は §10 の対象制限にも従う．
3. 全制約を保つ具体化が一つでもあれば，その入力型を `τi↑` とする．すべての候補が固定の型や共有制約に反するなら，その位置には付けない．

第 `i` 入力だけで持ち上げが成立する必要はない．ほかの入力も同時に持ち上げて初めて制約を満たす場合がある．各 `↑` はその位置を含む変換が可能であることを示し，許可同士の独立性は保証しない．使用時には，許可された位置の部分集合から，実際の関数の型と全制約を満たす変換を選ぶ．複数の関数引数がある場合も，共有する型変数と制約を切り離さない．

この判定は，定義時に受け取り側から得た制約を解くものである．関数を渡す際に，どちらかの本体を調べ直したり，受け取った `k` の各適用で別の変換を選んだりしない．

#### `map` と `filter` の違い

```text
map k xs = case xs of
  []      -> []
  x :: ys -> k x :: map k ys
```

`map` では `k : a -> b`，`x : a`，`k x : b`，結果は `[b]` である．`a = Tensor α`，`b = Tensor β` と具体化しても，同じ本体と再帰呼び出しが型付けできる．したがって `k` の入力型 `a` に `↑` を付ける．

```text
filter k xs = case xs of
  []      -> []
  x :: ys -> if k x then x :: filter k ys else filter k ys
```

`filter` では条件式が `k x : Bool` を要求する．スカラー述語を持ち上げると `Tensor Bool` を返すため，この条件を満たせない．したがって `↑` を付けない．型変数 `a` をテンソル型に具体化して，テンソル全体を受け取る述語を渡すことはできる．

高階関数自身の最終結果だけでは判断しない．

```text
discard k x = let unused = k x in True
discard : (a↑ -> b) -> a -> Bool
```

ここでは `k` の結果 `b` は固定されないため，入力型 `a` に `↑` を付けられる．`map2` の `k : a -> b -> c` では，両入力位置について判定が成立し，`a↑ -> b↑ -> c` となる．

入力位置によって判定が異なる例は次である．

```egison
def use k xs := map (\x -> k 0 x) xs
-- (Integer -> a↑ -> b) -> [a] -> [b]
```

`k` の第1入力は `0` への適用から `Integer` に固定されるため，その位置には `↑` が付かない．第2入力と結果にはテンソル型の具体化が可能なので，第2入力だけに許可が付く．`use` へ渡す実際の関数を変換した後は，本体の `k 0 x` を通常の適用のまま使う．

`foldl` では，累積値とリスト要素を区別して `(b↑ -> a↑ -> b) -> b -> [a] -> b` を得る．例えば整数の加算の第2入力を持ち上げると，結果は `Tensor Integer` になる．次の累積値も同じ `b` なので，この場合は第1入力も持ち上げなければならない．各位置の許可と，実際に許される組合せを，この共有制約で結び付ける．

### 3.3 保存する情報と一般化

定義には，型，`↑` の位置，未解決の制約，定義時に決めた挿入位置を保存する．**型スキーム**は，異なる使用で具体化できる型変数を量化し，制約を伴った型である．周囲と共有していない型変数を量化する操作を**一般化**と呼ぶ．捕捉した単相の型・値と，再帰定義内の型は共有する．別名も保存した型と制約を引き継ぐ．

```egison
def inc x := x+1                  -- Integer -> Integer
def apply k x := k x              -- (a↑ -> b) -> a -> b
def sum xs := foldl (+) 0 xs
def f xs ys := sum xs + sum ys
def g xs ys := (sum xs, sum ys)
```

`sum` の型は，制約付きで `[a] -> a` と表せる．制約は「整数の加算 `(+)` を `(a↑ -> a↑ -> a)` の位置へ渡せること」と「`0` を `a` として受け取れること」である．`a` は無制限に具体化できる変数ではない．スカラーの使用では `a = Integer`，テンソルの使用では `a = Tensor Integer` となり，後者では記録された `(+)` の受け渡し位置に挿入する．

```egison
sum [1,2]                         -- 3 : Integer
sum [[|1,2|],[|3,4|]]             -- [|4,6|] : Tensor Integer
g [[|1,2|]] [3,4]                 -- ([|1,2|], 7) : (Tensor Integer, Integer)
f [[|1,2|]] [3,4]                 -- [|8,9|] : Tensor Integer
```

`f` と `g` の二つの `sum` は，それぞれ新しい型変数と制約を使う．`f` は両結果への加算の変換条件も持ち，`g` は二つの結果型をそのまま保持する．単一の型表示に残る制約を省いて，これらが任意の要素型を受け取れるかのように表示してはならない．

同じ具体化と変換を使う呼び出しでは生成した本体を共有する．使用されない組合せを先に生成しない．テンソル型の要求だけで挿入が固定される定義は，一つの本体を使う．

## 4. スカラー関数にテンソルを渡す場合

関数へ引数を渡す式を**適用式**と呼ぶ．第1の挿入は，スカラー型の引数を受け取る関数にテンソルを渡す適用式を，成分ごとの適用へ変えるものである．この処理を**持ち上げ**と呼ぶ．

### 4.1 スカラー関数を成分ごとに適用する

`inc` の型は `Integer -> Integer` である．`def inc x := x + 1` の `x` のように，定義で引数を受け取る変数を**仮引数**と呼ぶ．`inc [|1,2|]` の `[|1,2|]` のように，適用式で渡す式を**実引数**と呼ぶ．この例では，仮引数の型が `Integer`，実引数の型が `Tensor Integer` なので，次の挿入を行う．

```egison
inc [|1,2|]
  → tensorMap inc [|1,2|]
-- [|2,3|] : Tensor Integer
```

`inc` 自身の型は `Integer -> Integer` のままで，挿入後の適用式の結果型は `Tensor Integer` になる．

二引数のスカラー関数では `tensorMap2` を使う．

```egison
[|1,2|] + 10
  → tensorMap2 (+) [|1,2|] 10
-- [|11,12|] : Tensor Integer
```

三引数以上では，添字の整列を保つように `tensorMap2` を複数組み合わせる．もともとテンソル全体を受け取る引数には，全体を渡す．スカラー入力に対する `tensorMap`・`tensorMap2` は通常の適用として働く．

```egison
inc [|1,2|]                         -- tensorMap inc [|1,2|]
tensorMap inc 5                     -- 6
tensorMap2 (+) [|1,2|] 10            -- [|11,12|]
```

複数の引数がある場合，持ち上げる引数は，全引数と結果に要求される型から決める．二つの挿入に共通する判断は §5.4 に記す．

### 4.2 関数の本体内にあるスカラー演算への挿入

同じ規則は，関数の本体内にある既知のスカラー演算にも適用する．例えば次の関数では，`tensorShape` が `x + 1 : Tensor Integer` を要求するため，未確定の `x` も `Tensor Integer` と推論する．そのため，`x + 1` の加算を成分ごとにする．

```egison
\x -> tensorShape (x + 1)
  → \x -> tensorShape (tensorMap (\z -> z + 1) x)
-- Tensor Integer -> [Integer]
```

この挿入は第1の場合である．`x` の型はテンソル型なので，あとで階数 0 の値を渡す場合も同じ本体を使う（§6，§8.2）．

保存した制約の具体化によって演算の入力型が決まる場合も同じ扱いになる．例えば `\xs -> head xs + 1` では，リスト要素が `Tensor Integer` に決まると，`head xs` の結果への加算に挿入する．これは定義時に記録した挿入箇所である．高階関数へ渡す際に，スカラー型に決まった関数の本体から新たな挿入箇所を探す処理は行わない．

### 4.3 テンソル全体をそのまま受け取れる場合

次の型の仮引数は，テンソル全体を受け取れるため，この適用への挿入は不要である．

- **型変数 `a`**：`a` をテンソル型に具体化する．例えば `\x -> x` の型は `a -> a` であり，この関数に `[|1,2|]` を渡す場合は，`a` を `Tensor Integer` にする．
- **`Tensor` 型**：要求されたテンソル型と照合してそのまま渡す．例えば `tensorShape [|1,2|]` は，挿入せずにテンソル全体の形状を求める．

型変数の具体化と，必要な持ち上げは区別する．元から受け取れる型へ具体化して済むなら挿入しない．スカラー入力にしか適合しない関数をテンソル入力に合わせるときには，記録した位置の変換条件から挿入する．

## 5. 高階関数にスカラー関数を渡す場合

高階関数へ関数を渡す際は，全引数と結果型の制約を合わせ，受け取る関数型の `↑` が許す入力位置から持ち上げる集合を選ぶ．その集合に従って，実際に渡す関数全体への変換を一度だけ決める．

```egison
map inc [[|1,2|]]
  → map (\t -> tensorMap inc t) [[|1,2|]]
-- [[|2,3|]] : [Tensor Integer]

apply inc [|1,2|]
  → apply (\t -> tensorMap inc t) [|1,2|]
-- [|2,3|] : Tensor Integer
```

`map` と `apply` が受け取る関数型は `Tensor Integer -> Tensor Integer` になる．本体の `k x` は通常の適用のままである．`map inc [1,2]` では `inc` をそのまま渡す．

`foldl` では `b` が累積値，`a` がリスト要素の型であり，それぞれ独立に具体化する．

```egison
foldl (+) 0 [[|1,2|],[|3,4|]]
  → foldl (\u v -> tensorMap2 (+) u v) 0 [[|1,2|],[|3,4|]]
-- [|4,6|] : Tensor Integer

foldl (+) [|1,2|] [10,20]
-- [|31,32|] : Tensor Integer

foldl (\acc t -> acc + tensorRank t) 0 [[|1,2|],[|3,4|]]
-- 2 : Integer
```

第一の例では，加算を持ち上げると結果が `Tensor Integer` になり，次の累積値でも同じ型を使うため，`b = Tensor Integer` となる．初期値 `0` は階数0として受け取る．第三の例では，渡す関数が `Integer -> Tensor Integer -> Integer` を持ち，`a = Tensor Integer`，`b = Integer` としてそのまま受け取る．

渡す関数がもともとテンソル全体を受け取る位置には，全体を渡す．`foldl (.) A [B]` は積を包まずに使う．`contractWith` の還元関数の両入力にも `↑` を推論する（§6.2）．

```egison
def gp k xs := (map k xs, k 0)
gp inc [[|1,2|]]
  → gp (\t -> tensorMap inc t) [[|1,2|]]
-- ([[|2,3|]], 1) : ([Tensor Integer], Tensor Integer)
```

`gp` では，`k : Tensor Integer -> Tensor Integer` を両方の箇所で共有する．`k 0` は階数0の入力を受け，値 `1` を同じ結果型 `Tensor Integer` で返す．`map k xs` の転送位置で `k` を別に包まず，`k 0` だけを別の関数型で使わない．

### 5.1 述語を渡す場合

述語は真偽値を返す関数である．`filter` は通常の多相型を持つ．テンソルのリストに使う場合は，型変数 `a` をテンソル型に具体化する．

```text
filter : (a -> Bool) -> [a] -> [a]
-- a := Tensor Integer の場合
filter : (Tensor Integer -> Bool) -> [Tensor Integer] -> [Tensor Integer]
```

`filter` の述語の入力には `↑` がない．一般に自動変換では，`↑` のある入力位置から持ち上げる集合を選び，渡す関数全体を `tensorMap`・`tensorMap2` でその入力の成分ごとに適用する関数へ包む．入力型と結果型の両方を，受け取り側の要求と照合する．`filter` の本体も，渡す述語の本体も，この照合のために調べない．

```egison
def pred x := let unused := x + 1 in True
-- Integer -> Bool

pred [|1,2|]
  → tensorMap pred [|1,2|]
-- [|True,True|] : Tensor Bool

filter pred [1,2]       -- [1,2] : [Integer]
filter pred [[|1,2|]]   -- 型エラー
```

`pred` 全体を包むと `Tensor Integer -> Tensor Bool` になる．`filter` が要求する `Tensor Integer -> Bool` には合わない．本体内の `x + 1` だけへ自動挿入して結果を `Bool` に保つ変換は認めない．加算の結果を使っていないことは，`pred` の入力だけを変換する理由にはならない．

直接書いたラムダ式，名前付き関数，保存した関数にも同じ規則を適用する．次はいずれも型エラーである．

```egison
filter (\x -> let unused := x + 1 in True) [[|1,2|]]
filter pred [[|1,2|]]
let predicates := [pred] in
  filter (head predicates) [[|1,2|]]
```

テンソル全体を受け取って `Bool` を返せる述語は，そのまま使える．利用者が `tensorMap2` を明示した次の述語は，定義自身から `Tensor Integer -> Bool` と型付けされる．

```egison
def predTensor x := let unused := tensorMap2 (+) x 1 in True
-- Tensor Integer -> Bool
filter predTensor [[|1,2|]]
-- [[|1,2|]] : [Tensor Integer]

filter (\x -> let unused := tensorMap2 (+) x 1 in True) [[|1,2|]]
-- [[|1,2|]] : [Tensor Integer]

filter (\x -> True) [[|1,2|]]
-- 述語は a -> Bool．a を Tensor Integer に具体化し，そのまま渡す
-- [[|1,2|]] : [Tensor Integer]
```

これらは，渡す式で述語の一部を自動変換して受理する例ではない．定義から得た型の具体化と通常の照合で受理する．`tensorShape (x + 1)` のように，本体自身のテンソル操作が入力型を決める規則は §4.2 のとおりであり，関数の渡し先によらない．

### 5.2 複数の関数引数と共有

```egison
def positive x := x > 0
def mapFilter f p xs := map f (filter p xs)
def filterMap p f xs := map f (filter p xs)

\xs -> mapFilter inc positive xs     -- [Integer] -> [Integer]
\xs -> filterMap positive inc xs     -- [Integer] -> [Integer]
```

`positive` の結果は `Bool` でなければならず，両方の関数が入力型を共有する．全引数の制約をまとめて解き，引数順で結果を変えない．もともとテンソル全体を受け取る述語なら，`mapFilter` または `filterMap` へ `inc` を渡す箇所で，`inc` だけを包める．本体の `map f` と `filter p` はそのままにする．

`\g h -> (g h, h 1)` のように，同じ仮引数を別の高階関数へ渡す場合にも，共有した型を使う．外側へ実際の関数を渡す箇所で変換を決める．本体の `g h` だけで `h` を包み，`h 1` には元のスカラー関数を残す変換は選ばない．

### 5.3 部分適用・別名・関数を返す式

部分適用とは，引数の一部だけを渡して，残りの引数を受け取る関数を得ることである．`(foldl (+)) 0 ts` と `foldl (+) 0 ts` は同じ型・値・挿入の判断になる．`let f := sum` のような別名では，一般化された型変数と制約を各使用で独立に具体化できる．捕捉した値の型は共有し，同名の変数が使用先にあっても捕捉する値を変えない．

```egison
let f := sum in (f [1,2], f [[|1,2|],[|3,4|]])
-- (3, [|4,6|]) : (Integer, Tensor Integer)
```

渡す関数の返り値が，使用箇所でさらに関数型になる場合も，全体の型から引数の個数を求める．型の途中にある `Tensor` を消して照合しない．`Integer -> Tensor (Integer -> Integer)` のような関数は，残る引数を格納された関数へ成分ごとに適用できる．もともとの入力型を保ち，テンソル全体を受け取る位置には全体を渡す．この場合も，関数の仮引数の使用ごとに異なる変換を選ぶことはしない．関数を返す型とテンソル内の関数にも対応する生成手順の形式化は，§13 の証明課題に含める．

### 5.4 二つの挿入に共通する型の判断

**連続適用**は `f e1 ... en` のように引数を続けて渡す式である．全引数と要求結果型の制約を合わせて変換を決める．関数を渡す箇所で「一度だけ」決めるとは，最初の引数を読んだ時点で決めるという意味ではない．`foldl (+)` では，残りの引数からの制約がそろうまで変換条件を保存する．

`sum xs := foldl (+) 0 xs` では，§3.3 の型制約と `(+)` の受け渡し位置を記録する．`sum [1,2]` は加算をそのまま使い，`sum [[|1,2|],[|3,4|]]` は同じ記録から加算を包んだ本体を生成する．`foldl` の本体と，そこでの `fn init x` は変更しない．

通常の適用 `f x` は，挿入の判断について `apply f x` と見なせる．`apply : (a↑ -> b) -> a -> b` の `↑` で `f` を変換し，その関数を適用すれば，第1の挿入と同じ成分ごとの適用になる．この解釈は，受け取った仮引数 `k` の各 `k x` で別の変換を許すものではない．`k` は，外側で実際の関数を渡す位置から一つの型と値を共有する．

後の引数によって，前の引数の扱いが決まることもある．

```egison
def hIf x k := if k x > 0 then 1 else 0
-- a -> (a -> Integer) -> Integer
hIf [|1,-2|] inc
  → tensorMap (\x -> hIf x inc) [|1,-2|]
-- [|1,0|]
```

比較が `k` の結果を `Integer` に固定するため，その入力位置に `↑` は付かない．`inc` をそのまま渡すと `a = Integer` となり，外側の `hIf` の適用をベクトルの成分ごとにする．

判断には次の条件を課す．

- 型の等式，包含，変換条件を合わせて解く．既知のテンソル型の要求を保ち，ほかでは挿入なしで全体を型付けできる場合を優先する．
- 型変数への具体化，階数0の包含，持ち上げを区別する．包含のためだけにラムダ式やテンソル構築を生成しない．
- 持ち上げが必要なら，全体を満たす引数集合のうち，他のすべての成功する集合に含まれる最小の集合を選ぶ．存在しなければ型エラーにする．
- 未解決の型変数と制約を一般化して保持する．実行する使用で持ち上げが不要なら挿入しない．処理順を曖昧さの解消に使わない．
- 定義の本体の候補を列挙して推論し直さない．関数を渡す際は，記録した型・制約・許可された位置だけを使う．同じ仮引数の各使用は同じ型と値を共有する．
- `(foldl (+)) 0 ts` と `foldl (+) 0 ts`，別名，関数を返す式，複数の関数引数でも，同じ制約から同じ判断を得る．

## 6. テンソル型の位置から決まる入力

- テンソル構築式の成分は，テンソル型の位置である．型のわからない成分は `Tensor a` 型になる．
- 成分の型は `Tensor` で包んで比べる．スカラーの成分は階数 0 の包含で受け取る．
- 成分の形状が合わない構築は，実行時の形状エラーである．型推論は，形状エラーを避けるために適用を成分ごとにすることはしない．直接書いた `[| [|1,2|], 10 |]` も，型エラーにせず実行時の形状エラーにする．
- 仮引数がテンソル構築式の成分でなく，構築式と並ぶ引数である場合は，§3.1 の規則 1 は当てはまらない．`\x -> x + [|10,20|]` の `x` はスカラー型のままである．

```egison
(\x -> [|x, x + 10|]) [|1,2|]
  → (\x -> [|x, tensorMap2 (+) x 10|]) [|1,2|]
-- [|[|1,2|],[|11,12|]|] : Tensor Integer

(\x -> [|x, 10|]) [|1,2|]           -- 実行時の形状エラー
[|[|1,2|], 10|]                      -- 実行時の形状エラー
```

### 6.1 要求を伝える範囲

`Tensor` 型の仮引数，テンソル構築式の成分，添字参照の対象を起点として，型が未確定の式の型を決める．ここで起点とは，ソースのテンソル操作が `Tensor` 型を要求する型の位置である．基本操作と利用者定義の関数に同じ条件を使い，演算子の名前だけで判断しない．

成分ごとの適用の結果が `Tensor` 型として必要なら，その適用で成分ごとに扱う入力へ要求を伝える．`let` とその参照，別名の型の関係も使う．一方の入力がテンソルであることだけを理由に，結果を経由して他方の入力をテンソル型に固定しない．通常の適用で入力と結果の型が無関係なら，結果への要求を入力に伝えない．リストの要素や関数の返り値を無条件にたどることもしない．

```egison
\x -> x + [|10,20|]                 -- Integer -> Tensor Integer
\x -> tensorShape (inc x)            -- Tensor Integer -> [Integer]
\x -> let y := inc x in tensorShape y
                                     -- Tensor Integer -> [Integer]
```

`ignore : a -> Integer` が引数を使わずスカラーを返す場合，`tensorShape (ignore (inc x))` の結果への要求だけでは，`x` をテンソル型に固定しない．`tensorShape 1` は階数 0 の包含で `[]` を返す．

`def inner u v := u_1 * v_1 - u_2 * v_2` は，添字参照のためにベクトル全体を受け取り，関数内で成分を選択する．先にベクトルを成分へ分けてから `u_1` を評価しない．

### 6.2 テンソルの積と縮約

縮約は，同じ名前の上下の添字に対応する成分をまとめる操作である．Egison のライブラリの基本操作は次の型を持つ．

```text
contract     : Tensor a -> [Tensor a]
contractWith : ((Tensor a)↑ -> (Tensor a)↑ -> Tensor a) -> Tensor a -> Tensor a
```

`contractWith reducer t` は `foldl1 reducer (contract t)` として定義する．積も共通の型付け規則で扱う．

```egison
def dot u v := contractWith (\x y -> x + y) (u * v)
-- Tensor Integer -> Tensor Integer -> Tensor Integer

-- 挿入後の本体
\u v -> contractWith (\x y -> tensorMap2 (+) x y) (tensorMap2 (*) u v)
```

`contractWith` の入力から `u * v` に要求が伝わり，`u` と `v` はテンソル型になる．スカラーを渡す場合にも同じ本体を使い，`dot 2 3` は値 `6`，静的な型は `Tensor Integer` である．添字のあるベクトルでは内積，行列では行列積を表せる．`dot a b`，`(dot a) b`，`let p := dot a in p b`，`map (dot a) xs` でも同じ入力型を使う．

論文は上のライブラリの型を使う．Lean の基本操作との接続は [仕様と実装の対応](tensor-inference-boundaries.md) で確認する．

## 7. 型注釈

型注釈は，利用者が式や仮引数に書く型であり，通常は必要ない．`↑` も定義の制約から推論する．

### 7.1 仮引数の型を指定する場合

`(x : Integer)` は固定のスカラー型を要求する．テンソルを渡す場合は関数の外側の適用を持ち上げる．型変数を含む注釈は，その共有関係と本体の制約を合わせて具体化する．普通の型注釈との照合では，持ち上げの許可を値の型と混同しない．明示された `Tensor` は保持する．

```egison
def mkS (x : Integer) : Tensor Integer := [|x, x + 10|]
mkS [|1,2|]
  → tensorMap mkS [|1,2|]
-- [|[|1,11|],[|2,12|]|]
```

### 7.2 縮約結果へのトップレベルの注釈

トップレベル定義の型注釈と推論型を合わせる境界では，外側の `Tensor` を取り除いて照合する規則を認める．例えば，縮約結果の推論型が `Tensor Integer` でも，利用者は `Integer` と注釈できる．**この規則は，利用者が実際の結果に合う型を正しく注釈することを前提とする**．階数が 0 であることを型推論が証明する規則ではない．

```egison
def A := [|1,2|]~i
def B := [|10,20|]_i
def r : Integer := dot A B
-- 注釈なしの式 dot A B は Tensor Integer，値は 50
-- r は注釈した Integer として使う
```

この照合は，`↑` の有無とは独立した，明示的なトップレベル注釈の規則である．通常の適用や型の等式で `Tensor a` と `a` を同一視したり，リストなどの内部の `Tensor` を無条件に消したりする規則にはしない．型を合わせるために値を成分へ分解する処理やテンソルを構築する処理も追加しない．

## 8. 生成する式と挿入なし型付け

### 8.1 型と変換条件から式を作る

- 保存した型・制約と挿入位置を具体化し，既知のスカラー演算への挿入と，関数を渡す際に入力位置の `↑` に従う挿入を生成する．`sum` では，内部の `foldl` へ渡す加算の変換条件が，使用ごとに異なる本体を決める．
- 同じ型の具体化と変換を使う使用は，同じ生成後の本体を共有する．使わない組合せは生成しない．捕捉した値を再評価せず，変数の束縛を保つ．
- `foldl`・`map`・`filter`・`apply`・`gp` の関数の仮引数の適用と転送は通常の適用のままにする．実際の関数を渡す位置で作った一つの関数を共有する．
- `dot` や `\x -> tensorShape (x+1)` は，テンソル型の要求から決まる一つの本体を使う．スカラー入力でも同じ本体を使う．
- 渡す関数の式を一度評価して束縛する．多引数の関数を包む場合も，各部分適用に必要な評価を残し，エラーや発散を後続の引数の適用まで遅らせない．

### 8.2 挿入なし型付けとの関係

- テンソル型の位置から §3.1 の規則 1 で決まる挿入は，入力式全体に挿入なしの型付けがあっても行う．この場合，式そのものを保つことに代えて，階数 0 の入力に対する評価結果を保つ．例えば `\x -> tensorShape (x + 1)` は本体が変わるが，スカラー入力では挿入前後とも `[] : [Integer]` を返す．
- 上の挿入以外については，入力式全体が挿入なしで型付けできるなら，その式を変えないという原則を保つ．テンソル型の位置からの根拠がない挿入を，この例外を理由に追加しない．

階数 0 の包含そのものは，値も式も変えない．テンソル型の位置から追加するのは，テンソル型の位置へ結果を渡す演算を成分ごとにするための `tensorMap`・`tensorMap2` である．この区別を，型付け規則と保存の定理にも反映する．

挿入なし型推論は，利用者が明示した `tensorMap`・`tensorMap2` を含む式も，追加の挿入なしで型付けする．自動挿入型推論は，型と必要な挿入を一緒に求める．この二つの扱いを合わせた利用者向けの型推論を統合型推論と呼ぶ．テンソル型の位置からの挿入を優先し，そのほかでは入力式全体の挿入なし型付けを保つ．

```egison
\x -> tensorShape (x + 1)
  → \x -> tensorShape (tensorMap (\z -> z + 1) x)
-- Tensor Integer -> [Integer]

(\x -> tensorShape (x + 1)) 5        -- [] : [Integer]
(\x -> tensorShape (x + 1)) [|1,2|]  -- [2] : [Integer]
```

上の二つには同じ挿入後の本体を使う．スカラー入力では，挿入前と同じ値 `[]` と結果型 `[Integer]` を保つ．

明示した `tensorMap` では，成分に適用する関数がテンソル型を受け取る場合も，階数 0 の包含を使える．例えば次の式では，同じ `f : Tensor Integer -> Integer` を使い，最後の適用に新たな挿入は行わない．

```egison
(\f -> let ys := tensorMap f [|1,2|] in f [|1,2|]) (\x -> 0)
-- 0 : Integer
```

既にある `tensorMap` を同じ理由で二重に包まない．渡す関数の式は一度束縛して，生成した関数の中で共有する．型や挿入の決定のためにソースのプログラムを実行しない．

## 9. リスト・分岐・関数の共通型

リスト構築，先頭への追加，連結，条件分岐では，成分や分岐に共通する型を求める．スカラーを階数 0 として受け取り，リストやタプルの内部にあるテンソルの位置も保つ．

```egison
[1] ++ [[|2,3|]]                     -- [Tensor Integer]
[[|2,3|]] ++ [1]                     -- [Tensor Integer]
[\x -> 0, \x -> [|0|]]              -- [a -> Tensor Integer]
```

関数の返り値は，階数 0 の包含で受け取れる．入力側にもこの包含を使う．`Tensor Integer -> b` の関数は，`Integer -> b` が要求される場所へ，式も関数値も変えずに渡せる．渡された整数を，その関数が階数 0 として受け取るためである．この照合のために `tensorMap` や関数を包むラムダ式は追加しない．

一般に，`a ≼ b` を「`a` 型の値を，値と式を変えずに `b` 型として受け取れる」と書く．`a ≼ b` と `c ≼ d` が成り立つなら，`(b -> c) ≼ (a -> d)` とする．関数の入力側では包含の向きが逆になる．これを入力の反変性と呼ぶ．この規則は型の等式ではなく，もとの関数がテンソル全体を受け取ることも変えない．

上の関数のリストでは，要素の順序によらず同じ共通型になり，どちらの関数の本体にも挿入やテンソル構築を加えない．返り値がさらに関数の場合も，同じ規則を再帰的に使う．`\v -> 1` のように引数を使わない関数は，テンソル全体を受け取れる．結果を `Tensor Integer` として受け取るだけなら，同じ式を使う．

例えば，`\k -> k 5 + 10` は，`k : Integer -> a` の結果と加算の変換条件を保存する．`Tensor Integer -> Integer` の関数は入力の包含によりそのまま渡せる．テンソルを返す関数の場合も，`k` の適用は変更せず，その結果への加算を具体化する．

```egison
(\k -> k 5 + 10) (\x -> let unused := tensorShape x in 0)
-- 10 : Integer
(\k -> k 5 + 10) (\y -> [|y,y|])
-- [|15,15|] : Tensor Integer
```

階数 0 の包含では `tensor [] [e]` を生成しない．`a` の値を `Tensor a` として受け取ることと，型の等式 `a = Tensor a` を解くことは別である．後者は正規化 `Tensor (Tensor b) = Tensor b` に従い，`a := Tensor b` と解く．リストなどを介して自分自身を含む型は循環する型として拒否する．

入れ子の適用では，外側が要求する型も内側の結果型の制約に含める．例えば `dp vars (map unique cnf)` の `dp` が `[[MathValue]]` を要求する場合，`map` の結果の要素型を `[MathValue]` と照合する．結果がリストだと分かる前に，`unique` へ不要なテンソル用の挿入を決めない．一方，型変数を含む期待型などから早く確定した型だけを理由に，全体の制約で成立する挿入を拒否しない．この処理でも，定義の本体は推論し直さない．

## 10. 型クラスと自動挿入の対象

型クラスは，加算など共通の操作を持つ型をまとめる仕組みである．スカラー型かどうかの判定には，具体型だけでなく型クラスの制約も使う．制約のない型変数だけではスカラーと断定しない．

例えば `+ : {AddSemigroup a} a -> a -> a` へ `Tensor Integer` を渡すとき，`AddSemigroup (Tensor Integer)` のインスタンスを要求するのではなく，要素型 `Integer` の加算を成分ごとに適用する．型の置換を制約にも反映してから定義を一般化し，使用箇所にも型と制約を一緒に引き継ぐ．型と挿入の決定後に，要素型に対応する操作の実装を選ぶ．操作をまとめて渡す値を型クラス辞書と呼び，その展開は挿入より後に行う．

`IO`，`IORef`，`Port` とこれらを含む型は，成分ごとの自動変換の対象にしない．関数型そのものを通常のスカラー成分と見なして持ち上げることもない．高階関数へ渡す関数を包む処理や，テンソルに格納された関数を呼び出す処理は，関数値をデータ成分として変換することとは区別する（§5）．

## 11. 添字・微分形式・シンボル宣言

添字はテンソル値の各軸に付く実行時情報であり，`Tensor a` の型引数には入らない．

```egison
def g_i_j : Tensor MathValue := [| [| 1, 0 |], [| 0, r^2 |] |]_i_j
def g~i~j : Tensor MathValue := [| [| 1, 0 |], [| 0, 1 / r^2 |] |]~i~j
```

同じ名前の共変添字と反変添字は，`contract` や添字つき演算によって縮約される．縮約後が
スカラーかテンソルかは型だけからは決まらないため，§7.2 のトップレベルの型注釈の
照合規則を使う．

### 11.1 追加添字と既存の名前の範囲

`tensor..._j` は，先頭から連続する名前付き軸だけを残し，その直後から新しい添字を処理する．名前のない軸の内側に名前付き軸があっても，その名前は残す範囲には含まれない．例えば `([|[|1,2|]_i,[|3,4|]_i|])..._j` の結果には外側の `_j` だけが付き，内側の古い `_i` は消える．`..._2` は名前のない `[|3,4|]` を返す．これは論文の，既存の先頭部分と新しい添字列を連結してから直接参照する規則に対応する．

内部の `DF` は名前のない次元を表す実行時の記号であり，§2 の持ち上げの許可とは別である．数値添字やシンボリックな添字として `tref` に渡さない．

`withSymbols` は，その式で導入した添字名だけを取り除く．名前のない軸には添字名を
取り出す操作を適用せず，その軸の寸法と成分を保持する．例えば
`withSymbols [i] [|[|1,2|]_i,[|3,4|]_i|]` は，名前のない外側の軸を保って
`[|[|1,2|],[|3,4|]|]` を返す．

添字による軸の並べ替えは，名前のない軸も含めた入力全体から指定した軸を探す．
指定した軸を先頭へ移し，残りの軸の順序を保つ．行列を値に持つ微分形式のように，
名前のある軸と名前のない軸が混在する場合も同じ規則を使う．
微分形式の積に使う一時的な軸情報は，部分積を結合して全体の軸順序を確定した後に除去する．

### 11.2 内部の空の保存配列

公開の `tensor` と `generateTensor` は0以下の軸長を拒否する．内部の配列表現と添字処理は，0の軸長も扱う．内部の参照処理は次元と添字の列を直接処理し，成分がなくても後続の軸長を保持する．例えば，内部の形状 `[0,3]` への `_i` は形状 `[0,3]` を保ち，`_i_4` は範囲外として失敗する．これは内部処理の性質であり，利用者が `tensor [0,3] []` を構築できることを意味しない．

実装箇所と検査対象は [仕様と実装の対応](tensor-inference-boundaries.md) に記す．

### 11.3 Wedge 適用

`!` を伴う Wedge 適用では，スカラー二項関数なら `tensorMap2` の Wedge 版へ変換し，
微分形式の添字を補ってから成分ごとに適用する．関数自身がテンソルを受け取る場合は，
通常の Wedge 適用を保つ．

### 11.4 シンボル宣言

テンソル成分に使う自由な数式シンボルは，未束縛変数ではなく `declare symbol` で宣言する．

```egison
declare symbol a11, a12, a21, a22
declare symbol x, y, z : Float
```

型を省略した場合は `Integer` を使う．宣言は型環境へ登録されるため，参照時に未束縛変数の
警告を出さない．CAS のシンボル値としての構築と型環境への登録は評価の前に行う．

## 12. 例と期待する結果

### 12.1 定義の型

基本の型は §2 の一覧のとおりである．中間値を持つ例では，型とともに変換条件を保存する．

```egison
def twiceSum xs := sum xs + sum xs
-- [a] -> a．sum と結果への加算の制約を共有する

def h x k := [|k x + 10, k x + 20|]
-- a -> (a↑ -> Tensor Integer) -> Tensor Integer

def hIf x k := if k x > 0 then 1 else 0
-- a -> (a -> Integer) -> Integer

def use k xs := map (\x -> k 0 x) xs
-- (Integer -> a↑ -> b) -> [a] -> [b]

\x -> tensorShape (x + 1) -- Tensor Integer -> [Integer]
\x -> x + [|10,20|]       -- Integer -> Tensor Integer
\xs -> head xs + 1        -- [a] -> b．head の結果への加算の制約を保存する
\k -> k 5 + 10            -- (Integer -> a) -> b．k の結果への加算の制約を保存する
```

`h` の `x` と `k` の入力は同じ `a` であり，二つの `k x` は同じ関数型を共有する．`k` の結果はテンソル構築式へ流れるため `Tensor Integer` である．`hIf` の比較は結果をスカラーに固定するため，`k` の入力には `↑` は付かない．`g` の二つの結果型は独立であり，`g ts [5,6]` の型は `(Tensor Integer, Integer)` となる．

## 13. 証明する性質

論文と同じく，次の六群を対象とする．実行例の一致と一般の証明を区別する．

1. **推論の停止性・健全性・完全性・主要型性**：独立した規則で許す型と変換をすべて推論する．主要型は，保存した制約を満たす具体化と，その後の式を変えない包含によって，選ばれた計算に許されるすべての型を表す．各入力位置の `↑` の判定は，その位置を持ち上げる合法な変換を受け取れる具体化の存在と一致する．実際の変換は，許可された位置の部分集合と全共有制約に従う．
2. **型構造と通常の型推論の保存**：挿入なしで型付けできる式は自動推論も成功する．`↑` と変換条件を付加した制約の記録から，挿入なしの条件へ戻して解くと，元の型構造と型変数の共有を回復する．既存の `Tensor` は消さない．テンソル操作のない式の受理・拒否，主要型，式を保つ．
3. **具体化・生成・評価の型保存**：任意の許される具体化で，保存した位置から生成でき，生成した式と終了した評価の値が対応する型を持つ．信頼する注釈の前提を明示する．
4. **式と計算の保存**：不要な挿入をしないこと，テンソル型の要求による挿入の階数0での値・エラー・発散の保存，第一階のスカラー挿入を取り除く性質を示す．
5. **共有と順序独立性**：一つの関数引数の全使用・転送・再帰呼び出しで型と値を共有する．部分適用の括り方や制約の処理順で判断を変えない．一般化した変数と捕捉した単相の変数を区別する．
6. **添字・形状と実行の対応**：添字処理の停止，配列境界，添字名の衝突回避，形状と成分の組立て，規定されたエラーを，挿入後の実際の評価へ結び付ける．

型構造の比較では，`\x -> tensorShape (x+1)` の固定した入力型を単に消してはならない．定義時の制約の記録から，テンソル型の要求が解決される前後の対応を示す．これは新たな利用者向けの型記号を導入することではない．

主要型の比較では，具体化した型 `s` と受け取る型 `t` の間に §9 の包含 `s ≼ t` を認める．包含には関数入力の反変性も含め，生成式と値を変えず，追加の挿入を行わない．例えば `1` の主要型 `Integer` は，包含により同じ式の型 `Tensor Integer` も表す．型変数の代入だけで両者を一致させることは要求しない．
