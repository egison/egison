# Egison のテンソル型と添字記法

この文書は，テンソル型，添字記法，型推論に基づく `tensorMap`・`tensorMap2` の挿入をまとめる．
テンソル計算のアルゴリズムそのものではなく，型推論と型に基づく変換を対象とする．

引数型，返り値型，テンソルを受け取る位置を利用者に指定させない．テンソルの要求がない式は，高階関数を使う定義も含め，通常の推論型と選択されるコードを保つ．定義には高階引数の変換候補も保持し，使用ごとに通常の候補を優先して選択する．未確定な仮引数へはテンソル全体を渡し，成分ごとの適用は明示的な `tensorMap` でも指定できる．

## 型推論の三つの役割

| 名前 | 入力と処理 |
| --- | --- |
| 挿入なし型推論（inference without insertion） | 書かれた式の型を求め，テンソル操作や高階引数の変換を追加しない．利用者が明示した `tensorMap`・`tensorMap2` も型付けする． |
| 自動挿入型推論（inference with automatic insertion） | 型と必要な変換を一緒に求め，`tensorMap`・`tensorMap2` の追加や高階引数の変換を許す．必ず変換を追加するという意味ではない． |
| 統合型推論（combined inference） | 入力式全体に挿入なし型推論を試し，成功すればその式を採用する．失敗した場合に自動挿入型推論を使う． |

この優先は部分式ごとの確定ではなく，後続の適用や let の使用を含む入力全体に対するものである．通常の Hindley–Milner 型推論は，テンソルに関する要求のないプログラムについて保存する．明示的なテンソル操作も受理する挿入なし型推論とは区別する．選択した型と式の保証，実装との対応，未完了の証明は [型推論の仕様と実装の対応](tensor-inference-boundaries.md) に記す．

## 1. テンソル型

テンソルは `Tensor a` と型付けし、`a` は要素型を表す。次元数、各軸の大きさ、添字名、
共変・反変は型には含めない。

```egison
def v : Tensor Integer := [| 1, 2, 3 |]
def m : Tensor Integer := [| [| 1, 0 |], [| 0, 1 |] |]
```

入れ子の `Tensor` 型は正規化で一つにまとめる。

```text
Tensor (Tensor a)  =  Tensor a
```

テンソルリテラルの成分は、すべて同じ型でなければならない。スカラーの成分と
テンソルの成分を混ぜた `[| 1, [| 2, 3 |] |]` は型エラーになる。成分の単一化で
テンソルをスカラーへほどいた場合に拒否する(`Infer.hs` の `unifyLiteralComponent`)。

実行時には、階数 0 のテンソルをスカラーそのものとして表す。例えば
`generateTensor f []` はテンソル容器ではなく `f []` を返す。大きさ 1 のベクトルは
階数 1 なので `Tensor a` のままである。

生成関数がテンソルを返す場合は，外側の形状 `S` と共通する内側の形状 `R` を `S ++ R` に
連結し，スカラー成分の配列も連結する．例えば `generateTensor (\_ -> [|1,2|]) [2]` は形状
`[2,2]`，成分 `[1,2,1,2]` を持つ．`Core.normalizeTensorWHNF` は生成・保存配列・写像の結果を
組み立て，内側の形状と添字の一致を検査する．リストなどのデータの内部はたどらない．
成分の形状が異なる `[|[|1,2|],[|3|]|]` は構築時に形状の不一致による動的型エラーとする．写像が返したテンソルを並べる場合も同じであり，`tensorMap (\f -> f 1) [|(\x -> [|x|]),(\x -> [|x,x|])|]` は同じ動的型エラーとなる．通常のリストはスカラーなので，`[|[1,2],[3]|]` は許す．
`tensor` と `generateTensor` の各軸長は正整数に限る．`tensor` は通常の引数評価後，軸長，成分数の順で検査する．`generateTensor` は形状の検査後に座標を列挙し，不正な形状では生成関数を適用しない．形状 `[]` は階数0として許し，空の座標へ一度適用する．空のテンソルリテラルと，始点が終点を超える範囲参照は実行時エラーにする．通常の空リストはスカラーのまま扱う．

## 2. 添字記法

添字はテンソル値の各軸に付く実行時情報であり、`Tensor a` の型引数には入らない。

```egison
def g_i_j : Tensor MathValue := [| [| 1, 0 |], [| 0, r^2 |] |]_i_j
def g~i~j : Tensor MathValue := [| [| 1, 0 |], [| 0, 1 / r^2 |] |]~i~j
```

同じ名前の共変添字と反変添字は、`contract` や添字つき演算によって縮約される。縮約後が
スカラーかテンソルかは型だけからは決まらないため、次節の限定的な Tensor とスカラーの
整合規則を使う。

### 追加添字と既存の名前の範囲

`tensor..._j` は，先頭から連続する名前付き軸だけを残し，その直後から新しい添字を処理する．名前のない軸の内側に名前付き軸があっても，その名前は残す範囲には含まれない．例えば `([|[|1,2|]_i,[|3,4|]_i|])..._j` の結果には外側の `_j` だけが付き，内側の古い `_i` は消える．`..._2` は名前のない `[|3,4|]` を返す．これは論文の，既存の先頭部分と新しい添字列を連結してから直接参照する規則に対応する．

内部の `DF` は名前のない次元を表すための印であり，数値添字やシンボリックな添字として `tref` に渡さない．`refTensorWithOverride` は追加参照の既存添字を最初の `DF` の手前までに限定する．`mini-test/9921-appended-index-prefix.egi` で，入れ子の配列，数値による成分選択，既存の先頭の名前の保持，同じ名前による対角成分の選択を検査する．

### 内部の空の保存配列

公開の `tensor` と `generateTensor` は0以下の軸長を拒否する．内部の配列表現と添字処理は，0の軸長も扱う．`emptyReference` は次元と添字の列を直接処理し，成分がなくても後続の軸長を保持する．例えば，内部の形状 `[0,3]` への `_i` は形状 `[0,3]` を保ち，`_i_4` は範囲外として失敗する．これは内部処理の性質であり，利用者が `tensor [0,3] []` を構築できることを意味しない．

公開操作の正常結果とエラーは，`type-tensor-mech/tests/egison-tensor-operations.json` の独立した期待結果と照合する．

## 3. 三つの単一化モード

テンソルの単一化は、利用目的ごとに次の三モードを使い分ける。

### 型クラス制約を伴う照合: `TensorConstraintAware`

型クラス制約を考慮する。制約付き変数 `a` と `Tensor t` を合わせるとき、
`Tensor t` がそのクラスのインスタンスでなければ `a = t` とし、値の側は後続の
`tensorMap`・`tensorMap2` の挿入に任せる。

例えば `+ : {AddSemigroup a} a -> a -> a` に `Tensor Integer` を渡す場合、
`AddSemigroup (Tensor Integer)` を要求せず、要素型 `Integer` の制約を保つ。

### 厳密な判定: `TensorStrict`

`Tensor a` と `a` を同一視しない。スカラー関数とテンソル引数を区別し、
`tensorMap` を挿入する必要があるかを判定するときに使う。

### トップレベルの期待型: `TensorTopLevel`

トップレベル定義の型注釈と推論型を合わせる境界では、`Tensor a` と `a` の外側を
取り除いて照合できる。縮約結果が実行時に階数 0 となる式へスカラー型を注釈するための規則である。
この規則は値の階数を静的に証明しないため、実際には階数 1 以上の値へスカラー注釈を付けると、
実行時の利用箇所で不整合が現れうる。

## 4. スカラー関数への `tensorMap`・`tensorMap2` の自動挿入

自動挿入型推論は，スカラー関数へ渡すテンソル引数と，必要な変換を型とともに求める．
`Type/TensorMapInsertion.hs` は，選択した型に従い，その関数を各成分へ適用する
`tensorMap` または `tensorMap2` の呼出しを生成する．この成分ごとの適用への変換を持ち上げと呼ぶ．

```egison
def inc (x: Integer) : Integer := x + 1
inc [| 1, 2, 3 |]

-- 概念上の変換
tensorMap (\x -> inc x) [| 1, 2, 3 |]
```

二つのテンソル引数を持ち上げる場合は `tensorMap2` を使う。片方がスカラーでも
`tensorMap2` が通常適用として扱えるため、縮約や反復の途中でスカラーからテンソルへ変わる場合も
同じ変換を使える。

高階引数とは，別の関数へ引数として渡す関数である．その変換候補は，受け取り側の型変数と共有制約をすべて満たす場合に使用できる．`map` は入力と結果の型変数をテンソル型にできる．`foldl` は結果と累積値の型を共有するため，必要な変換を両方へ伝える．`filter` に渡す述語の結果は `Bool` に固定され，`Tensor Bool` にできない．

述語の本体内の写像は，返り値を `Bool` に保てる場合に許す．例えば `filter (\x -> let unused := x+1 in True) [[|1,2|]]` は，加算だけへ `tensorMap` を挿入し，述語を `Tensor Integer -> Bool` とできる．別名で定義した述語も，既知の本体からこの候補を生成する．述語全体を写像して `Tensor Bool` を返す変換とは別に検査する．

```egison
def mySum xs := foldl (\x y -> x+y) 0 xs
-- 通常の型：[Integer] -> Integer

(mySum [1,2], mySum [[|1,2|],[|3,4|]])
-- (Integer, Tensor Integer)
```

定義は本体と内部制約を保持し，通常の候補が使用箇所に合わなければ変換候補を具体化する．別名も候補を引き継ぐ．一般化した型変数は使用ごとに新しくし，捕捉した単相な変数に関する型の関係は共有する．後続の引数や let の使用による不一致でも選び直せる．

スカラー型の判定には，本体と束縛に保持した型クラス制約を使う．一般化の前に制約中の型変数へ現在の代入を適用する．`zero` などの初期値は，変換後の累積値との整合を階数0の受け取りとして検査する．

`IO`，`IORef`，`Port`，関数型など，制御や資源を表す型は成分ごとの自動変換の対象にしない．候補の保持と選択は [高階引数の変換](tensor-map-higher-order-lift.md)，生成コードの規則は [tensorMap 自動挿入](tensor-map-insertion-simple.md) に記す．

### ほかの引数から決まるスカラー仮引数

どの引数位置を持ち上げるかは、関数適用のすべての引数を解いた後の型で決める。
`h : a -> (a -> Integer) -> Integer` について `h [| 1, 2 |] inc` を考える。仮引数 `a` は
型変数なのでテンソルをそのまま受け取れ、通常の検査は `a := Tensor Integer` を選ぶ。
その結果，高階引数 `inc : Integer -> Integer` が合わずに失敗する．しかし `inc` の型から
`a := Integer` と分かるので、`[| 1, 2 |]` の位置を持ち上げて
`tensorMap (\x -> h x inc) [| 1, 2 |]` とすべきである。

そこで引数の検査(`Infer.hs` の `checkApplicationArgumentsLifting`)は次のように動く。
- まず引数と仮引数の型を照合する。仮引数がすでにスカラー型の位置は持ち上げる。成功すればそれで決まる。
- 失敗したら、テンソル型の引数の位置の集合 S を試す。S の位置では、引数の成分型を仮引数と
  単一化し，結果型を `Tensor` 型とする．検査が成功し、しかも S のすべての位置の仮引数が最終的な
  型でスカラー型(テンソルと単一化できない型)になる S を集める。
- 集めた S のうち、ほかのすべての S に含まれる最小のものを選ぶ。そのような S がなければ、
  最初の検査のエラーを返す。

最初の照合で持ち上げる位置の仮引数はすでにスカラー型であり、
スカラー型は代入で保たれるので、上の条件を満たすどの S にも含まれる
からである。挿入(`TensorMapInsertion.hs`)は最終的な型から持ち上げる位置を読み直すので、
推論の選んだ S と一致する。形式的な規則は論文の ELAB-SPINE で、持ち上げる位置の集合を
rank-0 包含の集合 R と同じく「成功する候補のうち最小のもの」として定める。

利用者定義の関数の仮引数が，算術を経て `contractWith` などの固定テンソル位置へ流れる場合は，
その仮引数をテンソル引数(型 `Tensor a`)として割り当て，算術を `tensorMap2` で持ち上げる。
`def (.) u v := contractWith (\x y -> x + y) (u * v)` は注釈なしで
`Tensor a -> Tensor a -> Tensor a` になる。規則と実装は [固定テンソル位置へ流れる算術による仮引数の分類](tensor-demand-propagation.md) を参照する。

### 入れ子の適用へ伝える期待結果型

呼出し先が要求する引数型を、引数に書かれた関数適用の結果型として使う。
期待型が自由型変数も `Tensor` も含まなければ、内側の関数の結果型と
`TensorStrict` で単一化してから、その関数の引数を推論する。
`MathValue` などの数式処理の型も、この条件を満たせば使う。
型の内部にテンソルがないことは、リスト、タプル、関数型、数式処理の係数型などを
再帰的に調べる。型変数・テンソルを含む期待型や、この単一化に失敗する場合は、
通常の引数推論と検査を使う。
期待結果型による具体化の後で引数推論が失敗した場合も、試行中の型代入・制約・診断・
その他の推論状態を戻してから通常の推論を行う。新しい型変数の番号だけは再利用しない。
例えば数式処理の `foldl (*') 1 (map (uncurry (^')) xs)` は、内側の写像がテンソルを
返すと、畳み込みもテンソルを返す必要がある。外側の演算がスカラー型を要求していても、
その期待型への早期の具体化だけを理由に拒否しない。通常の推論の結果を使って、外側の
適用が必要なテンソル変換または不適合を判定する。

例えば `dp vars (map unique cnf)` で `dp` が `[[MathValue]]` を要求すると、
`map : (a -> b) -> [a] -> [b]` の `b` を `[MathValue]` に具体化してから
`unique` と `cnf` を推論する。これにより、結果がリストだと分かる前に `unique` を
テンソル上へ適応することを避ける。`[[Integer]]` にも同じ規則を用いる。
`TensorStrict` は数式処理のスカラー型間の適合規則を維持するが、
`Tensor a` と `a` は同一視しない。明示的なテンソル引数に必要な `tensorMap` の
挿入は通常の引数検査で決める。

## 5. Wedge 適用

`!` を伴う Wedge 適用では、スカラー二項関数なら `tensorMap2` の Wedge 版へ変換し、
微分形式の添字を補ってから成分ごとに適用する。関数自身がテンソルを受け取る場合は、
通常の Wedge 適用を保つ。この処理も `TensorMapInsertion.hs` が担当する。

## 6. シンボル宣言

テンソル成分に使う自由な数式シンボルは、未束縛変数ではなく `declare symbol` で宣言する。

```egison
declare symbol a11, a12, a21, a22
declare symbol x, y, z : Float
```

型を省略した場合は `Integer` を使う。宣言は型環境へ登録されるため、参照時に未束縛変数の
警告を出さない。CAS のシンボル値としての構築と型環境への登録は評価の前に行う。

## 7. 処理順と実装

統合型推論は，入力全体に対する挿入なし型推論の成功を優先する．自動挿入型推論が必要な場合も，型と変換の候補を同じ入力全体について比較する．選択した結果は次の順で処理する．

1. `Type/Infer.hs` が制約を考慮して型と候補を選び，型付き内部表現 `TIExpr` を生成する．
2. `Type/TensorMapInsertion.hs` が選択した型に従ってコードを生成する．自動挿入型推論が選んだ `tensorMap`・`tensorMap2` の追加と，利用者が書いた Wedge 記法を実行用の表現にする変換をここで行う．挿入なし型推論の成功は，新たな暗黙の写像や高階引数の変換を加えないことを意味し，Wedge 記法のコード生成を省くことではない．
3. `Type/TypeClassExpand.hs` が確定した要素型を使って型クラス辞書を選ぶ。
4. `Tensor.hs` と評価器が添字操作、縮約、実際の成分計算を行う。

型の正規化は `Type/Tensor.hs`、三モードの単一化は `Type/Unify.hs` にある。
処理全体の対応は [FILE_MAPPING.md](./FILE_MAPPING.md) を参照する。

主な回帰テストは `test/lib/math/tensor.egi` と、`sample/math/geometry/` のテンソル計算例である。
型推論と挿入は `test/TensorInference.hs`，テンソルを返す生成や写像は
`test/lib/math/tensor-assembly.egi` で検査する．実装との対応と制限は
[tensor-inference-boundaries.md](./tensor-inference-boundaries.md) を参照する．
