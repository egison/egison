# テンソル型と適用時の持ち上げ

この文書は型と挿入の設計仕様の正本である．例は仕様上の期待結果を示す．Lean の実装計画は [設計書](../../type-tensor-mech/docs/design.md)，既存コードとの対応は [実装状況](tensor-inference-boundaries.md) に記す．

## 1. 型の記法

`↑` は，適用時に `tensorMap` を挿入できる関数の引数に付ける．この許可を**持ち上げの許可（lifting permission）**と呼ぶ．`T↑ -> U` の `↑` はこの矢印の入力全体に属し，結果型には付けない．関数を成分ごとに適用する処理を**持ち上げ（lifting）**と呼ぶ．複数の引数を持ち上げる場合は，添字の対応を保つ `tensorMap2` とその組合せを使う．

型の中で `^` に続くのは真偽の条件である．`T^p` は，条件 `p` に応じたテンソル化を表す．`T^0 = T`，`T^1 = Tensor T` とする．条件は型スキーム（使用ごとに具体化できる型）の中で量化する．データの要素や関数の入出力では同じ条件を共有できる．例えば `sum : [Integer^p]↑ -> Integer^p` の返り値はリスト要素と同じ `p` を使う．本体内の算術の適用方法と等値比較の型が同じ入力に依存する場合にも，`pred1 : Integer^p -> Bool` のようにその条件が仮引数の型に現れる．

`^` がないことは，テンソル型にならないことを意味しない．通常の型変数 `a` 自身も `Tensor Integer` などに具体化できる．したがって `a^0` もテンソル型になり得る．`Bool` や `Integer` は固定の型であり，裸の型変数とは区別する．

```text
id : a -> a
id [|1,2|]  -- [|1,2|] : Tensor Integer，挿入なし
```

`[T]` はリスト型である．`[T^p]` は条件に応じてテンソルになる要素のリスト，`[T]^r` はリスト全体の条件付きテンソル化を表す．`[T]↑` は引数のリスト全体に対する持ち上げの許可であり，この二つの型とは異なる．

テンソル型は階数・軸長・添字名を型に持たない．入れ子は `Tensor (Tensor T) = Tensor T` に正規化する．従って `(T^p)^q = T^(p∨q)` である．ここで `∨` は論理和を表す．関数型とリストの内部へこの正規化を押し込まない．公開する型は以下のように `^p` で表し，型の末尾に `where` を付けない．内部の等式・包含・変換制約は別途保持する．

## 2. 基本の型

```text
min         : Integer↑ -> Integer↑ -> Integer
inc         : Integer↑ -> Integer
tensorShape : Tensor a -> [Integer]
contract    : Tensor a -> [Tensor a]
generateTensor : ([Integer] -> a) -> [Integer] -> Tensor a
pred1       : Integer^p -> Bool
id          : a -> a

map    : (a^p -> b^q)↑ -> [a^p]↑ -> [b^q]
filter : (a -> Bool)↑ -> [a]↑ -> [a]
zip    : [a]↑ -> [b]↑ -> [(a, b)]
mapInc : [Integer^p]↑ -> [Integer^p]
foldl  : (b^p -> a^q -> b^p)↑ -> b^p -> [a^q]↑ -> b^p
sum    : [Integer^p]↑ -> Integer^p

discard : (a^p -> b)↑ -> a^p -> Bool
length  : [Integer^p]↑ -> Integer
```

`tensorShape` や `contractWith` はテンソル全体について定義され，引数の型に `Tensor` を明記する．整数も値を変えずに階数0のテンソルとして渡せるので，例えば `tensorShape 7` は空の形状 `[]` を返す．`generateTensor` はテンソルを構築するので，結果の型に `Tensor` が付く．一方，`id` は受け取った値をそのまま返し，`zip` は二つのリストの要素をそのまま組に入れる．型変数にテンソル型を代入すれば両方の用途を表せる．

`length` はここでは整数または整数テンソルを要素とするリストについて示す．通常の多相的な `length : [a]↑ -> Integer` の具体化として読める．`zip` の `a` と `b`，`discard` の `b` にもテンソル型を代入できるので，そのためだけに `^` を加える必要はない．

## 3. 適用と関数の受け渡し

```text
Integer↑ -> Integer
```

この型の関数は，適用時の `tensorMap` 挿入によって，次の型を求められる場所でも使える．

```text
Tensor Integer -> Tensor Integer
```

整数への通常の適用ではそのまま使い，テンソル入力を要求する位置では関数全体を包む．

```text
inc [|1,2|]
  -> tensorMap inc [|1,2|]

map inc [[|1,2|]]
  -> map (\t -> tensorMap inc t) [[|1,2|]]
  -- [[|2,3|]] : [Tensor Integer]
```

後者で使うのは `inc` 自身の入力の `↑` である．`map` の第一引数全体に付いた `↑` とは区別する．関数の受け渡しでは，渡す関数の入力に記録された許可を使い，変換後の入力と結果を受取型に照合する．受け取る側の型に，関数の内部の入力位置の許可を仮定しない．関数式は一度だけ評価して束縛し，包んだ関数でその値を共有する．

`map` に関数のテンソルを渡すと，各成分の関数 `k` について同じ入力リスト `xs` で `map k xs` を計算し，得たリストをテンソルに並べる．第一引数の `↑` は関数のテンソル，第二引数の `↑` はリストのテンソルを渡す場合の許可である．内部の `p,q` と，これらの外側の持ち上げ条件は独立して扱う．例えば，内側の `p=q=0` を選んだ場合：

```text
map [|inc, inc|] [1,2]
  -> tensorMap (\k -> map k [1,2]) [|inc, inc|]
  -- [|[2,3],[2,3]|] : Tensor [Integer]

map inc [|[1,2],[3,4]|]
  -> tensorMap (\xs -> map inc xs) [|[1,2],[3,4]|]
  -- [|[2,3],[4,5]|] : Tensor [Integer]
```

両方がテンソルなら，別々の写像で添字の関係を失わず，`tensorMap2 (\k xs -> map k xs) ks xss` のように扱う．通常の `map inc` が返す `[Tensor Integer]` と，この `Tensor [Integer]` は異なる．

`↑` による外側の持ち上げは，適用結果全体をテンソル型にする．結果型に `^` がなくても同じである．

```text
discard k x := let unused = k x in True

discard inc [|1,2|]
  -> discard (\t -> tensorMap inc t) [|1,2|]
  -- True : Bool

discard [|inc, inc|] 1
  -> tensorMap (\k -> discard k 1) [|inc, inc|]
  -- [|True,True|] : Tensor Bool
```

最初の例では `a=Integer,p=1,b=Tensor Integer` を選ぶ．`inc` の変換によって `discard` 自身の結果までテンソル化する必要はない．後の例は `discard` の第一引数の許可を使う別の適用である．

## 4. 等値比較と本体内の成分ごとの適用

### 等値比較が共有する型

```text
(==) : Eq a => a -> a -> Bool
pred1 x := x * 2 - 10 == x
pred1 : Integer^p -> Bool

pred1 10         -- True
pred1 [|10,11|]  -- False
filter pred1 [9,10,11]                          -- [10]
filter pred1 [[|9,10|],[|10,10|],[|10,11|]]    -- [[|10,10|]]
```

`Eq a` は型 `a` の二つの値を比較できるという制約である．`(==)` 自身は，一つの型について二つの値を受け取り，一つの `Bool` を返す．比較対象の型が `t^p` なら，その使用箇所での型は `Eq (t^p) => t^p -> t^p -> Bool` となる．標準のテンソル用の実装には `Eq t => Eq (Tensor t)` という条件がある．`p=1` の比較をこの実装で行うには要素型の比較が必要であり，`Eq t` があれば `p=0` と `p=1` の両方を扱える．[標準ライブラリの等値比較](../lib/core/base.egi)

`pred1` の算術から成分型が `Integer` に決まる．`x` と算術結果には同じ条件 `p` を用いる．`p=0` では整数の乗算・減算に続いて整数同士を比較する．`p=1` では乗算・減算を成分ごとに行い，最後にテンソル用の等値比較を一度呼ぶ．例えば `[|10,11|]` なら左辺は `[|10,12|]` となり，全体を比較した結果は `False` である．どちらの比較も利用できるので，`pred1` の公開型に未解決の `Eq` 制約は残らない．定義からこの型を推論でき，`filter` が要求する一つの真偽値を返せる．成分ごとの真偽値が欲しい場合は `predScalar (x : Integer) := x*2-10 == x` と書くと，同じ入力から `[|True,False|]` が得られる．

### 本体内のどこに `tensorMap` を挿入するか

```text
mapInc xs :=
  case xs of
    | [] -> []
    | x :: rest -> inc x :: mapInc rest

mapInc : [Integer^p]↑ -> [Integer^p]
mapInc [[|1,2|],[|3,4|]]  -- [[|2,3|],[|4,5|]]
```

引数の型を構成するリスト・データ型のフィールドから値を取り出し，持ち上げ可能な関数の引数に使うとき，そのフィールドの型について通常の型 `T` と `Tensor T` の二通りを調べる．例えば `Cons x rest` の `x` は引数 `xs` の要素型を持つ．別名を付けても同じ要素型を追う．各候補について関数の許可，結果を使う位置の要求，同じ変数の他の使用，再帰呼出しを含む本体全体の制約を照合する．一方だけが適合すればその型に固定する．両方が適合し，対応する挿入を共有条件で表せるなら `T^p` として両方を残す．どちらも適合しなければその候補から型は得られない．通常の型変数 `a` 自体にもテンソル型を代入できる．

この型で再帰定義を使うには，リストの要素 `x` に対する `inc x` に挿入を許す．`p=0` なら通常の適用，`p=1` なら `tensorMap inc x` になる．残りのリストの要素にも同じ `p` を使う．上の入力の外側は普通のリストなので，リスト引数全体の `↑` による挿入は起きない．

### `map` と `filter` の要素型

```text
map f xs := case xs of
  | []        -> []
  | x :: rest -> f x :: map f rest
map : (a^p -> b^q)↑ -> [a^p]↑ -> [b^q]

filter pred xs := case xs of
  | []        -> []
  | y :: rest -> if pred y then y :: filter pred rest else filter pred rest
filter : (a -> Bool)↑ -> [a]↑ -> [a]
```

`map` の一回の呼出しでは，受け取る関数の入力とリスト要素が同じ `a^p`，その関数の結果と出力要素が同じ `b^q` である．その型を持つ関数を直接受け取るか，渡す関数自身の `↑` でその入出力を満たす関数に包む．整数要素への `inc` は通常の適用である．テンソル要素なら `inc` を成分ごとに適用してテンソルを返すことも，`tensorShape` に要素全体を渡して形状を返すこともできる．具体的な関数が許す組合せだけを使う．`map` の二つの外側の `↑` は，関数のテンソルとリストのテンソルに対する許可である．

`filter` の `if` は要素ごとに一つの `Bool` を要求する．`Integer↑ -> Bool` の述語を持ち上げると `Tensor Bool` を返すため，`pred y` にはこの写像を挿入できない．同じ `a` が述語の入力と両方のリストの要素を表す．`a = Tensor Integer` なら `Tensor Integer -> Bool` の述語をそのまま呼べる．例えば `filter pred1 [[|10,10|],[|10,11|]]` は `[[|10,10|]]` を返す．述語のテンソルを渡すときには `filter` 全体を写像できる．

```text
map inc [[|1,2|]]         -- [[|2,3|]]
map tensorShape [[|1,2|]] -- [[2]]
predScalar (x : Integer) := x*2-10 == x
filter predScalar [[|10,11|]] -- 型エラー（条件式が Tensor Bool）
```

### 直接の仮引数を使う計算

```text
ignore x := let v = x+1 in True
ignore : Integer↑ -> Bool
ignore 2                 -- True
ignore [|2,3|]           -- [|True,True|]
filter ignore [[|2,3|]]  -- 型エラー：述語の結果に Bool が必要
```

直接の仮引数についてスカラー型とテンソル型の両方を試さない．`ignore` では `x+1` が `x` を整数に定め，加算の結果を捨ててもその型は変わらない．テンソル入力では呼出し側が `ignore` 全体を成分ごとに適用する．`filter` が要求する一つの真偽値は，この成分ごとの適用では得られない．

`let y = x` で別名を付けても `y` は直接の仮引数と同じ値である．`mapInc` の枝でリストから取り出した要素には，§4 のフィールドの規則を使う．`pred1` の直接の仮引数に現れる条件は，算術と値全体の等値比較が同じ型を要求することから伝わる．

## 5. 畳み込みと型の共有

`foldl` は累積値の入力・関数の結果・最終結果に同じ `b^p` を使う．リスト要素は独立した `a^q` である．`p` は初期値の式の正確な型ではなく，初期値を受け取る累積値型の条件である．

```text
foldl (+) 0 [[|1,2|],[|10,20|]]
  -> foldl (\u v -> tensorMap2 (+) u v) 0 [[|1,2|],[|10,20|]]
  -- [|11,22|] : Tensor Integer

foldl (\acc t -> acc + tensorRank t) 0 [[|1,2|],[|3,4|]]
  -- 2 : Integer
```

前者は `p=q=1`，後者は `p=0,q=1` の具体化を使える．前者の `0` は値と式を変えない**階数0の包含（rank-0 inclusion）**でテンソル型の累積値として受け取る．次の反復でも累積値型は変わらない．要素がテンソルであるだけで最終結果をテンソルにしない．`foldl` のリスト引数全体の `↑` は，リストのテンソルへの外側の写像を別に許す．

`sum xs := foldl (+) 0 xs` は加算の変換を保存し，`sum : [Integer^p]↑ -> Integer^p` を持つ．`mapInc xs := map inc xs` も要素の入出力に同じ条件を使う．

```text
sum [1,2]                -- 3
sum [[|1,2|],[|3,4|]]    -- [|4,6|]
```

どちらも入力はリストである．二番目の結果がテンソルになるのは，要素に対して選んだ `p=1` を返り値でも使うためである．

一つの関数の仮引数は全使用・転送・再帰で同じ具体化した型・値・入力の許可を共有する．挿入操作は記録した使用位置ごとに決める．

```text
gp k xs := (map k xs, k 0)
gp inc [[|1,2|]]
  -- body with shared k = inc:
  --   (map (\t -> tensorMap k t) [[|1,2|]], k 0)
  -- ([[|2,3|]], 1) : ([Tensor Integer], Integer)
```

`k : Integer↑ -> Integer` を共有し，包むのは `map` へ渡す引数だけである．`k 0` は通常の適用として整数を返す．一つの使用位置で包んだ関数によって，別の使用位置の仮引数を置き換えない．本体は一度型付けして挿入位置を保存し，各位置の操作を辞書で渡す．

同じ関数を二か所で適用するときは，その値・型・入力の許可を共有し，呼出し方を位置ごとに決める．

```text
twin f := (f 0, f [|1|])
twin inc         -- (1, [|2|])
twin tensorShape -- ([], [1])
```

`inc` の場合，左は通常の適用，右だけが `tensorMap inc [|1|]` となる．`tensorShape` なら左の `0` は階数0として，右はベクトル全体として渡し，どちらも通常の適用を使う．コンパイラは具体化の際に，各適用の入力・結果・許可に合う操作を辞書（隠れた引数として渡す値）に格納する．一引数なら操作の選択を「この位置で写像するか」というフラグで実装できる．条件 `p` は型の具体化を指定する情報であり，入力がテンソルでも通常の適用を選ぶことがある．条件付きの関数は，保存した適用位置が必要とする条件や操作を受け取る．

一般化は，周囲に捕捉されていない型変数と条件変数を使用ごとに新しくする．再帰中の型は一般化しない．`foldl (+)` の部分適用でも条件を保持し，`(foldl (+)) 0 xs` と同じ挿入を選ぶ．

## 6. 推論・生成の要件

- 普通の型変数，条件変数，入力の `↑` を別の情報として保存する．`↑` は実行時の値や型構成子ではない．
- 本体を一度型付けして，型の等式，包含，変換条件，挿入位置を記録する．同じ仮引数の全使用を照合し，宣言が求める `Tensor`，型変数への代入，本体内で共有する条件および関数全体の持ち上げを区別する．通常の型とテンソル型を試すフィールドの規則は，直接の仮引数には適用しない．
- 使用時には全引数と要求結果型を照合する．型の具体化と包含だけで受け取れる場合を優先し，持ち上げが必要なら許可された入力集合から最小の合法な集合を選ぶ．最小の集合がない曖昧な適用は拒否する．
- 定義時の一般化で，別の入力型に対応する合法な条件まで消さない．既知の具体的な使用における最小の挿入と，定義の条件の一般化を区別する．
- `inc` のような `T↑ -> U` の型から条件付きの関数型を要求される場合は，入力側に用いた条件と同じ条件で結果全体をテンソル化する．
- 関数型もテンソルの成分にできる．ただし `Tensor (a -> b)` と `Tensor a -> Tensor b` を同一視しない．関数を返した後に，返した関数の本体へ写像を押し込まない．
- 関数式を一度評価し，部分適用の各段階の値・エラー・発散の順序を保つ．保存した位置からのみ生成する．
- 明示的なテンソルを受け取る操作，テンソルの構築，縮約，添字の型と値の規則を維持する．関数入力の包含は反変（受取側と逆向き）に照合する．
- 型クラスの演算を用いる場合，成分の型と挿入を決めてから対応する実装を選ぶ．副作用を表す `IO`，参照，ポートを自動的に持ち上げない．

関数を成分とするテンソルでは，各関数の入力と返り値の条件を保持する．例えば：

```text
def h x := [|\y -> x+y, \y -> x+y+100|]
h : Integer^p -> Tensor (Integer^q -> Integer^(p∨q))

h [|1,2|] [|10,20|]
  -- [|[|11,22|],[|111,122|]|]
```

`p` は捕捉する `x`，`q` は二つの関数が受け取る `y` の条件である．各ラムダ式は通常の関数であり，外側の `Tensor` は構築式が作る関数のテンソルを表す．成分の関数の返り値を一律にテンソル型へ固定せず，`p=q=0` では整数を返す．この適用では `p=q=1` とし，各関数へ第二引数全体を渡す．算術の辞書は定義時に保存した位置で使い，捕捉した `x` を共有する．`h` の第一入力には `↑` を付けない．構築の外へ写像を移すと軸の順序が変わるためである．

## 7. テンソル全体・注釈・実行

宣言に明記された `Tensor` は一般化で条件付き型に置き換えない．`contract : Tensor a -> [Tensor a]` の入力と結果の要素，`generateTensor : ([Integer] -> a) -> [Integer] -> Tensor a` の結果は，そのまま `Tensor` を保つ．関数をテンソルの成分として格納する場合には，外側の `Tensor` と成分の関数型を区別する．前節の `h` は `Integer^p -> Tensor (Integer^q -> Integer^(p∨q))` のままとし，成分の関数の返り値を一律に `Tensor Integer` に固定しない．

`tensorShape` はテンソル全体を受け取る．`\x -> tensorShape (x+1)` のテンソル型の要求は算術への挿入条件に伝わり，`Tensor Integer -> [Integer]` となる．整数 `5` を渡せば階数0として `[]` を，ベクトルを渡せばその形状を返す．この要求を，引数を無視する関数へ無条件に伝えない．

```text
contract : Tensor a -> [Tensor a]
contractWith : (Tensor a -> Tensor a -> Tensor a)↑ -> Tensor a -> Tensor a

dot u v := contractWith (+) (u * v)
-- Tensor Integer -> Tensor Integer -> Tensor Integer
dot 2 3                      -- 6 : Tensor Integer
dot [|1,2|]~i [|10,20|]_i    -- 50 : Tensor Integer
```

正しいトップレベルの縮約結果の注釈を信頼する規則は維持する．この規則は通常の型の等式で `Tensor a = a` としたり，リスト内部のテンソルを消したりするものではない．型安全性には注釈と実際の値が一致するという前提を明記する．

テンソルの構築では，成分を全体として受け取り，外側の形状 `S` と共通する内側の形状 `R` を `S ++ R` に結合する．成分の形状と添字列の不一致は実行時エラーであり，それを避けるために外側の写像へ変更しない．リスト内部はたどらない．公開する軸長は正整数，空の形状 `[]` は階数0である．`[|[1,2],[3]|]` はリストを成分とするテンソルである．

```text
(\x -> [|x, x+10|]) [|1,2|]
  -- [|[|1,2|],[|11,12|]|]
(\x -> [|x,10|]) [|1,2|]
  -- 形状エラー
tensorMap (\x -> [|x,x+10|]) [|1,2|]
  -- [|[|1,11|],[|2,12|]|]
```

添字の縮約・軸の並替え・名前の範囲・微分形式の規則は [実装との対応](tensor-inference-boundaries.md) と論文のテンソル添字記法の節に従う．追加添字は先頭の連続した名前付き軸を保持して処理する．`withSymbols` は導入した名前だけを除き，名前のない軸の形状と成分を保持する．内部配列の0の軸長と，公開構築で許す正の軸長を区別する．数式シンボルは `declare symbol` で宣言する．

## 8. 証明と検証の到達点

推論器から独立した型付け規則を定め，停止性・健全性・完全性・主要型性，通常の型構造の保存，任意の合法な具体化での生成と型保存，評価結果の型保存，式と階数0での計算の保存，共有と順序独立性，添字・形状・境界の保証を証明する．これらの目標を既存実装の範囲に縮小しない．

本書の全署名と例を，型・挿入位置・値・エラーについて検査する．関数のテンソルとリストのテンソル，名前付き・匿名・保存した述語，部分適用，捕捉，再帰を含める．既存の証明と回帰検査を削除して新仕様の実装済みという扱いにせず，仕様上変化する判断は明記して検査を追加・更新する．Lean の未実装項目と接続する定理は [設計書](../../type-tensor-mech/docs/design.md) に記す．
